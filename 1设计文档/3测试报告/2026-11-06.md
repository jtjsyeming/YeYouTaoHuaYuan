## 六、问题明细

### 6.1 本轮新发现（P-001~P-016）

**P-001　D-03 自动化用例期望值 off-by-one（测试代码缺陷，非产品缺陷）**　`（已修：未提交，2026-11-06）`
- 证据：全量回归 3 条失败；FT-17 在本地 19 点复现 `round` 口径三行全偏 1 天、`floor` 口径零偏差；FT-13 独立实现与页面逐字一致。
- 影响：门禁随执行时刻摆动（上午绿 / 下午红），会掩盖 D-03 的真实回归，也会让发布前测试失去可信度。
- 位置：`tools/e2e/tests/d03_calendar.spec.mjs:28`（`Math.round`），对照 `jtjsym/jtjsym/Pages/MyPage/LoveTime.razor:227`（`(now - t2).Days`）。
- 性质：确定、可复现、与时刻强相关。

**P-002　存档内容无合法性校验（D-17）**
- 证据：FT-01 五类注入全部原样恢复；代码 `Game_2048.razor:393` 仅 `st is { V: 1, Cells.Length: GridSize * GridSize }`。
- 影响：任何能写 `sessionStorage` 的来源（手改、扩展、旧版本残留、同步脚本）都能把棋盘和分数改成任意状态；`score` 无上限与非负校验，`cells` 无值域校验。
- 性质：数据完整性缺陷，稳定复现。现有 G2048-34 只覆盖 4 种「结构坏档」，未覆盖「结构合法、内容坏」的档。

**P-003　伪造分数污染永久最高分（D-17 × D-16 联动）**
- 证据：FT-02；恢复末尾 `UpdateBestScore()`（`Game_2048.razor:401`）在 `BestScore` 已加载后把存档分当破纪录，`WriteBestAsync` 写入 `localStorage`。
- 影响：`sessionStorage` 是标签级的，但被写坏的 `localStorage` 是 origin 级永久的；清掉会话存档、重开标签都消不掉，`最高分` 被永久抬高。
- 性质：跨存储层的数据污染，稳定复现。

**P-004　全空盘软锁**
- 证据：FT-03；`AfterMove` 的 `IsBoardChanged` 早退 + `AddRandomTile` 只在有效移动后调用，空盘任何方向都「无变化」。
- 影响：棋盘 0 块、无结束遮罩、方向按钮仍可点但毫无反应，用户只能靠「重玩」脱困。

**P-005　非法值参与合并 / int 溢出**
- 证据：FT-04；`Merge()` 的 `merged.Add(values[i] * 2)` 与 `Score += values[i] * 2` 均为 `int` 且无 `checked`。
- 影响：出现 6、-2 等非 2 幂块与负分；`TileClass()` 生成 `tile-6` / `tile--2` 等无 CSS 定义的类，配色丢失。

**P-006　恢复窗口内重玩被旧档覆盖（用户操作丢失）**
- 证据：FT-08，5/5 稳定复现；分数轨迹 `分数：0 → 分数：40` 证明点击已到达服务端，`archiveScore=40` 证明存档没被新局覆盖成功。
- 根因：`OnAfterRenderAsync` 先把 `isSessionReady=true` 开闸，再 `await sessionStorage.getItem`；窗口内 `RestartGame()` 会写档，而恢复分支随后用已读到的旧值覆盖 `board` / `Score`，之后不再落盘。
- 影响：用户看到「点了重玩，短暂变新局，又变回旧残局」，是与 P-009 首屏闪烁叠加后最容易被真实用户触发的路径。
- 性质：确定性竞态（在本用例构造的时序下 5/5），非偶发。

**P-007　fire-and-forget 落盘窗口**
- 证据：FT-07 最终轮 10/10 丢、对照 8/8 保持；另两轮（判据较弱时）分别 6/10 丢、0/10 丢，说明与时序/负载相关。
- 根因：`AfterMove()` 中 `_ = SaveSessionAsync()`，`JS.InvokeVoidAsync` 尚未完成时整页刷新会断开 circuit。
- 影响：点一下立刻刷新 / 切后台 / 断线重连，回来可能回退一步。注：本用例无法区分「@onclick 事件未送达」与「setItem 未完成」，两者对用户的表现相同，均落在同一交互窗口。
- 性质：概率性竞态，判据必须用 16 格盘面签名（位移步分数增量恒为 0，只比分数会假绿）。

**P-008　sessionStorage 的多标签语义边界**
- 证据：FT-06；`window.open` 打开的 B 完整继承 A 的 session 副本，全新 context 则不继承。
- 影响：《更新记录》与《现状》以「两个标签各玩一局互不干扰」作为选 `sessionStorage` 不选 `localStorage` 的关键理由，该理由只对「全新标签」成立；「复制链接 / 复制标签页 / 从页面内打开」会从同一残局开始（后续写入互不影响）。
- 性质：浏览器规范行为，属文档表述与实际语义的边界，不是代码 bug。

**P-009　首屏闪烁**
- 证据：FT-09；`_Host.cshtml` 是 `ServerPrerendered`，预渲染实例执行 `OnInitialized` → `RestartGame()` 生成新局并输出 HTML；交互实例在 `OnAfterRenderAsync` 才恢复残局。
- 影响：慢网下「新局」停留更久，用户可能以为进度丢了而点重玩（撞 P-006）。

**P-010　三行秒数瞬时不同步**
- 证据：FT-11；`ApplyCustomDate` / `ResetAnchor` 只调 `Render(anchor, type)`，其余两行沿用上一 tick 的文本，最多约 1 秒后才由 `RefreshAll()` 对齐。
- 影响：点击日期相关按钮后的瞬间三行秒数可差 1 秒；既有 LT-22 只在稳态 5 次采样，覆盖不到。

**P-011 / P-012 / P-013 / P-014 / P-015 / P-016**　见总结表，均为工程一致性、文档或覆盖类观察项，无功能故障。其中 P-016 的 320px 补测结果为全绿，说明产品在该视口无问题，仅既有套件缺这一档。

**P-017 / P-018　交叉验证补录（同日自动化全量报告）**
- P-017：Firefox 下 `/game_2048` 载入期偶发 `No interop methods are registered for renderer 1`，6 轮复现 2 次（≈33%）；DOM 断言全通过，功能无影响。本轮我的全量在 Firefox 上未复现，故不把它算作确定性缺陷，但按「现象一律登记」收录。
