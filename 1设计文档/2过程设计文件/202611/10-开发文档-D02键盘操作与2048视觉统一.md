## 2. 任务 A/B：键盘操作支持

### 2.1 技术选型：window 级 JS 监听（JS interop），不用 `@onkeydown`

| 方案 | 结论 |
|---|---|
| **A. JS interop，`window.addEventListener('keydown'/'keyup')`（选定）** | ① 焦点无关：点击按钮/侧栏后按键依然生效；② 可**按键级** `preventDefault()`（阻止方向键滚动页面），Blazor 的 `@onkeydown:preventDefault` 是元素级全拦，会误伤 F5/Tab；③ 需要 **keyup**（Tetris 松开 ↓ 停软降），Blazor 事件对窗口级 keyup 无能为力；④ 浏览器原生按住连发（key repeat）免费获得 |
| B. 容器 `tabindex="0"` + `@onkeydown` | 无 JS 依赖，但焦点移出游戏区即失效；无法按需 preventDefault；keyup 需要额外 hack。否决 |

实现采用 **JS 模块隔离**（`IJSRuntime.InvokeAsync("import", ...)`），无需在 `_Layout.cshtml` 加 `<script>`，两页共用一个模块文件。

### 2.2 新增共享模块 `wwwroot/js/gamekeyboard.js`

```js
// 夜游桃花源 游戏键盘支持（Game_2048 / Tetris 共用）
const MOVE_KEYS = ['ArrowLeft', 'ArrowRight', 'ArrowUp', 'ArrowDown'];
const REPEAT_MIN_INTERVAL_MS = 60;   // 按住连发节流，防弱网下 SignalR 指令积压
let dotNetRef = null;
let keydownHandler = null, keyupHandler = null;
let lastInvokeAt = Object.create(null);

export function register(ref) {
    dispose();                       // 防重复注册
    dotNetRef = ref;

    keydownHandler = (e) => {
        if (!MOVE_KEYS.includes(e.key)) return;
        e.preventDefault();          // 方向键不滚动页面；其余键不受影响
        const now = performance.now();
        if (e.repeat && now - (lastInvokeAt[e.key] ?? 0) < REPEAT_MIN_INTERVAL_MS) return;
        lastInvokeAt[e.key] = now;
        dotNetRef.invokeMethodAsync('OnKeyDown', e.key);
    };
    keyupHandler = (e) => {
        if (!MOVE_KEYS.includes(e.key)) return;
        dotNetRef.invokeMethodAsync('OnKeyUp', e.key);
    };
    window.addEventListener('keydown', keydownHandler);
    window.addEventListener('keyup', keyupHandler);
}

export function dispose() {
    if (keydownHandler) window.removeEventListener('keydown', keydownHandler);
    if (keyupHandler) window.removeEventListener('keyup', keyupHandler);
    keydownHandler = keyupHandler = null;
    dotNetRef = null;
}
```

设计说明：
- **白名单过滤**：只处理四个方向键，其余按键（F5、Tab、输入等）零干扰；
- **repeat 节流 60ms**：按住方向键时浏览器以 ~30Hz 连发 keydown，Blazor Server 每次都是一次 SignalR 往返，弱网下会积压排队导致"松手还在动"；节流保证指令速率 ≤16/s；
- `keyup` 不节流、不 preventDefault（软降松开必须即时可靠）。

### 2.3 Game_2048 接入

```razor
@page "/game_2048"
@inject NavigationManager Navigation
@inject IJSRuntime JS
@implements IAsyncDisposable
```

```csharp
@code {
    private IJSObjectReference? keyModule;
    private DotNetObjectReference<Game_2048>? dotNetRef;

    // 仅交互实例会执行（ServerPrerendered 下 OnInitialized 跑两次，此处天然规避）
    protected override async Task OnAfterRenderAsync(bool firstRender)
    {
        if (firstRender && keyModule is null)
        {
            dotNetRef = DotNetObjectReference.Create(this);
            keyModule = await JS.InvokeAsync<IJSObjectReference>(
                "import", "./js/gamekeyboard.js");
            await keyModule.InvokeVoidAsync("register", dotNetRef);
        }
    }

    [JSInvokable]
    public async Task OnKeyDown(string key)
    {
        await InvokeAsync(() =>
        {
            if (isGameOver) return;      // 结束后按键无效（与守卫后的按钮行为一致）
            switch (key)
            {
                case "ArrowLeft":  MoveLeft();  break;
                case "ArrowRight": MoveRight(); break;
                case "ArrowUp":    MoveUp();    break;
                case "ArrowDown":  MoveDown();  break;
            }
        });
    }

    [JSInvokable]
    public Task OnKeyUp(string key) => Task.CompletedTask;   // 2048 无 keyup 需求，接口占位

    public async ValueTask DisposeAsync()
    {
        if (keyModule is not null)
        {
            try { await keyModule.InvokeVoidAsync("dispose"); await keyModule.DisposeAsync(); }
            catch (JSDisconnectedException) { /* 断线/关页，无需清理 */ }
            keyModule = null;
        }
        dotNetRef?.Dispose();
    }
}
```

**配套必要小修（现状缺口）**：四个 `MoveX()` 方法首行加守卫——当前按钮在游戏结束后依然可以走棋（v2.0 测试时 G2048-04 因无法构造结束态被阻塞，未暴露），键盘接入会放大该问题：

```csharp
private void MoveLeft()
{
    if (isGameOver) return;          // ← 新增，MoveRight/MoveUp/MoveDown 同
    ...
}
```

### 2.4 Tetris 接入

复用同一模块，键位映射到既有方法（全部自带 `isDisposed/isGameOver/isPaused` 守卫，无需新增状态判断）：

| 按键 | 事件 | 调用 | 等价按钮 |
|---|---|---|---|
| ← | keydown（含 repeat） | `MovePiece(-1, 0)` | ← 按钮 |
| → | keydown（含 repeat） | `MovePiece(1, 0)` | → 按钮 |
| ↑ | keydown | `RotatePiece()` | 旋转按钮 |
| ↓ | **keydown** | `StartSoftDrop()` | 按住 ↓ 按钮（pointerdown） |
| ↓ | **keyup** | `StopSoftDrop()` | 松开 ↓（pointerup/out/leave） |

```csharp
[JSInvokable]
public async Task OnKeyDown(string key)
{
    await InvokeAsync(() =>
    {
        switch (key)
        {
            case "ArrowLeft":  MovePiece(-1, 0); break;
            case "ArrowRight": MovePiece(1, 0);  break;
            case "ArrowUp":    RotatePiece();    break;
            // StartSoftDrop 自带 isSoftDropping 幂等守卫：
            // 浏览器按住 ↓ 的 autorepeat 连发 keydown 不会重复建软降计时器
            case "ArrowDown":  StartSoftDrop();  break;
        }
    });
}

[JSInvokable]
public async Task OnKeyUp(string key)
{
    if (key == "ArrowDown")
        await InvokeAsync(StopSoftDrop);
}
```

生命周期：Tetris 现有同步 `Dispose()` 保留；追加 `IAsyncDisposable`，`DisposeAsync()` 内先做与 §2.3 相同的 JS 清理（try/catch `JSDisconnectedException`），再调用既有 `Dispose()` 停表。注册点同为 `OnAfterRenderAsync(firstRender)`（规避 ServerPrerendered 双执行，沿用 06/09 文档确立的模式）。

### 2.5 交互细节确认

- **按住 ← 连发**：浏览器原生 repeat + 60ms 节流 → 按住约每秒 16 格，手感接近原生俄罗斯方块；
- **↑ 连发**：允许 repeat（连续旋转），如实测手感差可在 JS 端对 ArrowUp 加 `if (e.repeat) return;`（一行开关，实施时定）；
- **暂停态**：Tetris 暂停中按键由既有方法守卫直接忽略，与按钮 disabled 语义一致；
- **与屏幕按钮共存**：键盘与按钮调用同一方法，无状态分叉；按钮无焦点要求。

## 8. 风险与权衡

| 风险 | 影响 | 缓解 |
|---|---|---|
| 按住连发经 SignalR 往返，弱网延迟叠加 | 移动"粘滞"、松手后仍动 | 60ms JS 端节流（§2.2）；Tetris 软降走本地计时器不受影响 |
| `JSDisconnectedException` | 关页/断线时 Dispose 抛错刷日志 | DisposeAsync 内 try/catch 吞掉（§2.3） |
| window 级监听误伤其他页面 | — | 模块随组件注册/注销，且仅两个游戏页注册；导航离开即 dispose |
| e2e `readScore` 与文案改动不同步 | G2048 套件全红（假失败） | §4 已列入改动清单，`test:g2048` 作为回归门禁 |
| 键盘事件与按钮 disabled 语义漂移 | 结束/暂停后按键"穿越" | 2048 补 Move 守卫（§2.3）；Tetris 复用方法级守卫；D02-4 验证 |
| 2048 空块与深色棋盘对比度 | `#cdc1b4` 在深色玻璃容器上偏亮 | 与标准 2048 观感一致，属预期；如有意见仅调 `tile-empty` 一处 |
