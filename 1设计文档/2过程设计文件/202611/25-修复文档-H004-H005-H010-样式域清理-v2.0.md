## 1. 问题与现状（均已核实）

### 1.1 H-004 / D-09：`.btn-primary` 全局类名

| 位置 | 内容 |
|---|---|
| `Counter.razor:11` | `.btn-primary { … }`：木鱼按钮主体（48×48、`counter.gif` 背景） |
| `Counter.razor:25` | `.btn-primary:active { … }`：按下反馈 |
| `Counter.razor:36` | `<FluentButton class="btn-primary" …>` |
| `site.css:14-18` | 另一条 `.btn-primary`（`#1b6ec2` / `#1861ac` 边框） |
| `bootstrap.min.css` | 还有第三条（`#0d6efd`） |

机制：`Counter.razor` 的 `<style>` 是**组件标记的一部分**，被渲染进 DOM（`<body>` 内），**Blazor 不对其做作用域隔离**（作用域只对 `*.razor.css` 生效）。因此它是一条全局规则，与 `site.css`、Bootstrap 的同名规则按"特异性相同 → 后者胜"互相覆盖。结果：任何页面只要写 `class="btn-primary"`（想要 Bootstrap 语义的主按钮），实际拿到的是木鱼样式。

### 1.3 H-010：`div { color:#886D68 }` 标签选择器

```
site.css:141-145   body { font-family:…; color: cornflowerblue; text-align:center; }
site.css:147-149   div  { color: #886D68; }
```

标签选择器（特异性 0,0,1）**压过从父元素继承来的颜色**，于是所有 div 的文本色被强制成褐色，而**不经过 div 的文本**（`body` 直系）拿 `cornflowerblue`。实际影响是三处对抗性写法：

- `NavMenu.razor.css:52` / `:68`：`.fluent-nav-text` 必须显式 `color: inherit`；
- `site.css:222` 注释：tile 8 以上必须显式白字；
- `site.css:330`：`.card-title` 必须显式给色；
- `LoveTime.razor:339`：`.timer-calendar` 必须显式 `#e48bfa`（注释里写明"`inherit` 只会拿到祖先 div 的褐色"）。

每新增组件都可能踩一次，是持续性的样式税。

## 2. 修复方案

### 2.1 H-004：`.btn-primary` → `.muyu-btn`

1. `Counter.razor` 三处同步改名：`:11`（规则）、**`:25`（`:active`）**、`:36`（class 属性）；
2. `site.css:14-18` 的 `.btn-primary`：改名后全仓 `class="btn-primary"` 归零 → 该定义成为孤儿，**删除**（Bootstrap 自带的那条仍在 `bootstrap.min.css` 里，需要时天然可用）；
3. e2e 15 处选择器同步改 `.muyu-btn`（`nav_fish.spec.mjs` 9、`code_nf.spec.mjs` 3、`smoke.spec.mjs` 3）。

**完成判据**：`grep -rn "btn-primary" --include=*.razor --include=*.mjs --include=*.css .`（排除 `bootstrap.min.css`、`bin/`、`obj/`、`.publish/`）**清零**。

> 注意发布产物：`.publish/staging` 与 `jtjsym/jtjsym/bin/**/publish` 下的 `site.css` 也会被 grep 命中，属构建产物，不要改。

### 2.2 H-005：乱码注释重写 + `.editorconfig` 顺手清理

1. 6 行注释按上表重写中文，**属性值零改动**；保存为 UTF-8 无 BOM；
2. `.editorconfig`：把行内 `#` 注释挪到独立行或删除（`indent_size`、`end_of_line` 两行有问题），`charset = utf-8` 保留不动。该项独立可验证：改完用 VS Code 打开 `site.css` 看右下角编码仍是 UTF-8。

### 2.3 H-010：`div{color}` → `body{color}`

**推荐实现（精确到行）**：

```diff
 body {
     font-family: 'Segoe UI', Tahoma, Geneva, Verdana, sans-serif;
-    color: cornflowerblue;
+    color: #886D68;
     text-align: center;
 }
-
-div {
-    color: #886D68;
-}
```

- **为什么等价（已实测）**：站点所有可见文本都在 `.page` / `article` 链上的 div 内，原本经 `div→逐层继承` 得到 #886D68；改后经 `body→逐层继承` 得到同值。`cornflowerblue` 从未落到任何可见文本上（否则它早该在页面上出现过）；
- **为什么不"只改选择器名"**：把 `div{}` 原地改成 `body{}` 会得到两条 `body` 规则，后一条覆盖前一条的 `color`，`cornflowerblue` 变成死声明 —— 下一次维护者很可能"修复"它，把 bug 带回来；
- **为什么消除隐患**：颜色回到正常继承链后，任何元素上的显式 `color`（无论选择器强弱）都自然生效，不再需要 `inherit` / 显式白字这类对抗式写法；
- **实测不受影响的特例**：`pre` 的颜色来自 Bootstrap 的 `pre{color:#212529}`（实测 `rgb(33,33,33)`），与继承链无关，改前改后都相同。

**注释联动（5 处）**：`site.css:222`、`site.css:330`、`NavMenu.razor.css:52`、`NavMenu.razor.css:68`、`LoveTime.razor:339`。改写口径统一为"颜色由 body 继承，显式色只是该元素自身的视觉选择"，不要写"会被 div 染色"。显式色本身**保留**（无害，且 tile 白字有对比度理由）。
