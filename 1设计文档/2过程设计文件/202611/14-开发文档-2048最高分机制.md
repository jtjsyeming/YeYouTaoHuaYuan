## 1. 背景与需求

2048 刷新/重开后分数即归零，没有"最好成绩"参照。需求：**在本浏览器内持久化历史最高分**，游戏过程中实时跟进、刷新与重玩不丢失。这是《13》文档"后续可选项"清单中优先级最高的一项（对难度感知/成就动机的影响最大），且不依赖任何存储设计。

**当前基线（已实施项）**：D-15 迁移后页面为 FluentButton + "分数：@Score"；D-01 概率已标准化；`Game_2048.razor` 已有 `@inject IJSRuntime JS`、`OnAfterRenderAsync(firstRender)` 守卫（规避 ServerPrerendered 双执行）、`IAsyncDisposable`——本机制完全复用这套已验证的生命周期。

## 2. 存储选型

| 方案 | 思路 | 结论 |
|---|---|---|
| **A. 浏览器 localStorage（推荐）** | 键 `jtjsym.g2048.best`，JS interop 读写 | **采用**。"最高分"的语义本就是"这台浏览器上的记录"；站点无账户体系，跨设备同步无从谈起 |
| B. 服务端内存（单例字典按 circuit） | 服务端存 | 否。Blazor Server 的 circuit 随刷新/断线销毁，**刷新即丢**，不满足需求；引入并发字典还多一处状态 |
| C. Cookie | 随请求上行 | 否。为一个纯展示值增加每请求负载，语义也不合 |
| D. IndexedDB / 引入 Blazored.LocalStorage 包 | 过重 | 否。一个键值对不值得引包/建库 |

**关键结论：无需新建 JS 文件。** Blazor 的 `InvokeAsync` 支持 `localStorage.getItem/setItem` 这类点分路径调用，两行 interop 即可，不建 `wwwroot/js/` 新模块。

## 3. 详细设计

### 3.1 状态与读写

```csharp
private const string BestKey = "jtjsym.g2048.best";
private int BestScore = 0;
private bool isBestLoaded = false;     // 防重复加载（与键盘模块的 keyModule 判空同型）

// 读取：并入现有 OnAfterRenderAsync 的 firstRender 分支（在键盘注册之前）
if (!isBestLoaded)
{
    isBestLoaded = true;
    try
    {
        var raw = await JS.InvokeAsync<string?>("localStorage.getItem", BestKey);
        if (int.TryParse(raw, out var v) && v > 0) BestScore = v;
    }
    catch (JSException) { /* 隐私模式禁用存储：best 恒 0，游戏照常 */ }
    StateHasChanged();   // 把真实最高分刷到 UI（预渲染首帧为 0，毫秒级补齐）
}

// 写入：破纪录时异步落盘（fire-and-forget）
private void UpdateBestScore()
{
    if (Score <= BestScore) return;
    BestScore = Score;
    _ = WriteBestAsync();
}
private async Task WriteBestAsync()
{
    try { await JS.InvokeVoidAsync("localStorage.setItem", BestKey, BestScore); }
    catch (JSException) { }          // 存储不可用时静默，仅本次会话内有效
    catch (JSDisconnectedException) { }  // 关页/断线，无需处理
}
```

### 3.2 调用点与语义

| 时机 | 行为 | 依据 |
|---|---|---|
| 四个 `MoveXxx()` 在 `AddRandomTile()` 之后 | 调 `UpdateBestScore()`（4 处各加 1 行） | 只在真实得分步后判断；`Merge` 内部保持纯计算不碰 IO |
| `RestartGame()` | **不重置** BestScore | 标准 2048 行为：最高分跨局保留 |
| 游戏结束 | 无特殊处理 | 破纪录发生在得分瞬间而非结束帧 |
| 组件销毁 | 无额外清理 | localStorage 不依赖电路；`isBestLoaded` 随实例消亡 |

### 3.3 展示

```razor
<p>分数：@Score　最高分：@BestScore</p>
```

- 沿用现有 `<p>` 文案风格（同分行内展示），不引入新卡片；
- **可选**：游戏结束遮罩内破纪录时显示"🏆 新纪录！"——一行条件渲染，列为顺带项；
- ServerPrerendered 首帧最高分显示 0，`firstRender` 后补真实值——毫秒级跳变，可接受（与键盘模块同一 trade-off，已在 06/10 文档确立该模式）。

### 3.4 健壮性

- 值损坏（手动改过/旧版本残留）：`int.TryParse` 失败或 ≤0 → 视为 0，下次破纪录自然覆盖；
- 隐私模式/存储被禁：读抛 `JSException` → best 恒 0；写失败静默——**游戏功能零降级**，仅无持久化；
- 键名带 `jtjsym.` 前缀命名空间，未来 Tetris 等页加持久化可复用前缀约定。

## 6. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| `localStorage.getItem` 点分调用在某些宿主不可用 | 读取失败 | try/catch 降级为 0；真遇到再落 JS 模块（方案 A 的备用形态，不预先做） |
| 破纪录步的 setItem 与页面关闭竞态 | 最后一步未落盘 | 影响仅为最高分少记一步的分值，下次得分即修正；不值得做 flush 机制 |
| e2e 断言依赖文案"最高分：" | 文案变更时假失败 | 断言集中在一个 spec 文件内 |

**回退**：还原 Game_2048.razor 一个文件（改动全部集中在该文件）；localStorage 里的键无需清理（新版忽略旧值）。
