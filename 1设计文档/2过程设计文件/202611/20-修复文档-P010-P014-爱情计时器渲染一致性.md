# 20 - 修复文档：P-010/P-014 爱情计时器渲染一致性

> 来源：《3测试报告/2026-11-06.md》§6.1 P-010 / P-014　|　日期：2026-11-06　|　状态：待实施
> 合并理由：两条同在 `LoveTime.razor`，都是"**状态变了但渲染没跟着全量刷新**"的一致性问题，改动集中且互不冲突
> 对应 FT 证据：FT-11（恢复默认后 12 次采样 4 次三行秒数不一致）

---

## 1. 两条问题

**P-010　事件回调后三行秒数瞬时不同步**
`ApplyCustomDate()` / `ResetAnchor()` 只调 `Render(anchor, type)` 重算**当前这一行**，另两行保留上一 tick 的文本（最多差 1 秒），要等下一次秒级 `RefreshAll()` 才对齐。FT-11：点"恢复默认"后 12 次采样 4 次不一致（如 `[34,33,33]`）。既有 LT-22 只在稳态采样，未覆盖该窗口。

**P-014　年份下拉跨年不更新**
`years` 列表在 `OnInitialized` 按 `DateTime.Now.Year` 一次性生成（`LoveTime.razor:109`）；页面从 12-31 停留到次年 1-1（Blazor Server 长驻电路完全可能），年份下拉永远不出现新年份。

## 2. 修复方案

### 2.1 P-010：事件回调统一走全量刷新

`ApplyCustomDate()` 与 `ResetAnchor()` 中，把：

```csharp
Render(anchorDates[type], type);        // 只刷一行
```

改为：

```csharp
RefreshAll();                            // 一次取时、三行同源，天然对齐
```

`RefreshAll()` 本来就是秒级刷新的汇聚点（一次 `DateTime.Now` 三行同源），事件回调复用它即保证三行瞬时一致，还顺带消除了"两行用旧 now、一行用新 now"的取时偏差。单行 `Render` 的其余调用点（ticker 内不需要——ticker 走的就是 RefreshAll）保持不变。

### 2.2 P-014：年份列表跨年自愈

在 `RefreshAll()` 开头加一次轻量检查（每秒一个 int 比较，代价可忽略）：

```csharp
private int yearsBuiltFor = DateTime.Now.Year;

private void EnsureYearsFresh()
{
    var y = DateTime.Now.Year;
    if (y == yearsBuiltFor) return;
    yearsBuiltFor = y;
    years = Enumerable.Range(1950, y - 1949).Select(v => v.ToString()).ToList();
    // selectedYear 保持不变（跨年不影响用户已选的年份）
}
```

- 选每秒检查而非 `visibilitychange` 监听：不引入新 JS 依赖/生命周期钩子，且秒刷循环已存在，成本为零；
- Blazor 会因 `years` 列表引用变化重渲染下拉（`foreach` 重新求值）；`FluentSelect` 的已选值不受选项列表追加影响；
- 副作用评估：跨年瞬间（元旦 0 点）若用户正开着下拉，列表多一项——可接受。
