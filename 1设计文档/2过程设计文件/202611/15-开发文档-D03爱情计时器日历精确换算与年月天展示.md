## 1. 背景与现状

D-03 两项内容，都落在 `LoveTime.razor` 的 `Render()`：

**① 换算是近似式，跨闰年差 1 天**（L204~206）：

```csharp
info.ElapsedTimeYear   = (elapsed.Days / 365).ToString();
info.ElapsedTimeMonths = ((elapsed.Days % 365) / 30).ToString();
info.ElapsedTimeDay    = ((elapsed.Days % 365) % 30).ToString();
```

固定 365/30 拆分，不考虑实际日历（闰日、月份 28~31 天不等）。实锤例子：锚点 2023-08-08、当天 2024-08-08，`elapsed.Days = 366`（2024 年含闰日）→ 旧算法给出"1 年 0 月 **1** 天"，实际应恰好 1 年整。

**② 三个属性只算不展示**：`ElapsedTimeInfo` 的 `ElapsedTimeYear/Months/Day` 无任何 markup 引用，纯死数据；页面每行只显示"X 天, X 小时, X 分钟, X 秒"。

**现状可复用项**：锚点机制（`anchorDates` + 自选/恢复）、`PeriodicTimer` 秒级刷新、`Render()` 单点重算——本次只换"算什么"，不动"怎么刷"。

## 2. 任务 A：日历精确换算

### 2.1 算法（年 → 月 → 余天逐级扣除）

```csharp
// 返回 (years, months, days, totalDays)；now < anchor 时全 0
private static (int y, int m, int d, int total) CalendarElapsed(DateTime anchor, DateTime now)
{
    if (now < anchor) return (0, 0, 0, 0);

    int y = now.Year - anchor.Year;
    var t = anchor.AddYears(y);
    if (t > now) { y--; t = anchor.AddYears(y); }          // 生日未到，回退一年

    int m = (now.Year - t.Year) * 12 + now.Month - t.Month;
    var t2 = t.AddMonths(m);
    if (t2 > now) { m--; t2 = t.AddMonths(m); }            // 周月未到，回退一月

    return (y, m, (now - t2).Days, (now - anchor).Days);
}
```

**为什么用 `AddYears/AddMonths` 而不是自算**：.NET 的 clamp 语义与人类对"周年/月纪念日"的直觉一致——

| 场景 | .NET 行为 | 直觉判断 |
|---|---|---|
| 2020-02-29 +1 年 | 2021-02-28 | 闰日生日的"第一个生日"落在 2-28，符合普遍预期 |
| 2023-01-31 +1 个月 | 2023-02-28 | 月底纪念日的"月纪念日"收敛到月末，业界标准做法 |

自算年月反而要重新发明这套 clamp，无收益。

### 2.2 验证用例表（实施与 e2e 的共同基准）

| # | 锚点 | 计算日 | 期望（年/月/天） | 说明 |
|---|---|---|---|---|
| 1 | 2023-08-08 | 2024-08-08 | 1 / 0 / 0 | **D-03 实锤**：旧算法错给 0/0/1（闰日） |
| 2 | 2020-02-29 | 2021-02-28 | 1 / 0 / 0 | 闰日锚点 clamp |
| 3 | 2023-01-31 | 2023-03-01 | 0 / 1 / 1 | 月末锚点 + 跨 2 月 |
| 4 | 2018-04-22 | 2026-11-05 | 8 / 6 / 14（共 3119 天） | 内置"相识"真实数据 |
| 5 | 任意 | 锚点当天 | 0 / 0 / 0（主行 0 天 0 小时…） | 边界 |
| 6 | 任意 | 锚点次日 | 0 / 0 / 1 | 边界 |

> 用例 4 的总天数以实施时手工核算为准（本文档给出 3119 供对照）；用例 1/2/3 可用"自选日期"功能在页面上直接构造，无需改内置纪念日。

### 2.3 `Render()` 改造

```csharp
var (y, m, d, total) = CalendarElapsed(anchor, now);
info.Years = y; info.Months = m; info.Days = d; info.TotalDays = total;
info.CalendarText = FormatCalendar(y, m, d);
// ElapsedTime 主行保持不变（X 天, X 小时…）
```

注意：日历换算基于**原始** `now` 与 `anchor` 比较，不复用顶部 clamp 后的 `elapsed`（后者已丢时间OfDay前的差异语义）；`now < anchor` 的双保险由 `CalendarElapsed` 开头承担，原有负值钳制保留不动。

## 3. 任务 B：展示设计

### 3.1 数据结构（顺带清理死属性）

```csharp
private sealed class ElapsedTimeInfo
{
    public string ElapsedTime { get; set; } = string.Empty;  // 主行，不变
    public int Years { get; set; }
    public int Months { get; set; }
    public int Days { get; set; }
    public int TotalDays { get; set; }
    public string CalendarText { get; set; } = string.Empty;
}
```

删除 `ElapsedTimeYear/Months/Day` 三个 string 属性（D-03"只算不展示"的死代码，直接移除而非继续维护）。

### 3.2 格式化规则（FormatCalendar）

跳过前导零段，避免"0 年 0 个月 5 天"这类冗余：

| y / m / d | 输出 |
|---|---|
| 8 / 6 / 14 | `8 年 6 个月 14 天` |
| 0 / 6 / 14 | `6 个月 14 天` |
| 0 / 0 / 14 | `14 天` |
| 0 / 0 / 0 | `刚刚开始`（锚点当天，避免空串） |

### 3.3 页面结构

每行计时下方加一行小字副行：

```razor
<div class="timer timer-display">我们相识已经过去了：@elapsedTimes["meet"].ElapsedTime</div>
<div class="timer-calendar">@elapsedTimes["meet"].CalendarText · 共 @elapsedTimes["meet"].TotalDays 天</div>
```

```css
.timer-calendar {
    text-align: center;
    font-size: .85em;
    color: #888;
    margin: -2px 0 8px;
}
```

- "共 N 天"顺带把总天数独立呈现（主行的 `X 天` 在长跨度下读数很大，日历拆分后总天数仍值得单看）；
- `timer-calendar` 是新类，**不**挂 `timer-display`——D-12 的 ≤520px 规则（padding/height）针对三行主行设计，副行文本短、`.85em` 下 375px 无溢出风险，不需要断点规则；若真机实测超宽再补，不预防性加。
