## 2. 任务 A：日历精确换算

### 2.1 算法（年 → 月 → 余天逐级扣除，保留 v1.0 主体）

```csharp
/// <summary>按日历扣减：先满年、再满月、余数为天。now &lt; anchor 全 0。</summary>
private static (int Years, int Months, int Days) CalendarElapsed(DateTime anchor, DateTime now)
{
    if (now < anchor) return (0, 0, 0);

    int y = now.Year - anchor.Year;
    var t = anchor.AddYears(y);
    if (t > now) { y--; t = anchor.AddYears(y); }          // 周年未到，回退一年

    int m = (now.Year - t.Year) * 12 + now.Month - t.Month;
    var t2 = t.AddMonths(m);
    if (t2 > now) { m--; t2 = t.AddMonths(m); }            // 月纪念日未到，回退一月

    return (y, m, (now - t2).Days);
}
```

**不变量**（实施时不必逐条断言，但改算法前先过一遍）：`t ≤ now` 且 `t2 ≤ now` 恒成立 ⇒ `y ≥ 0`、`m ≥ 0`、`m--` 不会出现 -1（`m=0` 时 `t2=t≤now`，不会进入回退分支）、`d ≥ 0`。

### 2.3 明确不要抄《06》§7.1 的参考实现（I-06）

《06…-v2.0》§7.1 给的 `DiffYmd` 用"借贷"式（`days<0` 就 `months--` 并加**上个月**天数），存在两个反例：

|---|---|---|
| 2023-01-31 → 2023-03-01 | `(0, 1, -2)` | 只借一次，`-30 + 28 = -2` **仍为负**，输出"1 个月 -2 天" |

### 2.4 `Render()` 改造

```csharp
private void Render(DateTime anchor, string type, DateTime? now = null)
{
    var n = now ?? DateTime.Now;          // ★ 只取一次时，主行与日历必须同源（I-11）
    var elapsed = n - anchor;
    if (elapsed < TimeSpan.Zero) elapsed = TimeSpan.Zero;   // 原双保险保留

    var info = elapsedTimes[type];
    info.ElapsedTime = $"{elapsed.Days} 天, {elapsed.Hours} 小时, {elapsed.Minutes} 分钟, {elapsed.Seconds} 秒";

    // 日历换算用未 clamp 的 (anchor, n)：anchor 恒为零点，n 含时分秒，故 now<anchor 时由方法内兜底
    var (y, m, d) = CalendarElapsed(anchor, n);
    info.CalendarText = FormatCalendar(y, m, d);
}
```

- `RefreshAll` 已统一 `var now = DateTime.Now`，三条线同源；`ApplyCustomDate`/`ResetAnchor` 走默认参数，各自取一次，语义不变；
- 负值 clamp 与 `CalendarElapsed` 的零值兜底是**两层**保护，不冲突（前者给主行，后者给副行）。

### 3.2 格式化（`FormatCalendar`）—— **跳过所有零段**

```csharp
private static string FormatCalendar(int y, int m, int d)
{
    if (y == 0 && m == 0 && d == 0) return "不到 1 天";

    var parts = new List<string>(3);
    if (y > 0) parts.Add($"{y} 年");
    if (m > 0) parts.Add($"{m} 个月");
    if (d > 0) parts.Add($"{d} 天");

    // 满年且零月零天 → "N 年整"（周年当天的自然说法）
    if (y > 0 && m == 0 && d == 0) parts[^1] = $"{y} 年整";

    return string.Join(" ", parts);
}
```

**规则表（v1.0 只覆盖前 4 行，后 3 行是这次补的）**：

| y / m / d | 输出 | 触发场景 |
|---|---|---|
| 8 / 6 / 14 | `8 年 6 个月 14 天` | 常态 |
| 0 / 6 / 14 | `6 个月 14 天` | 不足一年 |
| 0 / 0 / 14 | `14 天` | 不足一月 |
| 0 / 0 / 0 | `不到 1 天` | 锚点当天（主行 `0 天, X 小时…` 语义一致，比"刚刚开始"更贴） |
| **8 / 0 / 0** | **`8 年整`** | **周年当天（用例 1/2/8）——v1.0 空缺** |
| **8 / 0 / 14** | **`8 年 14 天`** | **周年后不足一月——v1.0 会输出"8 年 0 个月 14 天"** |
| **0 / 6 / 0** | **`6 个月`** | 月纪念日当天 |

> 若作者更想要"刚刚开始"而不是"不到 1 天"，改一行字面量即可；但 `0/0/0` 的文案必须与主行"0 天, 5 小时…"读起来不冲突。

- 不加"共 N 天"（I-03）。若坚持要，把它挂在 `CalendarText` 里拼（`$"{text} · 共 {total} 天"`），但那时 `0/0/0` 会变成"不到 1 天 · 共 0 天"，需要额外分支——所以不如不做。

### 3.4 样式（写在页面 `<style>` 内，桌面/窄屏两套间距）

```css
/* 副行：与上一条主行构成一个视觉块 */
.timer-calendar {
    text-align: center;
    font-size: .85em;
    color: inherit;        /* 继承 .timer 的 #e48bfa，不引入第三种灰（全局 div{color:#886D68} 会被类覆盖） */
    opacity: .65;
    line-height: 1.4;
    margin: -14px 0 12px;  /* 桌面端主行下边距 20px，−14 ≈ 6px 视觉间隔 */
}

@@media (max-width: 520px) {
    .timer-calendar {
        margin: -4px 0 10px;   /* 该断点 .timer-display 的 margin 是 8px */
    }
}
```

> **`@@media` 不是笔误**：《现状》§3.4-6 明确记录过这个坑——razor 的 `<style>` 里单个 `@` 会被当 C# 表达式，直接 `CS0103: 不存在名称 media`。要么写 `@@media`，要么把这段挪进 `site.css`（那样才可以写 `@media`）。本方案选前者，与页面内其它类放一起。

## 5. 测试计划

### 5.1 为什么不用 v1.0 的"相对今天"断言

v1.0 的 5 条里有 4 条在验证"今天/昨天/4 年前"，这类断言**永远碰不到 clamp**（闰日、月末），而 clamp 是这次唯一有争议的语义。`2020-02-29`、`2023-01-31` 这些锚点在页面上**完全可选**（年份 1950 起、日按 `DaysInMonth` 生成），所以正确做法是：**在 Node 里写一份独立实现**（按 §2.1 的规则重写，而不是调 .NET），对一批锚点算出期望文案，再与页面逐条比对——这就是 `g2048` 的 `simulate`/`moveLine` 已经在用的范式。

// D-03：爱情计时器日历精确换算（年/月/天）
// 手法同 G2048-STEP：Node 侧独立实现同一套规则（AddYears/AddMonths 的 clamp），
// 对多个锚点反算期望文案，再与页面副行逐条比对 —— 这样闰日/月末这些边界才真正被覆盖。
import { test } from '@playwright/test';

// ── 独立实现（不调 .NET，按文档规则重写）──
const clampAddMonths = (d, n) => {
  const y = d.getFullYear();
  const m = d.getMonth() + n;
  const first = new Date(y, m, 1);
  const lastDay = new Date(first.getFullYear(), first.getMonth() + 1, 0).getDate();
  return new Date(first.getFullYear(), first.getMonth(), Math.min(d.getDate(), lastDay));
};
const clampAddYears = (d, n) => clampAddMonths(d, n * 12);

function ymd(anchor, now) {
  const a = new Date(anchor.getFullYear(), anchor.getMonth(), anchor.getDate());
  if (now < a) return { y: 0, m: 0, d: 0 };
  let y = now.getFullYear() - a.getFullYear();
  let t = clampAddYears(a, y);
  if (t > now) { y -= 1; t = clampAddYears(a, y); }
  let m = (now.getFullYear() - t.getFullYear()) * 12 + now.getMonth() - t.getMonth();
  let t2 = clampAddMonths(t, m);
  if (t2 > now) { m -= 1; t2 = clampAddMonths(t, m); }
  return { y, m, d: Math.round((now - t2) / 86400000) };
}

function expectText({ y, m, d }) {
  if (y === 0 && m === 0 && d === 0) return '不到 1 天';
  const seg = [];
  if (y > 0) seg.push(`${y} 年`);
  if (m > 0) seg.push(`${m} 个月`);
  if (d > 0) seg.push(`${d} 天`);
  if (y > 0 && m === 0 && d === 0) seg[seg.length - 1] = `${y} 年整`;
  return seg.join(' ');
}

const day = n => new Date(n.getFullYear(), n.getMonth(), n.getDate());
const today = day(new Date());
const shift = (d, n) => new Date(d.getFullYear(), d.getMonth(), d.getDate() + n);

  await page.locator('fluent-button.timer').nth(btnIndex).click();
  await sleep(450);
  return (await subLines(page).nth(btnIndex).textContent())?.trim() ?? '';
}

test.describe('D03 爱情计时器日历年月天', () => {

  test('LT-27 闰日与月末锚点（clamp 语义）', async ({ page }) => {

| 风险 | 影响 | 缓解 |

| clamp 语义与个别用户直觉不同（1-31 的"月纪念日"落 2-28） | 展示争议 | 已在 §2.1/§2.2 用 trace 固化；真不接受才需自算，另立文档 |
