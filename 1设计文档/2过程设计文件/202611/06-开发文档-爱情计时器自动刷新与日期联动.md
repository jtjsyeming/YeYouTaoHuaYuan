# 开发文档：爱情计时器自动刷新与日期选择优化

> 版本：v1.0　|　日期：2026-11-01　|　对应文件：`jtjsym/jtjsym/Pages/MyPage/LoveTime.razor`
> 类型：功能优化开发文档　|　影响面：仅爱情计时器页面

---

## 1. 背景与目标

爱情计时器（/loveTime）当前存在三类交互问题：

1. **计时不会自动刷新**：秒数静止，只有刷新页面才更新，作为"计时器"体验名不副实；
2. **日期选择不联动**：日下拉框固定 1~31，选 2 月 31 日、4 月 31 日等不存在的日期时，`new DateTime(y, m, d)` 会抛异常（未捕获）；
3. **无合法性校验**：选择未来日期会得到负的经过时间，直接展示为负数，语义混乱。

**修复目标**：

- 计时展示每秒自动刷新（三个内置纪念日 + 用户自选计算结果均实时跳动）；
- 日选项随所选年月联动（含闰年 2 月 29 日）；
- 越界日期自动收敛、未来日期给出提示并拒绝计算；
- 不改动其他页面与全站样式。

---

## 2. 现状问题分析

### 2.1 现有实现要点（问题定位）

| 现状代码位置 | 行为 | 问题 |
|---|---|---|
| `OnInitialized()` → 对 `timePoints` 逐个 `CalculateElapsedTime` | 页面加载时计算一次 | 之后不再更新，秒数静止 |
| `days = Enumerable.Range(1, 31)` | 日选项固定 1~31 | 与年/月无联动；选 2 月 31 日 → `new DateTime(2025, 2, 31)` 抛 `ArgumentOutOfRangeException` |
| `CalculateElapsedTime(string type)` 中 `int.TryParse` 后直接 `new DateTime(...)` | 无 try/catch、无未来日期判断 | 非法日期崩溃；未来日期显示负值 |
| 组件未实现 `IDisposable` | — | 本次加计时器必须补上，否则泄漏 |
| `CalculateElapsedTime(DateTime, string)` 中"年/月/天"换算结果存入 `ElapsedTimeYear/Months/Day` | **已计算但从未渲染** | 可顺带在 UI 呈现（可选项，见 §7） |

### 2.2 关键约束：OnInitialized 会执行两次

`_Host.cshtml` 使用 `ServerPrerendered` 模式，组件会经历"预渲染 + 交互连接"两个阶段，`OnInitialized` **执行两次**。

**因此计时器禁止在 `OnInitialized` 里创建**（会创建两个 Timer，预渲染实例可能不被正常 Dispose，导致每秒重复回调）。正确做法：**在 `OnAfterRender(bool firstRender)` 中首次渲染后启动计时器**——只有交互实例会走到该回调，天然规避重复创建。这也是本项目 Tetris 页 Timer 生命周期的同源思路。

## 3. 方案设计

### 3.1 设计总览

```
页面加载
  OnInitialized     → 初始化数据、计算一次三组时间（不建 Timer）
  OnAfterRender(firstRender=true)
                    → 启动 1 秒刷新 Timer（仅交互实例执行一次）
每个 Tick
  Elapsed 回调（线程池线程）
    → isDisposed 检查 → InvokeAsync 切回渲染上下文
    → 依 activeDates[type] 重算三组时间 → StateHasChanged()
用户自选日期
  年/月变更 → days 列表按 DaysInMonth 重建 → selectedDay 越界收敛
  点击计算按钮 → 合法性校验（未来日期拒绝并提示）→ 更新 activeDates[type] → 立即重算
组件销毁
  Dispose() → 停止并释放 Timer
```

### 3.2 核心数据结构调整

引入 **activeDates**（各类型当前生效的锚点日期），解决"自动刷新会覆盖用户自选结果"的冲突：

```csharp
// 现有 timePoints（内置纪念日）保留不动，作为初始锚点
private readonly Dictionary<string, DateTime> timePoints = new()
{
    { "meet", new DateTime(2018, 4, 22) },
    { "love", new DateTime(2022, 2, 25) },
    { "married", new DateTime(2023, 8, 8) }
};

// 新增：各类型当前生效的锚点日期（初始 = 内置纪念日；用户自选后 = 自选日期）
private Dictionary<string, DateTime> activeDates;

// 新增：未来日期提示状态
private string? validationMessage;
```

- `OnInitialized`：`activeDates = new Dictionary<string, DateTime>(timePoints);` 然后按现有逻辑计算一次；
- 用户点"计算XX时间"且校验通过 → `activeDates[type] = selectedDate` 再重算；
- 刷新 Tick 重算时以 `activeDates` 为准 → **用户自选的结果也会持续跳动，且不会被内置纪念日覆盖**。

### 3.3 自动刷新实现

组件声明与生命周期：

```csharp
@implements IDisposable
@using System.Timers

@code {
    private System.Timers.Timer? refreshTimer;
    private bool isDisposed = false;
    private readonly object timerLock = new object();

    protected override void OnAfterRender(bool firstRender)
    {
        if (firstRender)
        {
            StartRefreshTimer();
        }
    }

    private void StartRefreshTimer()
    {
        lock (timerLock)
        {
            if (isDisposed || refreshTimer != null) return;

            refreshTimer = new System.Timers.Timer(1000);
            refreshTimer.Elapsed += OnRefreshTimerElapsed;
            refreshTimer.AutoReset = true;
            refreshTimer.Start();
        }
    }

    private async void OnRefreshTimerElapsed(object? sender, ElapsedEventArgs e)
    {
        if (isDisposed) return;

        try
        {
            await InvokeAsync(() =>
            {
                if (isDisposed) return;
                foreach (var type in activeDates.Keys)
                {
                    CalculateElapsedTime(activeDates[type], type);   // 复用现有计算方法
                }
                StateHasChanged();
            });
        }
        catch (ObjectDisposedException)
        {
            // 组件已销毁，忽略
        }
    }

    public void Dispose()
    {
        isDisposed = true;
        lock (timerLock)
        {
            if (refreshTimer != null)
            {
                refreshTimer.Stop();
                refreshTimer.Elapsed -= OnRefreshTimerElapsed;
                refreshTimer.Dispose();
                refreshTimer = null;
            }
        }
    }
}
```

设计说明：

- 沿用 Tetris 页验证过的模式：`isDisposed` 双检 + `InvokeAsync` 切渲染上下文 + `ObjectDisposedException` 兜底 + `Dispose` 停表；
- 与 Tetris 的差异：只有**一个**常驻 Timer，且启动点在 `OnAfterRender(firstRender)` 而非 `OnInitialized`（规避预渲染双执行，见 §2.2）；
- `refreshTimer != null` 判断是第二道防重复创建保险；
- 每秒仅重算 3 组时间并刷新，页面规模下无性能压力。

### 3.4 年月日联动（DaysInMonth）

日选项由所选年月动态生成，2 月闰年自动为 29 天：

```csharp
private List<string> GetDays()
{
    if (int.TryParse(selectedYear, out int y) && int.TryParse(selectedMonth, out int m))
    {
        return Enumerable.Range(1, DateTime.DaysInMonth(y, m))
                         .Select(d => d.ToString())
                         .ToList();
    }
    return Enumerable.Range(1, 31).Select(d => d.ToString()).ToList();
}
```

UI 侧改动（三个 FluentSelect）：

```razor
<FluentSelect TOption="string" Label="月份：" @bind-Value="selectedMonth"
              ValueChanged="OnYearMonthChanged" ...>   <!-- 年份同理 -->
    @foreach (var d in GetDays()) { <FluentOption Value="@d">@d</FluentOption> }
</FluentSelect>
```

```csharp
private void OnYearMonthChanged(string value)
{
    // selectedYear / selectedMonth 已被双向绑定更新
    var days = GetDays();
    // 越界收敛：如从 1 月 31 日切到 2 月 → 收敛为 2 月最后一天
    if (int.TryParse(selectedDay, out int d) && d > days.Count)
    {
        selectedDay = days[^1];
    }
    validationMessage = null;
}
```

> `FluentSelect` 同时使用 `@bind-Value` 与 `ValueChanged` 时，注意在 `ValueChanged` 回调中不要手动赋值绑定字段造成重复触发；如版本行为异常，可改为只用 `ValueChanged` 手动赋值（`selectedMonth = value;` + 状态更新），两种写法二选一，实施时以实测为准。

- 年份列表保持现状（1950 至当前年份），当前年份内 `DaysInMonth` 均有效；
- `DateTime.DaysInMonth` 天然处理闰年（2024、2028 年 2 月 = 29 天）。

### 3.5 合法性校验（未来日期）

```csharp
private void CalculateElapsedTime(string type)
{
    validationMessage = null;

    if (!(int.TryParse(selectedYear, out int year) &&
          int.TryParse(selectedMonth, out int month) &&
          int.TryParse(selectedDay, out int day)))
    {
        return;
    }

    DateTime selectedDate;
    try
    {
        selectedDate = new DateTime(year, month, day);
    }
    catch (ArgumentOutOfRangeException)
    {
        // 双保险：正常情况下联动已保证合法
        validationMessage = "所选日期不存在，请检查年月日。";
        StateHasChanged();
        return;
    }

    if (selectedDate > DateTime.Now)
    {
        validationMessage = "纪念日不能晚于今天，请重新选择。";
        StateHasChanged();
        return;
    }

    activeDates[type] = selectedDate;                 // 更新锚点
    CalculateElapsedTime(selectedDate, type);         // 立即重算一次
    StateHasChanged();
}
```

UI 提示（计算按钮区下方，条件渲染）：

```razor
@if (!string.IsNullOrEmpty(validationMessage))
{
    <div class="validation-tip" style="color:#d83b01; margin-top:8px;">@validationMessage</div>
}
```

## 5. 测试计划

### 5.1 手工验证用例

| # | 操作 | 期望结果 |
|---|---|---|
| T1 | 打开 /loveTime 停留 3 秒以上 | 三行计时**每秒自动跳动**，无需刷新页面 |
| T2 | 选择一个未来日期（如 2030-12-31），点任一"计算"按钮 | 不计算，显示"纪念日不能晚于今天"红色提示，原计时保持不变 |
| T3 | 选 2024 年 2 月 → 日选项为 1~29（闰年）；切到 2025 年 2 月 → 1~28 | 联动正确 |
| T4 | 先选 1 月 31 日，再切月份为 2 月 | 日自动收敛为 28（或当年 2 月实际天数），无异常 |
| T5 | 选一个合法过去日期点"计算恋爱时间" | 结果立即更新，且**停留观察 3 秒后仍在自动跳动**（锚点生效） |
| T6 | 选 2 月 30 日（若通过 URL/调试绕过联动）点计算 | 显示"所选日期不存在"，页面不崩溃（try/catch 双保险） |
| T7 | 浏览器直接关闭标签页 / 切走后关闭连接 | 服务端日志无 Timer 相关异常（Dispose 生效） |
| T8 | 连续快速点击同一"计算"按钮多次 | 无异常、无重复 Timer（刷新 Timer 始终只有一个） |
| T9 | 回归：2048 / 俄罗斯方块 / 电子木鱼页面 | 行为与改动前一致 |

### 5.2 重点观察项

1. **预渲染双执行**：确认 Timer 只创建一个（可在 `StartRefreshTimer` 临时打断点或日志验证，验证后移除）；
2. **FluentSelect 的 `@bind-Value` + `ValueChanged` 并用行为**：若出现赋值回路/不触发，按 §3.4 注释改为单一写法；
3. `OnAfterRender` 中同步创建 Timer 是否引发渲染警告（不应有，Timer 回调才进 `InvokeAsync`）。

### 5.3 验收标准

1. T1~T6 全部通过；
2. T7 无异常日志（重点：无 `ObjectDisposedException`、无未处理 Timer 回调异常）；

## 6. 风险与权衡

| 风险 | 影响 | 缓解 |
|---|---|---|
| 预渲染阶段组件提前销毁 | Timer 回调抛 ObjectDisposedException | `isDisposed` 双检 + try/catch 兜底（§3.3 已内置） |
| 每秒全页 StateHasChanged | 页面大时有渲染开销 | 当前页面元素少，可忽略；若未来页面复杂化，可改为仅局部组件承载计时展示 |
| SignalR 弱网 | 刷新推送延迟，秒数偶有跳帧 | 可接受；不影响正确性（计算基于 `DateTime.Now`） |
| 服务器长时间运行连接 | Timer 常驻占资源 | 每连接仅 1 个 1s Timer，个人站点规模可忽略 |
