## 1. 问题与现状（均已核实）

### 1.1 H-002 / D-05：备案号链接指向公安部平台

`Index.razor:63`：

```html
<a href="https://beian.mps.gov.cn/#/" target="_blank" rel="noopener">陕ICP备2024056488号</a>
```

两个问题：

1. `beian.mps.gov.cn` 是**公安部**互联网安全管理服务平台（用于公安备案），而 `陕ICP备…` 是**工信部** ICP 备案号，应指向 `beian.miit.gov.cn`；
2. 即使是公安备案号，链接也应是备案号详情，而非平台首页 `#/`。

台账 D-05 当前状态"待确认"（需外部查证）；规范口径明确：ICP 备案号按工信部要求统一链接 `https://beian.miit.gov.cn/`。站点页脚只有 ICP 号、无公安备案号，因此 mps 链接属张冠李戴，修正方向确定。

### 1.2 H-009：CodeAnswer 是未渲染的死字段

`CodingPlace.razor:34` 保留整段 C++ 参考答案字符串，标记中无任何 `@CodeAnswer` 引用，页面只显示题面。C-09 已记载。**信息是有价值的，只是没出口**——直接删除是信息损失，方案应先把"要不要展示"定下来。

### 1.3 H-012：UseHttpsRedirection 在开发判断之外

`Program.cs:20` 的 `app.UseHttpsRedirection()` 注册在 `if (app.Environment.IsDevelopment())` 之外。用 `--no-launch-profile --urls http://localhost:xxxx` 启动时无 https 端口可推断，中间件不重定向只打告警日志（测试报告的 14075 实例即此现象），导致 NF-05 只能在生产环境有确定结论。

## 2. 修复方案

### 2.1 H-002：备案链接改为工信部

```html
<a href="https://beian.miit.gov.cn/" target="_blank" rel="noopener">陕ICP备2024056488号</a>
```

- 说明：工信部备案系统为统一查询入口，无稳定的"备案号详情直链"，指向系统首页即合规惯例（绝大多数站点做法）；
- **文档同步**：《07》§5 第 23 行 NAV-05 描述与 `:132` NAV-06 预期值同步更新为 miit（当前描述是"现状如实描述"，修后必须改预期，否则用例假红）；
- D-05 状态流转：实施 + 手工点击验证 → "待确认" → "已关闭"（关闭依据含工信部规范口径说明）。

### 2.2 H-009：CodeAnswer 用折叠区展示（推荐方案 A）

```html
<details class="code-answer">
    <summary>参考答案（点击展开）</summary>
    <pre>@CodeAnswer</pre>
</details>
```

- **选 A（展示）而非 B（删除）的理由**：参考答案对"编程挑战"页面有真实价值，死字段的病根是"没有出口"不是"不该存在"；原生 `<details>` 零 JS、不引入新 Fluent 组件风险（3.8.0 的 FluentAccordion 表现未验证，不冒这个险）；
- 样式：沿用题面 `<pre>` 的现有深色代码块样式（class 复用），summary 加手型光标；
- 字段本身从 `private string` 改为 `private readonly string`（只读语义固化，CS0414 类问题不再复发——它曾被 D-10 类检查盯上过）；
- 若用户拍板不要展示，则退化为方案 B：删除字段与整段答案文本（实施前以本节为决策点，默认 A）。

### 2.3 H-012：UseHttpsRedirection 移入生产分支

```csharp
if (app.Environment.IsDevelopment())
{
    // ...现有开发配置
}
else
{
    app.UseHttpsRedirection();   // 移入
}
```

- 效果：开发环境 http-only 启动不再刷告警；生产行为完全不变（NF-05 判据不变）；
- 顺带核对：pipeline 中间件顺序移动后 `UseStaticFiles`/`UseRouting` 等相对次序不乱（一行搬家，位置在管线尾部，风险趋零）。
