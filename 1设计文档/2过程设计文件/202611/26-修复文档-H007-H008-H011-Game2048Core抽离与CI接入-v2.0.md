## 2. 方案（重排后的四阶段）

### 阶段①（先做）：满盘用例解锁 —— 不需要抽离 Core

**关键事实**：`Game_2048.razor:451-471` 的恢复路径对存档做结构闸 + 内容闸后 `isGameOver = IsGameOver()`（**重算，不信任存档**），而 **`AddRandomTile` 不在恢复路径里**。所以注入一份合法满盘存档 = 得到确定性的满盘画面。d18 已经证明这条路可用：

```js
// d18_archive_guard.spec.mjs:82-94（G2048-39，已转正）
const dead = [2,4,2,4, 4,2,4,2, 2,4,2,4, 4,2,4,2];
await seed(page, { v: 1, cells: dead, score: 24 });   // 8 个 4 ⇒ 内容闸 cap=32，24 ≤ 32 合法
// → 断言：16 块 / 遮罩出现 / 四方向按钮 disabled
```

**逐条处置**：

| 用例 | 处置 | 判据要点 |
|---|---|---|
| G2048-19（满盘无相邻同值 → 立即结束+遮罩） | **去重**：`G2048-39` 已完全覆盖 → 删除 `g2048.spec.mjs:210-215` 的 fixme 占位，在《07》把 19 标为 `covered by G2048-39` | — |
| G2048-04（结束态观察 + 方向键无效） | 合并进 D02-4：遮罩/禁用由 G2048-39 覆盖，"方向键无效"归 D02-4 | — |
| **G2048-20**（满盘但有一对相邻同值 → 可合并、不结束） | 新增用例 `G2048-43` | 注入下面这个 16 格档 + `score: 0`（cap＝1992，余量充足）：`[2,2,4,8, 4,8,16,32, 8,16,32,64, 16,32,64,128]` —— 只有首行左端一对 2 相邻，其余同值全部错开。向右移动后首行 `[2,2,4,8] → [0,4,4,8]`（合并 2+2 得 4，**+4 分**），腾出的 1 格被 spawn 补回 ⇒ **仍 16 块、无遮罩、总分 4** |
| G2048-05（结束态点遮罩重玩） | 新增用例 `G2048-44` | 注入死局 → 点 `.overlay-replay-btn` → 2 块 / score 0 / 遮罩消失 |
| **D02-4**（结束态键盘失效） | 重写（当前用例体为空）→ `D02-4` | 注入死局 → `keyboard.press('ArrowLeft')` → 盘面签名不变、分数不变 |

**内容闸的两个硬约束（写进用例注释）**：
1. 每块必须是 `[2, 131072]` 内的 2 的幂；
2. `score ≤ Σ v·(log₂v − 1)`：纯 2/4 棋盘 cap = `4 × 4 = 16`（每个 4 贡献 1×4）；注入 `score: 0` 最稳。

### 阶段③：CI 接入（H-007）

`.github/workflows/tests.yml`（**已按 v1.0 的两处硬错修正**）：

```yaml
name: tests
on:
  push: { branches: [main] }
  pull_request: {}
  schedule: [{ cron: '0 22 * * *' }]        # UTC 22:00 = 北京 06:00
jobs:
  e2e:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with: { dotnet-version: 8.0.x }
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: tools/e2e/package-lock.json
      - run: npm ci
        working-directory: tools/e2e
      # PR/push 只装 chromium；夜间任务才装 firefox（见下面的条件）
      - run: npx playwright install --with-deps chromium ${{ github.event_name == 'schedule' && 'firefox' || '' }}
        working-directory: tools/e2e
      # PR/push：只跑 chromium 全量（≈2/3 时长）
      - if: github.event_name != 'schedule'
        run: npx playwright test --project=chromium
        working-directory: tools/e2e
      # 夜间：双浏览器全量（Firefox 是 P-017 的常态观测窗口）
      - if: github.event_name == 'schedule'
        run: npx playwright test
        working-directory: tools/e2e
      - if: always()
        uses: actions/upload-artifact@v4
        with: { name: playwright-report, path: tools/e2e/playwright-report }
```

要点：

1. **不要写 `env: BASE_URL`**（v1.0 的 `''` 会让 `baseURL` 变成空串 → 全红）。缺省即 `http://localhost:14074`，由 `webServer` 自启（`reuseExistingServer: true` 在 CI 上等价于"没有就直接起"）；
2. **不要单独 `dotnet build -c Release`**：`webServer` 的 `dotnet run` 会自己 build（Debug），Release 那步纯属浪费且配置不一致。若要 Release 验证，另立 job；
3. `--project=chromium` 是**必需**的，否则 PR 也跑 firefox（多 30% 时长且与"分层"策略矛盾）；
4. `webServer.command` 已带 `--environment Development`（缺了它 Fluent 静态资源 404，所有尺寸断言假绿）——这一点在 `playwright.config.mjs` 里有大段注释，**不要为了 CI 去改它**；
5. **时长与分钟数**：本地全量 19~21 分钟（含 TRIS-14 320s、TRIS-26 240s 两座固定的山）；ubuntu 2 核预计 30~45 分钟。私有库 2000 分钟/月 → 夜间每天一次约 900~1350 分钟，PR 再跑就爆。**建议**：夜间全量保留，PR 只在 `pull_request` 上跑 `--grep "NAV-|FISH-|G2048-|LT-|TRIS-0|D14-"` 的子集（≈8 分钟），或把夜间改成每周三次（`cron: '0 22 * * 1,3,5'`）。这一项要在落地前拍板，否则第一次月底就会收到配额警告。

### 阶段④：抽离 Game2048Core（H-008 根治，**最后做**）

按《05》§6.2 的既定设计落地，只搬线粒度逻辑：

```csharp
// jtjsym/jtjsym/Services/Game2048Core.cs
namespace jtjsym.Services;
public static class Game2048Core
{
    /// <summary>压缩 → 成对消费 → 尾补零。score 累加走 ref（与原 Merge 语义一致）。</summary>
    public static int[] Merge(int[] line, ref int score) { /* 原 :336-370 逐行搬迁 */ }

    /// <summary>无空格且无相邻同值才判死。棋盘以扁平 16 格传入（组件侧一行 Cast 即可）。</summary>
    public static bool IsGameOver(int[] flat, int size = 4) { /* 原 :172-197 */ }

    /// <summary>90/10 取值（D-01 常量随迁）。</summary>
    public static int SpawnValue(Random rng, int fourPercent = 10) => rng.Next(100) < 100 - fourPercent ? 2 : 4;
}
```

组件侧改动只有三处：`Merge(...)` 调用改 `Game2048Core.Merge(line, ref Score)`、`IsGameOver()` 改 `Game2048Core.IsGameOver(board.Cast<int>().ToArray())`、`AddRandomTile` 的取值改 `SpawnValue(random)`。**棋盘仍是 `int[,]`**，`AfterMove(int[,])`、`IsBoardChanged(int[,],int[,])`、D-16/D-17 的存档代码一行不动。

> `board.Cast<int>().ToArray()` 的遍历顺序是行主序（`[0,0],[0,1]…`），与存档的 `i/GridSize, i%GridSize` 完全一致，不会引入转置错误。

| 《05》§4.3 | **9 组** | 已核对存在（`[2,2,2,2]→[4,4,0,0] +8` 等，含 `[8,8,8,8]`、`[2,2,4,4]`） |

## 5. 风险与边界

| 风险 | 处置 |
|---|---|
