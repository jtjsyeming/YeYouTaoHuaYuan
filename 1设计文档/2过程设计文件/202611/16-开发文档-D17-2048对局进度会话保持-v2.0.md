### 1.2 生命周期链（I-01 的判据）

`Pages/_Host.cshtml:L8` → `<component type="typeof(App)" render-mode="ServerPrerendered" />`，故每次进入 `/game_2048` 都有**两个实例**：

```
预渲染实例（无 circuit，OnAfterRenderAsync 不会跑）
  OnInitialized → RestartGame()            ← board 已在服务端内存里，但页面还没交互
───────────────────  HTML 回浏览器、Hub 连上  ───────────────────
交互实例（真正可交互）
  OnInitialized → RestartGame()            ← 【I-01 的雷】此处若保存，存档被新开局覆盖
  render → OnAfterRenderAsync(firstRender) ← 唯一的 JS interop 窗口
      ① 读 best（localStorage）
      ② 【新增】读存档（sessionStorage）并覆盖 board
      ③ 注册键盘
```

三个直接推论，全部与 I-01 相关：

1. **写只能在交互实例发生**：预渲染实例里调 `JS.InvokeVoidAsync` 抛的是 `InvalidOperationException`（"JavaScript interop calls cannot be issued at this time…"），**不是** `JSException` —— v1.0 的 `catch (JSException)` 兜不住。而且它被包在 `async Task` 里，会变成**未观察异常**，静默污染日志。
2. **`OnInitialized` 里那次 `RestartGame` 必须"不写"**：否则用户在页面上看到的、以及下一帧读到的，都是这次调用刚生成的随机新局。**恢复路径被自己写死。**
3. **`RestartGame` 不能简单拆成"初始化版 / 按钮版"**：它在 L34 与 L40 两处 `@onclick` 上，且用户点"重玩"后**必须**落盘（v1.0 的"覆盖而非清除"论证是对的）。拆分要改三处调用，收益不如一个闸门标志。

## 2. 存储选型（沿用 v1.0，补两条支撑论据）

| 方案 | 语义 | 结论 |
|---|---|---|
| **A. sessionStorage（采用）** | 标签页会话级：切页/刷新/切后台都在，关标签即清 | 采用。"本次访问"逐字匹配 |
| B. localStorage（best 所用） | 跨会话永久 | 否。属"过程"不属"纪录"；且**两个标签页会互相覆盖**——A 标签玩到一半，B 标签开一局，回来 A 的进度就变成 B 的 |
| C. 服务端内存字典 | circuit 外缓存 | 否。circuit 销毁正是要解决的问题；引入全局状态与并发清理得不偿失 |

补充论据（v1.0 未写，但恰是选 A 的实证理由）：

- **多标签天然隔离**：sessionStorage 按 tab 分桶，同一浏览器开两局互不干扰；localStorage 是 origin 级共享，一定会互相踩。
- **隐私模式不炸**：Safari 无痕/部分企业策略下 `sessionStorage.setItem` 抛 `QuotaExceededError`（→ `JSException`），降级为"无会话保持"，游戏零影响——与 D-16 的降级口径一致。

键名 `jtjsym.g2048.session`（沿用 `jtjsym.` 命名空间约定；与 `jtjsym.g2048.best` 前缀相同、后缀区分语义）。

## 3. 详细设计

### 3.1 序列化格式与 DTO（两个编译/运行期坑先钉死）

`board` 是 `int[,]`，**System.Text.Json 不支持多维数组**（`NotSupportedException`）→ 必须扁平化。存档：

```json
{ "v": 1, "cells": [2,0,4,0, 0,0,0,0, ...16 个...], "score": 1234 }
```

```csharp
// 文件顶部（L2 之后）—— 全仓此前无任何 System.Text.Json 引用，ImplicitUsings 也不含它
@using System.Text.Json
@using System.Text.Json.Serialization
```

```csharp
// @code 内，字段区之后
private const string SessionKey = "jtjsym.g2048.session";
private bool isSessionReady;   // 恢复流程已启动（含失败）：之前一律不写，见 §3.2

/// <summary>存档 DTO。Cells 可为 null —— 缺字段的合法 JSON 会走到这条分支，必须靠模式匹配挡掉而非 NRE。</summary>
private sealed class SessionState
{
    [JsonPropertyName("v")]     public int V { get; set; }
    [JsonPropertyName("cells")] public int[]? Cells { get; set; }
    [JsonPropertyName("score")] public int Score { get; set; }
}
```

- `v` 版本号：将来棋盘尺寸/结构变化时**丢弃旧档**而非错解；
- `cells` 行优先扁平：`board[i / GridSize, i % GridSize]`；
- **不存 `isGameOver`**：恢复后用 `IsGameOver()` 重算，单一事实源，杜绝"存档说没结束、棋盘其实已死"；
- 属性用 `{ get; set; }` 而非 `init`：`private sealed class` + 隐式公共无参构造，反射反序列化零悬念（本项目无 source generator，走反射路径）。

### 3.2 `isSessionReady`：一个标志同时管住"写闸门"和"恢复入口"

这是 v2.0 修 I-01 的核心，**不能删、不能改成 try/catch**：

```csharp
/// 语义：恢复流程开始前为 false。它同时承担两件事 ——
/// ① 写闸门：预渲染/初始化那次 RestartGame 一律不写（否则用新开局冲掉存档）；
/// ② 一次性判据：恢复只跑一次。
/// 注意：不能靠 catch 兜底 —— 预渲染里 JS 调用抛的是 InvalidOperationException，不是 JSException。
private bool isSessionReady;
```

闸门放在 `SaveSessionAsync()` 第一行（§3.3），开闸放在恢复分支第一行（§3.4）。两处必须是**同一个**字段，否则无法保证"`RestartGame` 先跑、恢复后跑"这个顺序下的唯一正确性。

### 3.3 写：`AfterMove` 汇聚点 + `RestartGame` 末尾

```csharp
private async Task SaveSessionAsync()
{
    if (!isSessionReady) return;              // ★ 预渲染 / 恢复前：绝不写

    try
    {
        // 快照在第一个 await 之前完成 —— 故 fire-and-forget 晚完成也不会读到"后来的盘面"
        var cells = new int[GridSize * GridSize];
        for (int r = 0; r < GridSize; r++)
            for (int c = 0; c < GridSize; c++)
                cells[r * GridSize + c] = board[r, c];

        var json = JsonSerializer.Serialize(new SessionState { V = 1, Cells = cells, Score = Score });
        await JS.InvokeVoidAsync("sessionStorage.setItem", SessionKey, json);
    }
    catch (JSException) { }                   // 隐私模式 / 配额超限
    catch (JSDisconnectedException) { }       // 切页/断线：此时往往已经写成功，丢失也不影响下一变更点
    catch (ObjectDisposedException) { }       // 电路已释放（与 D-16 的 WriteBestAsync 同口径）
}
```

两个调用点：

```csharp
private void AfterMove(int[,] boardBefore)
{
    if (!IsBoardChanged(boardBefore, board)) { StateHasChanged(); return; }

    UpdateBestScore();
    AddRandomTile();
    if (IsGameOver()) isGameOver = true;

    _ = SaveSessionAsync();                   // ★ void 方法内 fire-and-forget（同 L300 的 _ = WriteBestAsync()）
    StateHasChanged();
}

private void RestartGame()
{
    board = new int[GridSize, GridSize];
    Score = 0;
    AddRandomTile();
    AddRandomTile();
    isGameOver = false;

    _ = SaveSessionAsync();                   // 覆盖为新局；初始化那次被 isSessionReady 闸门挡掉
}
```

| 写入点 | 时机 | 语义 |
|---|---|---|
| `AfterMove()`（D-16 已确立的唯一汇聚点） | 每步**有效**移动后（早退分支不写） | 保存当前局 |
| `RestartGame()` 末尾 | 点"重玩" | **覆盖为新局存档（不是清除）** |

> **为什么"重玩"是覆盖而不是清除**：若清除，"重玩 → 立刻切页 → 回来"会走"无存档"分支得到**全新随机局**——用户看到的是"重玩被撤销了一半"（旧局没了，但新局的盘面也不是他刚看到的那个）。覆盖才自洽：重玩后的第一屏原样回来。

> **为什么不在 `DisposeAsync` 里写**：手机切后台时 circuit 可能直接死亡，`DisposeAsync` 里的 interop 只会拿到 `JSDisconnectedException`。即写即存是唯一可靠时机；每步一次往返与 D-16 的 best 写入同级（1ms 量级），可接受。

### 3.4 恢复：并入 `OnAfterRenderAsync(firstRender)`，**位置不可调换**

```csharp
protected override async Task OnAfterRenderAsync(bool firstRender)
{
    if (!firstRender) return;

    // ① 读最高分（现有，必须排在 ② 之前 —— 见下方"顺序约束"）
    if (!isBestLoaded)
    {
        isBestLoaded = true;
        try
        {
            var raw = await JS.InvokeAsync<string?>("localStorage.getItem", BestKey);
            if (int.TryParse(raw, out var v) && v > 0) BestScore = v;
        }
        catch (JSException) { }
        catch (JSDisconnectedException) { }
        StateHasChanged();
    }

    // ② 恢复对局（新增）
    if (!isSessionReady)
    {
        isSessionReady = true;                 // 先开闸：即使下面全失败，也不能永久不写
        try
        {
            var json = await JS.InvokeAsync<string?>("sessionStorage.getItem", SessionKey);
            var st = json is null ? null : JsonSerializer.Deserialize<SessionState>(json);

            // 嵌套属性模式：Cells 为 null 时**匹配失败**，不会 NRE（I-04）
            if (st is { V: 1, Cells.Length: GridSize * GridSize })
            {
                var cells = st.Cells!;
                for (int i = 0; i < cells.Length; i++)
                    board[i / GridSize, i % GridSize] = cells[i];

                Score = st.Score;
                isGameOver = IsGameOver();     // 重算，不信任存档；死局自然出遮罩
                UpdateBestScore();             // 存档分若高于本地纪录（best 被清过），补一次
                StateHasChanged();             // 预渲染首帧是新局，这一帧必须刷成恢复态
            }
            // 无存档 / 版本不符 / 长度不符 / 损坏 → 保持 OnInitialized 的初始新局，静默
        }
        catch (JSException) { }
        catch (JsonException) { }              // 半截 JSON
        catch (JSDisconnectedException) { }
        catch (ObjectDisposedException) { }
    }

    // ③ 键盘注册（现有，不动）
    if (keyModule is not null) return;
    /* … 原逻辑 … */
}
```

**顺序约束（硬性，不是风格）**：`①` 必须在 `②` 之前。

- 反例：若先恢复再读 best，此刻 `BestScore` 还是字段初始值 `0`；恢复出的 `Score = 100` 会让 `UpdateBestScore()` 判定"破纪录"，把 `localStorage['jtjsym.g2048.best']` 里真实的 **500 覆盖成 100**。`UpdateBestScore` 的 `Score <= BestScore` 只防"变小"，防不了"基准还没加载"。
- 这条已在 e2e 里守起来：G2048-35 预置 best=500 再走子往返，断言 `最高分` 仍是 500（§5.2）。

其余要点：

- **恢复成功必须 `StateHasChanged()`**：`OnInitialized` 已经渲染过一次新局，交互实例又要再 `RestartGame()` 一次，不加这一句用户看到的就是新局；
- 首帧会闪一次新局（预渲染 HTML 里就是新局），恢复在毫秒级补齐——与 D-16 的 best、D-02 的键盘同一 trade-off，历史上无感知；
- 本段有两次 `StateHasChanged()`（`①` 末尾、`②` 内）。合并不是必需，两帧都在同一渲染批次窗口内，实测无感知；**不要为了省一帧去动 `①`（它负责把预渲染的 `0` 补成真实 best）**。

### 3.5 与 D-16（best）的协同

| | best（C-06） | 进度（D-17） |
|---|---|---|
| 存储 | `localStorage` | `sessionStorage` |
| 生命周期 | 永久（跨会话） | 本次访问（关标签即清） |
| 多标签 | 共享，会互相覆盖 | 各 tab 独立 |
| 重玩 | 不清（纪录保留） | **覆盖为新局** |
| 读取 | firstRender `①` 段 | firstRender `②` 段（依赖 `①` 已完成） |

两者唯一耦合点是 `UpdateBestScore()`：恢复后补调一次，使"存档分 > 本地纪录"（例如用户清过 localStorage 但没关标签）时纪录能自愈。语义仍是只增不减，不会因恢复旧局把 best 刷爆——旧局分数必然 ≤ 当时已写入的 best。

### 5.2 新增 `tools/e2e/tests/d17_session.spec.mjs`

**手法**：往返类用例一律比**盘面签名**（`sig`），不比"2 块 / 0 分"——恢复失败时页面同样是 2 块 0 分，只比形态等于恒真。切页一律走**客户端路由点击**（`nav a.fluent-nav-link`），因为 `page.goto` 与 NavLink 点击在 Blazor Server 下走的是两条不同路径（前者换 circuit、后者组件 `Dispose` 后再 `OnInitialized`），两条都要覆盖。

```js
// D-17：2048 对局进度会话保持（sessionStorage `jtjsym.g2048.session`）
// 手法：断言一律"盘面签名 + 分数 + 存档原文"三方对照。只比"2 块、0 分"测不出恢复
//      —— 恢复失败时新开局的形态与期望完全一样，必须比具体盘面才具备判别力。
import { expect, test } from '@playwright/test';
import {
  check, checkEq, clickDir, countTiles, open, readBest, readBoard, readScore, readSession, sleep, trackErrors,
} from './helpers.mjs';

const BEST_KEY = 'jtjsym.g2048.best';
const DIRS = ['left', 'down', 'right', 'up'];

/** 盘面签名：16 格按行拼成字符串，用于"是否同一盘面"的精确比对 */
const sig = b => b.map(r => r.join(',')).join('|');

/** 站内切页往返（客户端路由：组件会 Dispose，再回来是新实例 —— D-17 的主场景） */
async function leaveAndReturn(page) {
  await page.locator('nav a.fluent-nav-link', { hasText: 'jtjsym' }).first().click();   // 回首页
  await sleep(1200);
  await page.locator('nav a.fluent-nav-link', { hasText: '2048' }).first().click();     // 再进 2048
  await sleep(400);            // 恢复在 firstRender，毫秒级；真等不到交给 expect.poll 判红
}

/** 走子直到分数 ≥ min（2048 前几步必有合并）。打死就停，别点重玩——重开会把存档覆盖掉。 */
async function playUntilScore(page, min = 4, max = 30) {
  for (let i = 0; i < max && (await readScore(page)) < min; i++) {
    if (await page.locator('.game-over').count()) return false;
    await clickDir(page, DIRS[i % 4]);
  }
  return (await readScore(page)) >= min;
}

const waitBoard = (page, s) => expect.poll(async () => sig(await readBoard(page)), { timeout: 7000 }).toBe(s);

test.describe('D17 2048 对局进度会话保持', () => {
  test('G2048-30 无存档首进：2 块开局且不写档', async ({ page }) => {
    await open(page, '/game_2048', 1800);
    const b = await readBoard(page);
    checkEq(
      'G2048-30',
      { tiles: countTiles(b), score: await readScore(page), archive: await readSession(page) },
      { tiles: 2, score: 0, archive: null },
      '初始化那次 RestartGame 不得落盘 —— 一旦落盘就会冲掉上次的存档，这是 D-17 最容易写错的地方',
    );
  });

  test('G2048-31 站内切页往返：盘面与分数原样恢复', async ({ page }) => {
    await open(page, '/game_2048', 1800);
    const ok = await playUntilScore(page);
    const b = await readBoard(page);
    const s = await readScore(page);
    check('G2048-31-前置', ok && s > 0, `已走子到分数 ${s}（盘面 ${sig(b)}）`);
    check('G2048-31-存档', (await readSession(page)) !== null, '每步有效移动后应有存档');

    await leaveAndReturn(page);
    await waitBoard(page, sig(b));
    await expect.poll(() => readScore(page), { timeout: 7000 }).toBe(s);
  });

  test('G2048-32 刷新：进度保持（sessionStorage 跨刷新）', async ({ page }) => {
    await open(page, '/game_2048', 1800);
    await playUntilScore(page);
    const b = await readBoard(page);
    const s = await readScore(page);
    check('G2048-32-前置', s > 0, `刷新前分数 ${s}`);

    await page.reload({ waitUntil: 'domcontentloaded' });
    await page.waitForFunction(() => !!window.Blazor, null, { timeout: 15000 }).catch(() => {});
    await waitBoard(page, sig(b));
    await expect.poll(() => readScore(page), { timeout: 7000 }).toBe(s);
  });

  test('G2048-33 重玩后切页回来：是新局而非旧档', async ({ page }) => {
    await open(page, '/game_2048', 1800);
    await playUntilScore(page);
    const oldSig = sig(await readBoard(page));

    await page.locator('.replay-btn').first().click();
    await sleep(600);
    const b2 = await readBoard(page);
    const s2 = await readScore(page);
    check('G2048-33-重玩', countTiles(b2) === 2 && s2 === 0, `重玩后 ${countTiles(b2)} 块、分数 ${s2}`);
    // 判据自检：新局盘面必须与旧局不同，否则下面"恢复成哪一局"根本分不出来
    check('G2048-33-换盘', sig(b2) !== oldSig, '重玩必须换一块新盘');

    await leaveAndReturn(page);
    // 覆盖 → 回来是 b2；若实现成"清除存档"→ 回来是第三块随机盘，签名不符即红
    await waitBoard(page, sig(b2));
    await expect.poll(() => readScore(page), { timeout: 7000 }).toBe(0);
  });

  test('G2048-34 坏档容错：非 JSON / 版本不符 / 缺字段 / 长度不符 → 均新局', async ({ page }) => {
    const errs = trackErrors(page);
    const bad = [
      'xyz',                                                              // 非 JSON
      JSON.stringify({ v: 2, cells: Array(16).fill(0), score: 0 }),        // 版本不符
      JSON.stringify({ v: 1 }),                                            // 缺 cells（易 NRE 的那条）
      JSON.stringify({ v: 1, cells: [2, 4], score: 9 }),                   // 长度不符
    ];

    await open(page, '/game_2048', 1800);
    const rows = [];
    for (const payload of bad) {
      await page.evaluate(([k, v]) => sessionStorage.setItem(k, v), ['jtjsym.g2048.session', payload]);
      await page.reload({ waitUntil: 'domcontentloaded' });
      await page.waitForFunction(() => !!window.Blazor, null, { timeout: 15000 }).catch(() => {});
      await sleep(900);
      const b = await readBoard(page);
      rows.push({ payload: payload.slice(0, 26), tiles: countTiles(b), score: await readScore(page) });
    }
    check('G2048-34', rows.every(r => r.tiles === 2 && r.score === 0), JSON.stringify(rows));
    check('G2048-34-无异常', errs.length === 0, errs.length ? errs.slice(0, 3).join(' | ') : '4 种坏档全程无 console error / pageerror');
  });

  test('G2048-35 与最高分协同：预置 500，恢复不得改写纪录', async ({ page }) => {
    // 只在键不存在时写：addInitScript 每次导航（含 reload）都会重跑，无条件写会把刚破的纪录冲掉
    await page.addInitScript(
      ([k, v]) => { if (localStorage.getItem(k) === null) localStorage.setItem(k, v); },
      [BEST_KEY, '500'],
    );
    await open(page, '/game_2048', 1800);
    await playUntilScore(page);
    const b = await readBoard(page);
    const s = await readScore(page);
    check('G2048-35-前置', s > 0 && s < 500, `分数 ${s} 须落在 (0,500) 内，才能验证"恢复不会把纪录冲成当前分"`);

    await leaveAndReturn(page);
    await expect.poll(() => readBest(page), { timeout: 7000 }).toBe(500);   // ← 恢复若排在读 best 之前，这里会是当前分
    await waitBoard(page, sig(b));
    await expect.poll(() => readScore(page), { timeout: 7000 }).toBe(s);
  });

  test('G2048-36 会话边界：新上下文全新开局（证明用的是 sessionStorage 而非 localStorage）', async ({ page, browser }) => {
    await open(page, '/game_2048', 1800);
    await playUntilScore(page);
    check('G2048-36-前置', (await readSession(page)) !== null, '本上下文已有存档');

    const ctx = await browser.newContext({ baseURL: new URL(page.url()).origin });
    const p2 = await ctx.newPage();
    try {
      await open(p2, '/game_2048', 1800);
      const b = await readBoard(p2);
      checkEq(
        'G2048-36',
        { tiles: countTiles(b), score: await readScore(p2), archive: await readSession(p2) },
        { tiles: 2, score: 0, archive: null },
        '新标签/新会话不得继承上一会话的残局 —— 换成 localStorage 实现时这条必红',
      );
      check('G2048-36-原会话', (await readSession(page)) !== null, '原上下文存档不受另一个上下文影响');
    } finally {
      await ctx.close();
    }
  });
});
```

### 5.5 手工清单（真机，e2e 无法覆盖 circuit 死亡）

1. 玩几步 → 切后台/锁屏 30 秒 → 回来接续；
2. 切后台 **超过 1 分钟**（circuit 已被服务端回收）→ 回来仍接续（这条只有真机能验，`sessionStorage` 在浏览器侧、与 circuit 无关）；

4. 点"重玩" → 立刻切页 → 回来是**重玩后那一局**（不是重玩前，也不是第三块随机盘）；
5. 同一浏览器开两个标签各玩一局 → 互不干扰（sessionStorage 分桶）；
6. 观察首帧是否有可感知闪动（预期不可，毫秒级）。

## 6. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| 初始化那次 `RestartGame` 落盘，把存档冲成新局 | **功能完全失效且不报错**（症状是"看起来做了，就是恢复不出来"） | `isSessionReady` 闸门（§3.2）+ G2048-30 直接断言"首帧 archive 为 null" |
| `AfterMove` 是 `void`，误用 `await` / `async void` | CS 编译失败 / 异常穿进渲染树终止 circuit | `_ = SaveSessionAsync()`（§3.3），与 D-16 同款 |
| 恢复排在读 best 之前 | **最高分纪录被改成当前分**（500 → 100） | §3.4 顺序约束 + G2048-35 断言 `best === 500` |
| 每步一次 interop 写入 | 弱网下略增延迟感 | fire-and-forget 不阻塞移动渲染；快照在 await 前完成，晚完成不影响正确性 |
| 手机进程被系统杀掉 | sessionStorage 随进程消失，无法恢复 | 属"本次访问"之外的冷启动，文档如实声明边界，不补救 |
| 存档 schema 演进 | 旧档错解 | `v` 版本号 + 长度校验 + 四项坏档用例 |
| 恢复闪帧（预渲染新局 → 恢复旧局） | 轻微视觉跳动 | 与 best 同模式；真机可感知再启用 §7 的提示条方案 |
| 与 D-16 的 G2048-27 正面冲突 | `test:d16` 必红 | §5.3 随本次一并改写该用例（**不是豁免**） |

**回退**：还原 `Game_2048.razor` 单文件（并恢复 G2048-27 原断言）。sessionStorage 残键无需清理——无存档路径天然容错。

## 7. 明确不做 / 后续可选

- **不做"继续上局？"提示条**：当前按无感恢复实现；若真机闪帧可感知再启用（需新增状态 + 顶部条 + 与结束遮罩互斥）；
- **不做跨会话续玩**（localStorage 降级）：破坏"纪录 vs 过程"的语义分工，不值得；
- **不做服务端存档**：无用户体系，引入存储层与清理策略远超收益；
- **Tetris 同机制**另行立项：它的状态是"网格 + 计时器三件套"，恢复需重建 Timer 且跳过预渲染双实例，复杂度不在一个量级；
- **不做"存档加密/防改"**：纯本地娱乐站，改档无收益可言。
