## 1. 问题与现状（均已核实）

### 1.1 H-004 / D-09：`.btn-primary` 全局类名

两处定义：

- `Counter.razor:11` 的 `<style>` 内：木鱼按钮样式（48×48、counter.gif 背景图），`FluentButton class="btn-primary"`（`:36`）引用；
- `site.css:14` 另有一处 `.btn-primary`。

问题：`.btn-primary` 与 Bootstrap 同名，而站点仍依赖 Bootstrap 骨架；两处定义互相覆盖关系取决于加载顺序，新增页面若想要 Bootstrap 语义的主按钮会被木鱼样式劫持（或反之）。属于《12》文档 L1 迁移后的残留命名债务。

### 1.2 H-005：site.css 乱码注释

6 处注释为 GBK 字节按 Latin-1 存成 UTF-8（已定位）：`:63 / :64 / :73 / :74 / :98 / :99`，例如：

```css
justify-content: center; /* Ë®Æ½¾ÓÖÐ */        ← 实为"水平居中"
align-items: center; /* ´¹Ö±¾ÓÖÐ */             ← 实为"垂直居中"
```

无功能影响，但不可读、不可维护；根因是当年编辑器以 GBK 保存后又被按 Latin-1 转写。

### 1.3 H-010：`div { color: #886D68 }` 标签选择器

`site.css:91` 用标签选择器给**所有 div** 上默认色。继承机制上它**压过从父元素继承的颜色**（标签选择器特异性 0,0,1 > 继承），导致：

- NavMenu 必须显式 `color:inherit` 规避；
- tile 8 以上必须显式白字（`site.css:222` 注释记载）；
- `.card-body` 必须显式给色（`site.css:330` 注释记载）；

每新增一个组件都可能踩一次，是持续性的样式税。

## 2. 修复方案

### 2.1 H-004：`.btn-primary` → `.muyu-btn`

- `Counter.razor`：`<style>` 内类名与 `FluentButton` 的 `class` 属性同步改为 `.muyu-btn`（语义=木鱼按钮，杜绝与任何框架撞名）；
- `site.css:14` 的 `.btn-primary`：先查引用——若全站再无其他使用点则**删除**；若有使用点则一并迁移为新名（实施第一步 grep 确认，预期为孤儿定义）；
- **e2e 同步（必改）**：`btn-primary` 选择器在三个 spec 中共 **15 处**——`nav_fish.spec.mjs`（9）、`code_nf.spec.mjs`（3）、`smoke.spec.mjs`（3），全部改为 `.muyu-btn`。这是本条的主要回归面，漏改即假红。

### 2.3 H-010：`div{color}` → `body{color}`

```css
/* 改前 */ div { color: #886D68; }
/* 改后 */ body { color: #886D68; }
```

- **为什么等价**：站点所有可见文本都在 body 内，div 后代原本经"div → 逐层继承"获得 #886D68，改后经"body → 逐层继承"获得同值；视觉结果不变；
- **为什么消除隐患**：颜色变成正常继承链，任何元素上的显式 `color`（无论选择器强弱）都自然生效，不再需要 `inherit`/显式白字这类对抗性写法；新组件默认即正确；
- **视觉差量（唯一要查的）**：当前**不在任何 div 内**的文本元素拿的是浏览器默认色（黑），改后变 #886D68。实施时逐页排查：预期此类元素极少（文本几乎都被布局 div 包住），有则显式补色；
- 联动清理：`site.css:222`、`:330` 两处"会被 div 染色"的注释同步改写（对抗性写法可保留——显式色无害，但注释要反映新机制，或顺手简化写法并回归验证）。
