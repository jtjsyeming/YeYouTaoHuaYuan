# 开发文档：移动端网格自适应缩放（Tetris / 2048）

> 版本：v1.0　|　日期：2026-11-01
> 对应文件：`jtjsym/jtjsym/Pages/MyPage/Tetris.razor`、`jtjsym/jtjsym/wwwroot/css/site.css`
> 类型：缺陷修复 / 响应式优化　|　影响面：Tetris、2048 两页的样式与 Tetris 一处内联样式

---

## 1. 背景与目标

《03-界面与交互设计.md》改进清单第 5 条指出：移动端 Tetris 按钮区已适配，但 **10×20 与 4×4 网格使用固定像素尺寸**，小屏幕上溢出或显示局促。本设计用 `min()`/`vw`（CSS 变量方案）解决。

**目标**：

- Tetris 网格在 ≤480px 视口下按屏幕宽度等比缩小，不出现横向滚动条；
- Tetris 当前方块 overlay 与网格在任意缩放尺寸下**保持逐格对齐**；
- 2048 棋盘与块上数字在窄屏下自适应缩放，多位数（1024/2048）不溢出；
- 桌面端显示效果**与现状完全一致**（缩放仅在窄屏生效）。

**前置确认**：`_Layout.cshtml` 已含 `<meta name="viewport" content="width=device-width, initial-scale=1.0" />`，无需改动。

## 2. 现状问题分析

### 2.1 Tetris（Tetris.razor，样式在页面内）

| 位置 | 现状 | 问题 |
|---|---|---|
| `.grid-cell` / `.piece-cell` / `.piece-empty` | 固定 `30px` | 网格宽恒为 300px |
| **`current-piece-overlay` 内联样式** | `style="top: @(y * 30)px; left: @(x * 30)px;"` | **像素常量 30 同时硬编码在 C# 代码里**——若只改 CSS 不改此处，CSS 缩放后 overlay 与网格错位（这是本任务最关键的坑） |
| `.preview-cell` | 固定 `18px` | 预览块不随网格缩放 |
| `.top-area` | 横排：game-area(flex:3) + side-panel(min-width 110px) | ≤480px 时 300px 网格 + 110px 面板 ≈ 420px > 375px 视口 → **横向溢出**（375px 手机实溢出；320px 更严重） |

溢出推演：视口 375px，cell=30px 固定 → 网格 300px + 面板 ≥110px + 间隙 ≈ 420px > 375px。**根因是"网格 + 侧栏横排"在窄屏放不下**，仅缩小 cell 不够，还需窄屏改纵向堆叠。

### 2.2 2048（样式在 site.css）

| 位置 | 现状 | 问题 |
|---|---|---|
| `.tile` | 固定 `50px`、`font-size: 20px` | 320px 视口下勉强不溢出（50×4+间距 ≈ 257px），但**无自适应机制**；"1024/2048"等 4 位数宽约 48px，在 50px 块内濒临溢出，字号不随块缩放 |
| `.row` | `gap: 5px` | 与固定 tile 尺寸耦合计算 |

### 2.3 方案选型

| 方案 | 思路 | 结论 |
|---|---|---|
| **A. CSS 变量 + min()（选定）** | 在容器上定义 `--cell-size: min(30px, calc((100vw - 32px)/10))`，所有尺寸引用变量；overlay 内联样式改用 `calc(var(--cell-size) * N)` | 改动最小、单一事实来源、无 JS；现代浏览器（含 iOS Safari 15+）均支持内联 style 使用 CSS 变量 |
| B. JS interop 测量容器宽度，C# 算像素 | 每次窗口 resize 需回调渲染 | 复杂、有往返延迟，杀鸡用牛刀 |
| C. 整体重构为 CSS Grid 布局 | `repeat(10, 1fr)` 自适应 | 更彻底但需重构 DOM 结构，回归风险大，本次不做（见 §8 可选项） |

## 3. 方案设计

### 3.1 核心机制：单一尺寸来源

```
--cell-size（Tetris 格子）
   ├─ .grid-cell / .piece-cell / .piece-empty 的 width/height
   ├─ overlay 内联定位：top/left = calc(var(--cell-size) * 格子坐标)
   └─ --preview-size（预览块，按比例派生）
```

变量定义在**容器级**（`.tetris-container` / `.game-container`），页面所有尺寸从它派生；视口变化时浏览器自动重算，**无需任何 JS、无需 C# 感知尺寸**。

### 3.2 Tetris 改动

**(1) 容器上定义变量**（`.tetris-container` 的 style 内新增）：

```css
.tetris-container {
    /* 新增：格子尺寸单一来源。32px = 两侧留白(页面 padding 24px + 8px 余量) */
    --cell-size: min(30px, calc((100vw - 32px) / 10));
    /* 其余现有属性不变 */
}
```

- 桌面端（视口 > 332px）：`min()` 恒取 30px，**显示与现状一致**；
- 窄屏（≤332px）：格子按 `（视口-32)/10` 缩小，10 格总宽始终占满可用宽度。

**(2) 三类格子改用变量**：

```css
.grid-cell   { width: var(--cell-size); height: var(--cell-size); border: 1px solid; box-sizing: border-box; }
.piece-cell  { width: var(--cell-size); height: var(--cell-size); border: 1px solid #333; box-sizing: border-box; }
.piece-empty { width: var(--cell-size); height: var(--cell-size); }
```

**(3) 预览块按比例派生**：

```css
.side-panel { --preview-size: min(18px, calc(var(--cell-size) * 0.6)); }
.preview-cell { width: var(--preview-size); height: var(--preview-size); border: 1px solid #444; display: inline-block; box-sizing: border-box; }
```

**(4) overlay 内联样式去硬编码（关键改动）**：

```razor
<!-- 改前 -->
<div class="current-piece-overlay" style="top: @(y * 30)px; left: @(x * 30)px;">
<!-- 改后：坐标计算交给 CSS calc，C# 只输出格子坐标 -->
<div class="current-piece-overlay" style="top: calc(var(--cell-size) * @(y)); left: calc(var(--cell-size) * @(x));">
```

> 原理：`--cell-size` 定义在祖先 `.tetris-container` 上，内联 style 中 `var()` 正常继承生效；`calc` 乘以整数坐标即得像素偏移。**C# 代码从此不再持有像素常量**。

**(5) 窄屏纵向堆叠**（解决 §2.1 的横排溢出，≤480px 生效）：

```css
@media (max-width: 480px) {
    .top-area {
        flex-direction: column;
        align-items: center;
    }
    .side-panel {
        width: calc(var(--cell-size) * 10);
        max-width: none;
        min-width: 0;
    }
}
```

堆叠后布局：网格在上（宽度 = 10 × cell，恰为可用宽度），侧栏信息面板移到网格正下方，等宽对齐；底部操作按钮区不变。

### 3.3 2048 改动（site.css）

**(1) `.game-container` 定义块尺寸变量**（120px = 内容区 padding 48 + 容器 padding 40 + gap 15 + 边框余量）：

```css
.game-container {
    /* 新增 */
    --tile-size: min(50px, calc((100vw - 120px) / 4));
    /* 其余现有属性不变 */
}
```

**(2) `.tile` 引用变量并让字号随块缩放**（0.4 系数 = 现状 20px/50px，桌面端字号不变）：

```css
.tile {
    width: var(--tile-size);
    height: var(--tile-size);
    display: flex;
    justify-content: center;
    align-items: center;
    background-color: #eeeeee;
    font-size: calc(var(--tile-size) * 0.4);
    font-weight: bold;
    border: 1px solid #999;
}
```

> 数字缩到 4 位也不溢出：块 40px 时字号 16px，"2048"约 34px < 40px。

`.row`、`.controls`、`.game-over`（百分比定位）均无需改动。

### 3.4 缩放效果速查

| 视口宽度 | Tetris cell | Tetris 网格宽 | 布局 | 2048 tile |
|---|---|---|---|---|
| ≥1024px（桌面） | 30px | 300px | 横排（现状） | 50px |
| 768px（平板） | 30px | 300px | 横排（现状） | 50px |
| 414px（大屏手机） | 30px | 300px | **纵向堆叠** | 50px |
| 375px（主流手机） | 30px | 300px | **纵向堆叠** | 50px |
| 320px（小屏手机） | 28.8px | 288px | **纵向堆叠** | 50px |

> 320px 以下 cell 继续按公式线性收缩，理论上不会出现溢出。

## 6. 风险与权衡

| 风险 | 影响 | 缓解 |
|---|---|---|
| **子像素缝隙**：`--cell-size` 为小数（如 28.8px）时，相邻格边框处可能出现 ≤1px 的发丝缝 | 视觉瑕疵，不影响功能 | 格子已 `box-sizing: border-box`；若实测明显，可把公式改为取整友好值（如媒体查询分段定值 28px/26px）或升级为 CSS Grid 方案（见 §8） |
| 内联 style 使用 `var()` 的兼容性 | 老旧浏览器（iOS Safari <9.3 等）失效导致 overlay 错位 | 项目已要求现代浏览器（Blazor Server 本身不支持 IE）；iOS Safari 9.3+、各主流内核均支持 |
| calc 中变量继承失败（拼写错误/作用域错误） | overlay 飞出棋盘 | 变量定义在 `.tetris-container` 根容器，overlay 为其孙元素，继承链明确；T4 用例专门验证 |
| 窄屏堆叠后页面变长 | 需下滑看分数/下一块 | 可接受（信息面板内容少）；可选后续优化：窄屏把分数并入网格上方单行 |
| 2048 的 120px 预算系数与实际样式有出入 | 极窄屏仍轻微溢出 | T8/T11 验证；必要时微调系数 |

## 8. 后续可选优化（不在本次范围）

| # | 项 | 说明 |
|---|---|---|
| 1 | 棋盘重构为 CSS Grid（`repeat(10, 1fr)`） | 彻底消除子像素缝隙、DOM 更简洁；改动大，可与"overlay 改 transform 定位"一起做 |
