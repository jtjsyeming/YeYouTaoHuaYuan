## 1. 背景与问题

用户 2026-11-01 真机反馈（375×667 手机，两张截图）：

- 打开 `/tetris`，**首屏只有网格**，难度/分数/下一方块被压到网格下方，操作按钮（旋转/方向）在更下面，需要滚动 2~3 屏；
- 游戏进行中看不到分数变化，移动方块时手够不到按钮，"操作和分数应该显示在右边才合理"。

### 1.1 根因（不是 08 方案的笔误，而是它的两个副作用叠加）

《08》v2.0 为解决横向溢出，在 ≤520px（L2）把 `.top-area` 改为纵向堆叠。但：

1. **格子尺寸公式没有随堆叠收小**：`--cell-size: min(30px, calc((100vw - 78px) / 10))` 仍按"独占整行"取宽。375px 手机上 → `(375-78)/10 = 29.7px`，网格宽 297px、**高 594px**——一格快 30px 在手机上过大，20 行把首屏占满；
2. **堆叠把面板和按钮全部排到网格之后**：文档流顺序 = 网格 → 信息面板 → 操作按钮，在 667px 高的屏幕上全部折叠到首屏之外。

结论：手机端正确形态不是"堆叠"，而是**回到与桌面一致的左右结构**——网格居左，信息 + 操作居右，代价是格子随右栏预算收小。

## 2. 目标与非目标

**目标**

- ≤520px：网格居左、信息面板 + 操作按钮居右，**667px 高的屏幕一屏放下，无需滚动**；
- 桌面端（≥521px 各断点）**视觉零变化**（延续 08/09 的硬性验收口径）；
- 单份 DOM、零 JS、零 C# 改动（纯 CSS）；
- 横向不溢出（延续 D-12-6 断言）。

**非目标**

- 不改 641~780px"窄窗真空区"的堆叠行为（那是桌面浏览器拖窄窗口的场景，鼠标滚轮可用，堆叠无碍）；
- 不动游戏逻辑、按钮事件（含 ↓ 软降的 pointer 按住机制）；
- 不处理 320px 以下机型（见 §7 风险）。

## 3. 方案选型

| 方案 | 思路 | 结论 |
|---|---|---|
| **A. `display: contents` + CSS Grid 重排（推荐）** | ≤520px 时把 `.top-area`/`.bottom-area` 两个"包装层"从布局中抹掉（`display: contents`），让 `.game-area`/`.side-panel`/`.control-buttons` 直接成为 `.tetris-container` 的 grid 项，用 `grid-template-areas` 排成"左格右栏" | **采用**。零 DOM 改动、零 JS；`display: contents` 在 iOS Safari 11.1+ / Android Chrome 65+ 均已支持（2018 年），覆盖现实机型 |
| B. 改 DOM：把按钮挪进侧栏 | 调整 razor 结构使所有视口都是"格 + 右栏" | 否。桌面端按钮会从底部条移进右栏，**破坏"桌面零变化"**；若保留两份按钮按断点显隐则 DOM 重复、事件双份维护 |
| C. 操作按钮 `position: fixed` 底栏 | 按钮固定在视口底部拇指区 | 否。用户明确要"显示在右边"；且 fixed 层遮挡内容、需处理安全区（safe-area），复杂度更高。作为后续可选备选记录 |
| D. JS 测量重排 | 同《08》已否决的路线 | 否，理由同前（时序、ResizeObserver 复杂度、SSR 双执行） |

## 4. 详细设计

### 4.1 尺寸预算（核心）

右栏进入宽度预算后，格子公式从"减固定开销 78px"变为"再减右栏 132px"：

```
--side-col: 124px            /* 右栏列宽（信息面板与按钮共用） */
列间距 gap: 8px
--cell-size: min(30px, calc((100vw - 210px) / 10))
                /* 210 = 78（08 既有开销：布局 padding 48 + 容器 padding 20 + 画布边框 4 + 余量 6）
                        + 124（右栏）+ 8（列间距） */
```

各视口实测预算：

| 视口宽 | 格子 | 网格（宽×高） | 右栏 | 合计 | 横向余量 |
|---|---|---|---|---|---|
| 320px | 11.0px | 114×224 | 132 | 246 | −4（见 §7，320 归入边缘机型） |
| 360px | 15.0px | 154×304 | 132 | 286 | +74 |
| 375px | 16.5px | 169×334 | 132 | 301 | +74 |
| 414px | 20.4px | 208×412 | 132 | 340 | +74 |
| 520px | 30px（封顶） | 304×604 | 132 | 436 | +84 |

> 375×667 纵向验证：页头 ≈56 + 容器 padding 20 + 网格 334 ≈ **410px < 667，一屏放下**。右栏高度：信息面板（紧凑化后 ≈210）+ 操作区（≈104）≈ 314px < 网格高，左右底边基本对齐。

### 4.2 媒体查询改造（Tetris.razor `<style>` 内）

**改动 1 —— 拆开 L2 堆叠断点**。原：

```css
@@media (max-width: 520px), (min-width: 641px) and (max-width: 780px) { /* 堆叠 */ }
```

改为两段：

- `(min-width: 641px) and (max-width: 780px)`：保留原堆叠规则原样（桌面窄窗场景不变）；
- `(max-width: 520px)`：删除堆叠，换成下面的 Grid 重排。

**改动 2 —— ≤520px Grid 重排**（方案 A 核心）：

```css
@@media (max-width: 520px) {
    .tetris-container {
        display: grid;
        grid-template-columns: auto var(--side-col);
        grid-template-areas:
            "canvas panel"
            "canvas controls";
        align-content: start;
        justify-content: center;   /* 整体居中，两侧均分余量 */
        column-gap: 8px;
        --side-col: 124px;
        --cell-size: min(30px, calc((100vw - 210px) / 10));
    }

    /* 抹掉包装层，让孙级直接参与网格布局 */
    .top-area, .bottom-area { display: contents; }

    .game-area       { grid-area: canvas; }   /* 保留内部 flex 居中画布 */
    .side-panel      { grid-area: panel;  }
    .control-buttons { grid-area: controls; }
}
```

要点：

- `.top-area`、`.bottom-area` 设 `display: contents` 后自身不产生盒子，`.game-area`/`.side-panel`/`.control-buttons` 升格为 `.tetris-container` 的直接 grid 项——**razor 标记一行不改**；
- `canvas` 区跨两行（`grid-template-areas` 同名区域自动跨行），右栏 panel 在上、controls 在下；
- `.side-panel` 原有的 `min-width: 110px`、堆叠用的 `width: calc(...)` 等规则在本断点内显式覆盖（`width: auto; min-width: 0; box-sizing: border-box;`），避免 641~780 段遗留规则串扰（该段选择器已不含 ≤520，实际不串扰，覆盖是为防御未来断点再调整）。

**改动 3 —— 右栏内部布局（同断点内）**：

```css
/* 信息面板紧凑化 */
.side-panel          { padding: 8px; }
.next-piece-preview  { min-height: 44px; padding: 6px; }
.divider             { margin: 2px 0; }
.control-btn         { height: 38px; font-size: 13px; }   /* 暂停/重新开始 */

/* 操作区：纵向栈——旋转在上，←↓→ 一行在下 */
.control-buttons { flex-direction: column; width: 100%; gap: 8px; }
.direction-pad   { flex-direction: column; gap: 8px; width: 100%; }
.rotate-btn      { width: 100%; height: 44px; font-size: 16px; }
.dir-buttons     { gap: 6px; }
.direction-btn   { flex: 1; width: auto; height: 52px; font-size: 20px; }
```

- 触控目标：高度 44~52px 达标（Apple HIG 44pt）；←↓→ 单个宽约 37px（(124−16 面板 padding−12 gap)/3），**低于 44px 宽度建议**——这是"格子够大"与"按钮够宽"的取舍点，备选是把右栏加宽到 140px（格子 375px 下从 16.5 降到 15.1），实施后按真机手感二选一，文档默认 124px；
- ↓ 按钮的软降靠 `@onpointerdown/up/out/leave`，与 DOM 位置无关，移动后行为不变；
- 暂停/重新开始两枚按钮留在面板内（原位），与分数同屏可见。

**改动 4 —— 删除 L4（≤400px）旧按钮缩档**。原 L4 缩 `.direction-pad`/`.rotate-btn`/`.direction-btn` 的定宽尺寸，与新布局的 `flex: 1` 弹性 sizing 冲突。替换为：

```css
@@media (max-width: 360px) {
    .tetris-container { --side-col: 112px; --cell-size: min(30px, calc((100vw - 198px) / 10)); }
}
```

（360px 级别小屏右栏收窄一档；320px 机型见 §7。）

### 4.3 断点行为总表（改造后）

| 视口 | 布局 | 格子公式 |
|---|---|---|
| ≥901px | 桌面原版：80% 宽 top-area + 底部按钮条 | `min(30px, (100vw−78)/10)`，实际恒 30px |
| 641~900px | L1 放开 100%；780 以下堆叠（不变） | 同上 |
| 521~640px | 横排（不变） | `min(30px, (100vw−78)/10)` |
| **≤520px** | **Grid 重排：左格右栏（本次新增）** | `min(30px, (100vw−210)/10)` |
| ≤360px | 同上，右栏收窄一档 | `min(30px, (100vw−198)/10)` |

## 7. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| `display: contents` 兼容性 | 老旧 WebView（<2018）布局退化为堆叠 | 内容仍完整可玩（堆叠是已验证的可用形态），属优雅降级；不做 polyfill |
| 320px 机型格子仅 11px | 可玩性差 | 预算表如实标注；若确有该档机型需求，后续可做"隐藏下一方块预览"或压缩布局 padding（需动全局样式，另立文档） |
| ←↓→ 按键宽 37px 偏窄 | 误触率可能升高 | §4.2 已给 140px 右栏备选；真机手感定夺 |
| 子像素缝隙（格子 15~16.5px 非整） | 视觉发丝缝 | 08 已有同类处理经验（border + box-sizing），实测确认即可 |
| e2e 断言 3 依赖视口高度 | 小屏笔记本跑 e2e 误报 | 断言用固定视口 `viewport: { width: 375, height: 667 }`，与宿主无关 |

**回退方案**：整体还原 ≤520px 段为原 L2 堆叠规则即可（单一 `<style>` 块内，git 还原一个文件）。

## 8. 后续可选项（不在本次范围）
