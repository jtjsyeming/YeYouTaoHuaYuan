两个此前没人写进文档的事实：

- **`_Layout.cshtml` 里没有静态 `<title>`**（只有 `<component type="typeof(HeadOutlet)" render-mode="ServerPrerendered" />`）。所以"布局层标题"是**唯一的兜底**，拆掉它换来的不是"站点名回退"，而是"没有标题"。
- `App.razor` 的 `<PageTitle>` 写在 `<LayoutView>` **之外**，而 `MainLayout` 自己的 `<PageTitle>` 在 `<LayoutView>` 内部渲染 → **后渲染者胜**，故 jtjsym 覆盖 Not found。当前 `/counter`、`/tetris` 能显示页面名，正是"页面内容渲染在布局 `@Body` 内、晚于布局标题"这同一条规则的正面表现。

### 3.2 方案 A（推荐）：把 NotFound 的 `PageTitle` 移进 `<LayoutView>` 内

```razor
<NotFound>
    <LayoutView Layout="@typeof(MainLayout)">
        <PageTitle>页面不存在</PageTitle>
        <p role="alert">Sorry, there's nothing at this address.</p>
    </LayoutView>
</NotFound>
```

只移动 1 行，不增删任何组件：标题组件由"布局之外"变为"布局 `@Body` 之内"，渲染顺序反转为后渲染 → 生效。**布局层兜底、新增页面无需关心标题、SPA 导航行为全部保持现状。**

### 3.3 方案 B（v1.0 原案）：删除布局层标题 + 三个页面补标题

需要 5 个文件联动（删 1 处、改 1 处、补 3 页）。它能达成的效果与"方案 A + 三个页面补标题"**完全相同**，但代价是多拆掉一层兜底：

| 改动文件 | 1（`App.razor`）或 4（含三页补标题） | 5 |
| 布局层兜底 | **保留** | 拆除 |
| 漏写标题的后果 | 显示站点名 | **无 `<title>`**（`_Layout` 无静态 title） |
| SPA 导航标题 | 行为不变（已实测正常） | 需重新验证"旧标题 dispose 后是否残留空标题" |
| `NAV-07` | 需改写（见 §10） | 需改写 |

## 4. D-12：`/loveTime` 375px 横向溢出（根因重定位）

### 4.1 实测：溢出的不是计时文本

375×812 视口（`isMobile:true, hasTouch:true`）实测：

| 元素 | 实测几何 | 结论 |
|---|---|---|
| `document.documentElement` | `scrollWidth 430` / `clientWidth 375` | 溢出 55px（复现台账 D-12） |
| `article.content` | width 375，left 0（`px-4` 内含）→ 内容宽 327 | — |
| 三个 `div.timer` | **width 287，left 44，右边缘 331** | **不溢出**；且文本**已经折成 2 行**（行高 24，盒高 52，`clientHeight` 50 = `scrollHeight` 50，无裁切） |
| `.date-bar` | width 327（正常），**内容实际占 440** | 溢出源 |
| `fluent-select` ×3 | 宽 120 / 100 / 100，位置 **left = −10.5 / 169.5 / 329.5** | 间隔各 **60px**；第三个右边缘 **429.5 ≈ scrollWidth 430** |
| 三个计算按钮（`fluent-button.timer`） | width 180，right 277.5 | 不溢出 |
| 三个恢复默认按钮 | width 106，right 297.5 | 不溢出 |

**两个由此暴露的新事实**：

1. **年份下拉的 left = −10.5**：`.date-bar` 是 `justify-content:center` 的 flex 容器，内容 440 居中溢出到两侧 → 年份选择器左半截跑到视口外。而**负方向溢出不会产生滚动区域**，用户既看不到它的左边缘，也无法"横向滚过去"。这比台账写的"需要横向滚动才能看全"更严重。
2. **`.timer` 的固定 `height:52px` 会在更窄处裁字**：320px 下三行文本折成 **3 行**，`scrollHeight 61 > clientHeight 50` → 文字溢出圆角框外（v1.0 未发现，见 §4.5）。

各区间的实测溢出量（`scrollWidth − clientWidth`）：

| 视口 | 320 | 375 | 414 | 480 | 481 | 500 | 520 | 640 |
|---|---|---|---|---|---|---|---|---|
| 溢出 | **+82** | **+55** | **+35** | **+3** | **+2** | 0 | 0 | 0 |

→ **溢出阈值 ≈ 488px**。所以 v1.0 的 `@media (max-width: 480px)` 恰好漏掉 **481~487px**，而 480px 本身也只是"差 3px"的边界值。

### 4.2 根因

1. **主因**：`.date-bar` 不换行，且三个 `FluentSelect` 用 `Width="120px"/"100px"/"100px"` 写死内联宽度（外加每处约 60px 的额外间隔），整行需要 **440px**；无侧栏时可用宽 = 视口 − `px-4`(48)。440 + 48 = **488** 即为临界点。
2. **次因（v1.0 未发现）**：`.timer` 固定 `height:52px`，窄屏折行后高度不够，文字溢出框外。

**v1.0 归因的"`padding: 0 30px` + `margin: 20px` 撑宽"不成立**：`inline-flex` 在 375px 下已收缩到 287px 并折行，padding/margin 并未造成横向溢出。

### 4.3 修复

**(1) `Pages/MyPage/LoveTime.razor`** —— 三个展示行追加 `timer-display`（`.timer` 仍被三个按钮复用，故必须用追加类隔离）：

```razor
<div class="timer timer-display">我们相识已经过去了：@elapsedTimes["meet"].ElapsedTime</div>
<div class="timer timer-display">我们相爱已经过去了：@elapsedTimes["love"].ElapsedTime</div>
<div class="timer timer-display">我们步入婚姻已经过去了：@elapsedTimes["married"].ElapsedTime</div>
```

**(2) `wwwroot/css/site.css`** —— 追加到文件末尾：

```css
/* D-12：展示行允许折行；日/月/年下拉在窄屏折行（主修复）。
   tabular-nums 让秒级刷新时数字等宽，行宽不抖动 */
.timer-display {
    max-width: 100%;
    box-sizing: border-box;
    font-variant-numeric: tabular-nums;
}

@media (max-width: 520px) {
    .timer-display {
        height: auto;          /* 解除固定 52px，折行后自动长高 */
        min-height: 52px;
        padding: 6px 16px;     /* 原为 0 30px，窄屏收窄左右内边距 */
        margin: 8px auto;      /* 原为 20px */
    }

    .date-bar {
        flex-wrap: wrap;       /* ★ 主修复：三个下拉换行，row 宽 440 → 单行 ≤ 236 */
        row-gap: .5rem;
    }
}
```

设计说明：

- **不需要 `display: block`**（v1.0 用了）：实测保留 `inline-flex` 只加 `height:auto` 即可，药丸外观与三行区分度不变，改动更小；
- **断点 520 而非 480**：480/481 实测仍溢出（+3/+2），520 是实测干净的第一档（500 亦干净但 481~487 不覆盖）；同时与《08》Tetris 的 520 断点统一，项目内只剩 641（布局断崖）/ 520（移动端）/ 400（按钮缩档）三个断点；
- 520 会连带到 500~520（桌面拖拽窗口）本可单行的区间，换行属观感变化、非缺陷；主流机型宽度（360/375/390/412/430）全部 < 488，均在必需区间内；
- `.timer` 与 `.date-bar` 都定义在 `site.css`（沿用其所在位置），`timer-display` 的页内 `<style>` 方案不可取——`LoveTime.razor` 的 `<style>` 是**全局**样式（非 `.razor.css` 隔离），放在页面内只会让覆盖关系更难追踪。

已在 §4.3 的 `height: auto; min-height: 52px` 里覆盖。该问题独立存在于 320px 及更窄（实测 3 行文本溢出 52px 盒 11px），不修则"给了横向不滚，纵向文字压到边框上"。

### 5.2 迁移范式的纠正（v1.0 最危险的一条）

临时脚本是**顺序场景脚本**：一个 `browser` → 一个 `context` → 一个 `page`，用 `rec(id, pri, status, expected, actual)` 逐条记录，中途不重置页面状态。例如 LT-11（1 月 31 日切 2 月收敛）**依赖** LT-10 选择的状态，TRIS 系列更是连续操作同一局。

因此**不能**"一条用例一个 `test()`"——那会让每条用例重新开局，状态依赖断裂，且默认并行 worker 会并发打同一台 Blazor Server 实例。正确范式：

> **一个"场景"（原脚本的一个连续流程）= 一个 `test()`；场景内的每条用例用 `expect.soft()` 逐条断言。**

```js
// tools/e2e/tests/lt.spec.mjs
import { test, expect } from '@playwright/test';

test.describe('LT 爱情计时器', () => {
  test('LT-08~LT-11 年月日联动（含 1/31 → 2 月收敛）', async ({ page }) => {
    await page.goto('/loveTime');
    await waitBlazor(page);

    // LT-08 2024-02 有 29 项
    await pick(page, 0, '2024'); await pick(page, 1, '2');
    await expect.soft(await dayCount(page)).toBe(29);      // ← soft：失败不中断本场景

    // LT-11 1/31 → 2 月 → 自动收敛 28
    await pick(page, 0, '2025'); await pick(page, 1, '1'); await pick(page, 2, '31');
    await pick(page, 1, '2');
    await expect.soft(await dayValue(page)).toBe('28');
  });
});
```

配套约定：

- **用例编号写进 `test()` 标题首段**（`test('LT-08 ...')`）：`--grep LT-08`、`--grep LT` 才能过滤，也才能把报告与《07》编号一一对应（这是《07》执行记录要求"可回溯到用例编号"的前提）；
- 迁移时**只改外壳**（fixtures 取代 `chromium.launch()`、`expect.soft` 取代 `rec()` 的 `cond ? 'pass' : 'fail'`），**选择器、等待策略、校验算法（含 G2048 的 40 步不变式、TRIS 的坐标归一化）一行不动**；
- `page.waitForFunction(() => !!window.Blazor)` + 固定 `waitForTimeout` 这类等待保留原样（Blazor Server 无稳定的"就绪"信号，改成 `networkidle` 反而更脆）。

### 5.5 `playwright.config.mjs`（修正版）

```js
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
    testDir: './tests',
    timeout: 60_000,
    expect: { timeout: 7_000 },          // Blazor Server 渲染有往返延迟，默认 5s 偏紧
    fullyParallel: false,               // 场景脚本内部有状态依赖
    workers: 1,                         // ★ 单实例 Blazor Server：并行会互相干扰，且与 11-01 基线不可比
    retries: 0,                         // 计时类断言（秒级/难度）不允许重试掩盖抖动
    reporter: [['list'], ['html', { open: 'never' }]],
    use: {
        baseURL: process.env.BASE_URL ?? 'http://localhost:14074',
        actionTimeout: 10_000,
        trace: 'retain-on-failure',
    },
    projects: [
        { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
        // Firefox 只跑 NF 兼容组（v1.0 的 testIgnore:/smoke/ 会让所有非冒烟文件都在 Firefox 跑）
        { name: 'firefox', testMatch: /code_nf\.spec\.mjs/, use: { ...devices['Desktop Firefox'] } },
    ],
    // ★ 缺省时 npm run test:* 会因"站点没起"直接全红
    webServer: {
        command: 'dotnet run --project ../../jtjsym/jtjsym --no-launch-profile --urls http://localhost:14074',
        url: 'http://localhost:14074',
        reuseExistingServer: true,      // VS 调试实例已占用 14074 时直接复用
        timeout: 120_000,
        stdout: 'ignore',
        stderr: 'pipe',
    },
});
```

配置要点逐条对应 v1.0 的缺陷：

| v1.0 | 问题 | v2.0 |
|---|---|---|
| 无 `workers` | 默认 `CPU/2` 并行 → 多 worker 同时打一个 Blazor Server 实例，且场景内状态互踩 | `workers: 1` + `fullyParallel: false` |
| 无 `webServer` | 忘记起站点时 7 个 spec 全红，且 README 里写的 `dotnet run` 在本机必失败（HTTPS 证书） | `webServer` + `--no-launch-profile --urls`，`reuseExistingServer` 复用 VS 实例 |
| `retries` 未设（默认 0） | 默认值恰好合适，但未写明"不要加重试" | 显式 `retries: 0` 并注明原因 |
| firefox `testIgnore:/smoke/` | 注释与行为矛盾 | `testMatch: /code_nf\.spec\.mjs/` |
| `--grep NAV` | 若标题不含 NAV 则 0 用例静默通过 | §5.2 约定"编号进标题"，并在 README 写明 `--grep` 依赖标题约定 |

| 迁移脚本引入未验证行为 | 冒烟"假绿" | §7 要求与 11-01 记录逐条比对；迁移只改外壳不动选择器/算法 |
| `workers:1` 使全量耗时偏长（含 3 分钟×2 难度项） | 单次 `test:all` 约 20~25 分钟 | 分钟级用例一律 `test.slow()` + 单独 `--grep` 跑；冒烟集不含它们 |
| `webServer` 复用 VS 调试实例时构建已过期 | 测的是旧二进制 | §2 前置：改 `.razor` 后必须重启；D-12-6 的 `fixme` 就是这个现象的产物 |
| Node 进入 .NET 仓库的管理成本 | 有人误把 `node_modules` 提交 / 误把 e2e 塞进发布链路 | `.gitignore` + `private:true` + README 说明"仅开发期" |
