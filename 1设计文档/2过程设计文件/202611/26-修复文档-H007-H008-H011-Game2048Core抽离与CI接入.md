## 2. 方案（四阶段）

### 阶段①：抽离 Game2048Core（H-008 根治）

- 新建 `jtjsym/jtjsym/Core/Game2048Core.cs`（静态纯函数类）：
  - `MoveLeft/Right/Up/Down(int[] board)` → `(int[] newBoard, int gained, bool moved)`（内部复用现有压缩→成对消费逻辑）；
  - `bool IsGameOver(int[] board)`；
  - `int SpawnValue(Random rng)`（90/10，D-01 常量随之迁移）；
- `Game_2048.razor` 全部委托 Core 调用，组件只留状态与渲染；**棋盘数据结构从 `int[,]` 顺势改为 `int[]`（16 格扁平）**——D-17 存档本就以扁平数组存储，改后消灭"棋盘↔存档"两套形状的转换层（这是顺势收益，非额外重构）；
- 新建 xUnit 测试项目 `jtjsym/jtjsym.Tests/`（首个测试项目），覆盖：合并规则全表（文档《05》的 9 组用例转自动化）、`[2,2,2,2]→[4,4,0,0]`、满盘死局/可动判定、90/10 分布抽样检验（10 万样本卡方粗判）。

### 阶段②：e2e 满盘用例解锁（H-008 + H-011 的 6 条 fixme）

**关键设计决策：不需要任何 debug 注入端点。** d18/d19 spec 已验证"合法存档注入"路径可用，而 C-15 内容闸允许 2 幂值——构造**合法的满盘死局存档**（如棋盘 2/4 相间填满 16 格、score 任意合法值）经 `sessionStorage` 注入即可稳定构造满盘结束态：

- G2048-04/05（满盘死局判定）、G2048-19/20（结束遮罩/重玩）、D02-4（结束时键盘失效）逐条去 `fixme`，前置一律改为"注入满盘合法存档"；
- 合并不变式断言仍以 e2e 真实走子 + Core 单测双覆盖。

### 阶段③：CI 接入（H-007）

新建 `.github/workflows/tests.yml`：

```yaml
on: { push: {branches: [main]}, pull_request: {}, schedule: [{cron: '0 22 * * *'}] }  # cron 为 UTC，= 北京 6:00
jobs:
  e2e:
    runs-on: ubuntu-latest        # Blazor Server 跨平台可跑，ubuntu 速度快、分钟数省
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4 (8.0.x)
      - uses: actions/setup-node@v4 (22, cache: npm, cache-dependency-path: tools/e2e/package-lock.json)
      - run: dotnet build jtjsym/jtjsym -c Release
      - run: npm ci && npx playwright install --with-deps chromium firefox
        working-directory: tools/e2e
      - run: npx playwright test
        working-directory: tools/e2e
        env: { BASE_URL: '' }   # 由 playwright webServer 自启站点（配置已具备 reuseExistingServer）
      - uses: actions/upload-artifact@v4 (always: true, test-results/)
```

- **分层策略**：PR/push 只跑 **chromium 全量 + 冒烟**（~10 分钟）；`schedule` 夜间任务跑 **双浏览器全量**（含 Firefox，即 P-017 的常态观测窗口）；
- ubuntu 注意点：时区用例（d03 的"天数期望"已带 ±1 天容差与截断口径，时区安全）；`dotnet run` 首次启动时长在 webServer timeout 内可容纳；
- 失败即红：main 分支 push 后必须绿，回归不再靠自觉。

### 阶段④：skip 治理收口（H-011）

- FISH-07（计数上百）：木鱼每次点击是一次 SignalR 往返（实测 ~50ms），e2e 循环点击 105 次 ≈ 6 秒，**可自动化**，去 skip；
- NF-05/07/08（生产环境）：夜间任务里加一步 `dotnet publish + production 运行` 跑这三条（可选增强）；不实施则**在 spec 注释里写明人工执行指引**，不再是无主 skip；
- TRIS-23（服务端日志人工项）：维持人工，在《07》手工保留项清单中确认登记（已有）；
- 目标：skip 从 9 条降到 **≤3 条**（NF-03 条件跳过 + NF 生产类或有条件自动化 + TRIS-23 人工）。
