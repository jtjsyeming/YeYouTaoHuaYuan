> 版本：v1.0　|　日期：2026-11-01　|　基线代码：当前仓库 main（`ae2818e` 之后）
> 适用方式：既可按功能模块**单点测试**，也可按第 9 章**全量测试**。目前项目无自动化测试，本文档全部为手工测试用例。

## 1. 使用说明

### 1.1 用例编号规则

`模块代号-序号`，模块代号：

| 代号 | 模块 | 路由 |
|---|---|---|
| NAV | 站点框架（导航/布局/首页） | 全站 / `/` |
| FISH | 电子木鱼 | `/counter` |
| LT | 爱情计时器 | `/loveTime` |
| G2048 | 2048 | `/game_2048` |
| TRIS | 俄罗斯方块 | `/tetris` |
| CODE | 编程挑战 | `/coding_place` |
| NF | 非功能（兼容/异常/恢复） | 全站 |

### 1.2 优先级定义

| 级别 | 含义 | 全量测试中的角色 |
|---|---|---|
| P0 | 核心功能，坏了即不可用 | **冒烟集**（每次发布必测，见 §9.3） |
| P1 | 重要功能或边界，坏了明显影响体验 | 全量测试必测 |
| P2 | 一般功能、文案、样式细节 | 抽测 |

### 1.3 已知缺陷标注

部分用例的预期行为按**标准需求**编写，但当前代码尚未实现，执行时会失败。此类用例在"预期结果"中标注 **`[已知缺陷-05]`**（2048 合并逻辑，见《05-开发文档-2048合并逻辑修复.md》）或 **`[已知缺陷-06]`**（爱情计时器，见《06-开发文档-爱情计时器自动刷新与日期联动.md》）。对应修复合入后，这些用例转为常规用例。

### 1.4 结果记录

每条用例执行后记录：**通过 / 失败 / 阻塞 / 未测**。失败需附：实际结果、截图、操作步骤复现说明。全量测试结果汇总表见 §9.4。

## 2. 测试环境与前置条件

| 项 | 要求 |
|---|---|
| 运行方式 | `cd jtjsym/jtjsym && dotnet run`（.NET 8 SDK） |

## 11. 附录：与自动化测试的衔接建议

当前全部为手工用例。后续如引入自动化，优先级建议：

1. **单元测试（xUnit）**：G2048 合并规则（G2048-07~18 可 1:1 转化为断言，需先按 05 文档抽离 `Game2048Core`）与 LT 时间换算（LT-16）——纯逻辑、零 UI 依赖，收益最高；
