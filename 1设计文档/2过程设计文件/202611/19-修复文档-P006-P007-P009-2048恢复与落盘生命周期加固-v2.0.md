### 2.1 为什么必须是两个布尔

```
时间轴 ──────────────────────────────────────────────────────────▶
       OnInitialized  交互首帧   onAfterRender    getItem 返回   恢复结束
       RestartGame    (新局)     (开始恢复)                       (残局)
写闸门  ────────────────┐  false   ├──────────────────────────────── true
isSessionReady          └──────────┘  ← 必须在"开始"就开：否则窗口内 RestartGame 写不进
UI 门闸  ────────────────────────────┐                        ├────────── true
isRestoring                true      └────────────────────────┘ ← 必须在"结束"才开
```

两个边界的**位置不同**，所以不能共用一个字段。命名上都带 `is`，务必用 XML 注释把职责钉死，否则下一个人一定会合并它们。

```csharp
/// <summary>写闸门（D-17）：恢复启动前一律不写，避免 OnInitialized 那次 RestartGame 冲掉存档。
/// 注意：它在恢复「开始」就放行，**不是** UI 门闸。</summary>
private bool isSessionReady;

/// <summary>UI 门闸（P-006/P-009）：初值 true，恢复结束（无论成败）才置 false。
/// 预渲染实例不会走到 OnAfterRenderAsync，故其 HTML 恒带 session-loading —— 这是 P-009 的缓解点。
/// 与 isSessionReady 边界不同，不可合并。</summary>
private bool isRestoring = true;
```

### 2.2 恢复窗口内的用户操作：代码级守卫（不能靠 CSS/属性）

**为什么 `Disabled` 不够**：`FluentButton` 的 `Disabled` 只改宿主样式（d15-12 断言的就是 `[disabled]` 与 `opacity 0.5`），不拦宿主上的 click 监听；`pointer-events` 又只作用在 `.game-container` 上——那里**没有任何可点元素**。而 FT-08 的验收手法 `b.click()`（`element.click()`）对两者都免疫。C-08 已经为同样的原因在四个 `MoveXxx` 里补过 `if (isGameOver) return;`。

**为什么不能用 `restartRequested` 布尔**：`OnInitialized()` 也调 `RestartGame()`（L154），布尔一置位就再也分不出"初始化"与"用户点击"。

→ **正确做法：把用户入口与初始化入口分开**，守卫只放在用户入口上：

```csharp
protected override void OnInitialized() => RestartGame();      // 初始化：不进守卫，不计用户意图

/// <summary>重玩的唯一用户入口（主按钮 + 遮罩按钮共用）。恢复窗口内的点击一律忽略：
/// 按钮此时是 disabled 视觉态，且程序化点击也必须被挡住（FT-08 用 element.click()）。</summary>
private void OnReplayClicked()
{
    if (isRestoring) return;
    RestartGame();
}
```

`MoveXxx` 同理（键盘路径**没有任何**禁用机制，守卫是唯一防线，见 §1-④）：

```csharp
private async Task MoveLeft()
{
    if (isGameOver || isRestoring) return;   // ← 新增 isRestoring
    var before = (int[,])board.Clone();
    for (int row = 0; row < GridSize; row++)
    {
        SetRow(row, Merge(GetRow(row)));
    }
    await AfterMove(before);
}
```

四个方向各一行，`MoveRight/MoveUp/MoveDown` 同构。

### 2.3 P-007：`await` 的真实收益是"渲染即已落盘"，不是"窗口减半"

- **事实一**：`_ = SaveSessionAsync()` 与 `await SaveSessionAsync()` 的 **interop 派发时刻完全相同**——`SaveSessionAsync` 在第一个 `await` 之前只做扁平化与 `JsonSerializer.Serialize`，随后立刻 `await JS.InvokeVoidAsync(...)`。所以"零等待刷新"的丢失率不会因为这次改动下降。
- **事实二**：`StateHasChanged()` 在 `await` 之后 ⇒ **服务端渲染 diff 的发出，晚于 `setItem` 完成**。于是得到一条可断言的不变式：**用户在页面上看到这一步，这一步就已经在存档里**。这才是本次改动的真收益，也是把 FT-07 的 `afterDom` 分支从"8/8 的经验观测"升级为"必然成立"的依据。
- **必须如实声明物理极限**：用户手速快于一个 SignalR 往返时（点完立刻 reload / 关标签），事件可能还没到服务端、或到服务端但 interop 没执行完，该步**任何客户端方案都保不住**——这是 Blazor Server 的架构边界。
- **因此判据口径要改**（§4.2）：门禁判定改为"等 DOM 更新后再 reload → 100% 保持"；"零等待 reload"降为观测项，只记录丢步率、不判红。

### 2.4 `AfterMove` 与 `MoveXxx` 的 async 化（含两个必须注意的点）

```csharp
private async Task AfterMove(int[,] boardBefore)
{
    if (!IsBoardChanged(boardBefore, board))
    {
        StateHasChanged();
        return;
    }

    UpdateBestScore();
    AddRandomTile();

    if (IsGameOver()) isGameOver = true;

    await SaveSessionAsync();      // ← 原 `_ = SaveSessionAsync();`
    if (disposed) return;          // 电路已释放：StateHasChanged 会抛 ObjectDisposedException
    StateHasChanged();
}
```

**注意点 1 — `[JSInvokable] OnKeyDown` 会静默退化成 fire-and-forget。**
现在的写法是 `await InvokeAsync(() => { switch (key) { case "ArrowLeft": MoveLeft(); ... } });`。四个方法改成 `async Task` 后，这个 lambda **没有返回值**，重载解析会绑到 `InvokeAsync(Action)` 而不是 `InvokeAsync(Func<Task>)` → `MoveLeft()` 的 Task 被丢弃，`await` 形同虚设（不报错、不警告）。必须显式 await：

```csharp
[JSInvokable]
public Task OnKeyDown(string key) => InvokeAsync(async () =>
{
    switch (key)
    {
        case "ArrowLeft":  await MoveLeft();  break;
        case "ArrowRight": await MoveRight(); break;
        case "ArrowUp":    await MoveUp();    break;
        case "ArrowDown":  await MoveDown();  break;
    }
});
```

（`async () => { … }` 的 lambda 返回 `Task` → 绑定 `Func<Task>` 重载。）

**注意点 2 — 新增 `disposed` 标志。**
`await` 之后 `StateHasChanged()` 时组件可能已被销毁（切页/断线），`ComponentBase` 会抛。项目内 Tetris 的既有模式就是 `isDisposed` 双检（`MEMORY` 已记为约定）：

```csharp
private bool disposed;

public async ValueTask DisposeAsync()
{
    disposed = true;
    // …原有 keyModule/keyRef 清理不动…
}
```

### 2.5 P-009：只能降级为"加载态"，且要有可见文案

预渲染实例拿不到 `sessionStorage`，所以"首帧直接是残局"做不到。能做到的是让首帧**看起来像加载中**而不是像新局：

- `.game-container` 带 `session-loading`：半透明 + `pointer-events:none`（纯视觉，不承担拦截职责）；
- 四个方向键与"重玩"的 `Disabled` 加 `|| isRestoring`（视觉 + 语义，真正的拦截靠 §2.2 的守卫）；
- **加一行可见文案**"正在恢复对局…"——否则用户看到的仍然是"分数：0、两块 2/4"，v1.0 说的"从误导降级为加载指示"就只是自说自话。

```razor
<div class="@(isRestoring ? "game-container session-loading" : "game-container")">
    @for (int row = 0; row < GridSize; row++)
    {
        <div class="row">
            @for (int col = 0; col < GridSize; col++)
            {
                <div class="tile @TileClass(board[row, col])">@(board[row, col] == 0 ? "" : board[row, col].ToString())</div>
            }
        </div>
    }
</div>

@if (isRestoring)
{
    <p class="session-tip">正在恢复对局…</p>
}

<div class="controls">
    <FluentButton Class="dir-btn dir-up" @onclick="MoveUp" Disabled="@(isGameOver || isRestoring)">⬆️</FluentButton>
    <div class="dir-row">
        <FluentButton Class="dir-btn" @onclick="MoveLeft"  Disabled="@(isGameOver || isRestoring)">⬅️</FluentButton>
        <FluentButton Class="dir-btn" @onclick="MoveDown"  Disabled="@(isGameOver || isRestoring)">⬇️</FluentButton>
        <FluentButton Class="dir-btn" @onclick="MoveRight" Disabled="@(isGameOver || isRestoring)">➡️</FluentButton>
    </div>
</div>
```

```razor
<p><FluentButton Class="replay-btn" @onclick="OnReplayClicked" Disabled="@(isGameOver || isRestoring)">重玩</FluentButton></p>

@if (isGameOver)
{
    <div class="game-over">
        <h2>游戏结束</h2>
        <FluentButton Class="overlay-replay-btn" Appearance="Appearance.Accent" @onclick="OnReplayClicked" Disabled="@isRestoring">重玩</FluentButton>
    </div>
}
```

`.session-tip` 用 `@if` 块（恢复后整块消失），不要常驻占位——常驻会给 2048 页面永久加一行高度。

```css
.game-container.session-loading { opacity: .55; pointer-events: none; transition: opacity .15s ease; }
.session-tip { text-align: center; color: #886D68; font-size: 14px; margin: 4px 0 0; }
```

> 注：`.session-tip` 出现/消失会带来约 20px 的纵向抖动，仅存在于恢复窗口（毫秒级），所有既有用例都在 settle 之后采样，不受影响；若介意可改为 `min-height` 预留。

### 2.6 恢复分支的最终形态（在《18》落地之后）

```csharp
        // ② 恢复对局（D-17 + 《18》内容校验 + 《19》UI 门闸）
        if (!isSessionReady)
        {
            isSessionReady = true;             // 写闸门：开始即放行（v1.0 想把它挪到末尾，会把窗口内的写入挡掉）
            try
            {
                // …《18》落地后的结构闸 + 内容闸 + 恢复体原样保留，此处不重复…
                //   唯一差异：恢复体末尾**没有** UpdateBestScore()（《18》P-003 已删）
            }
            catch (JSException) { }
            catch (JsonException) { }
            catch (JSDisconnectedException) { }
            catch (ObjectDisposedException) { }
            finally
            {
                isRestoring = false;           // UI 门闸：无论成败都解除，避免永久卡在加载态
                StateHasChanged();
            }
        }
```

窗口内的用户操作由 §2.2 的守卫挡在入口，**不再需要任何"恢复让位于重玩"的互斥标志**——语义更简单：恢复窗口内的点击是"无效的"（按钮此时也确实是禁用态），不是"优先的"。

### 4.1 新增 `d19_restore_gate.spec.mjs`（G2048-43~45）

窗口只有毫秒级，**不要试图在 e2e 里"卡点"点击**（那类断言要么恒假绿、要么随机红）。可判定的只有三件事：预渲染 HTML 的形态、恢复后的可用性、"看到即已存"。

```js
// 19：恢复与落盘生命周期（P-006/P-007/P-009）
// 判据原则：窗口竞态不可在 e2e 里稳定复现 —— 只断言"确定性可观测"的三件事：
//   ① 服务端预渲染 HTML 的形态（含 session-loading / disabled）
//   ② 恢复完成后门闸必须解除（防"关不回去"）
//   ③ 看到该步之后再刷新必须保持（await 带来的不变式）
import { expect, test } from '@playwright/test';
import { check, checkEq, clickDir, countTiles, open, readBoard, readScore, readSession, sleep } from './helpers.mjs';

const sig = b => b.map(r => r.join(',')).join('|');

test.describe('19 2048 恢复与落盘生命周期', () => {
  test('G2048-43 预渲染 HTML：容器带 session-loading、五个按钮带 disabled', async ({ page }) => {
    // 直接取服务端返回的原始 HTML —— 这是预渲染实例的确定性快照，不受时序影响
    const html = await (await page.request.get('/game_2048')).text();
    check('G2048-43-loading类', /class="[^"]*\bsession-loading\b/.test(html),
      `预渲染容器类：${(html.match(/class="game-container[^"]*"/) || ['未找到'])[0]}`);

    const btns = [...html.matchAll(/<fluent-button[^>]*>/g)].map(m => m[0]);
    const replay = btns.filter(t => t.includes('replay-btn'));
    const dirs = btns.filter(t => t.includes('dir-btn'));
    check('G2048-43-重玩禁用', replay.length >= 1 && replay.every(t => /\bdisabled\b/.test(t)),
      `重玩按钮：${JSON.stringify(replay)}`);
    check('G2048-43-方向键禁用', dirs.length === 4 && dirs.every(t => /\bdisabled\b/.test(t)),
      `方向键 ${dirs.length} 个，disabled 数 ${dirs.filter(t => /\bdisabled\b/.test(t)).length}`);
  });

  test('G2048-44 恢复完成后门闸解除：可点、可走、盘面是残局', async ({ page }) => {
    await open(page, '/game_2048', 1600);
    await clickDir(page, 'left');                 // 建立一份真实存档
    const b = await readBoard(page);
    const s = await readScore(page);

    await page.reload({ waitUntil: 'domcontentloaded' });
    await page.waitForFunction(() => !!window.Blazor, null, { timeout: 15000 }).catch(() => {});
    await expect.poll(async () => sig(await readBoard(page)), { timeout: 7000 }).toBe(sig(b));

    // 门闸必须回到"已就绪"：否则用户永远点不动（比 P-006 更严重的倒退）
    const st = await page.evaluate(() => ({
      loading: !!document.querySelector('.game-container.session-loading'),
      tip: !!document.querySelector('.session-tip'),
      dis: [...document.querySelectorAll('.controls fluent-button')].map(x => x.disabled === true || x.hasAttribute('disabled')),
      replayDis: (() => { const r = document.querySelector('.replay-btn'); return r.disabled === true || r.hasAttribute('disabled'); })(),
    }));
    checkEq('G2048-44-门闸', { loading: st.loading, tip: st.tip, replayDis: st.replayDis },
      { loading: false, tip: false, replayDis: false }, '恢复完成后 loading/提示行/禁用必须全部解除');
    check('G2048-44-方向键', st.dis.every(d => d === false), `四方向键禁用态：${JSON.stringify(st.dis)}`);
    await expect.poll(() => readScore(page), { timeout: 7000 }).toBe(s);

    // 恢复后仍能正常走子，且存档与画面逐格一致（证明守卫没有误伤主流程、落盘链路仍是活的）
    await clickDir(page, 'right');
    await expect.poll(async () => {
      const raw = await readSession(page);
      const arch = raw ? JSON.parse(raw).cells.join(',') : 'null';
      return arch === (await readBoard(page)).flat().join(',');
    }, { timeout: 5000 }).toBe(true);
  });

  test('G2048-45 看到即已存：DOM 更新后立刻刷新，5 轮全保持（P-007 门禁判据）', async ({ page }) => {
    await open(page, '/game_2048', 1600);
    await clickDir(page, 'left');                 // 先确保有存档
    const rows = [];
    for (let i = 0; i < 5; i++) {
      if (await page.locator('.game-over').count()) {
        await page.locator('.overlay-replay-btn').click();
        await sleep(500);
      }
      const before = await readBoard(page);
      if (countTiles(before) === 16 && (await page.locator('.game-over').count())) break;
      const beforeSig = sig(before);
      await clickDir(page, ['left', 'down', 'right', 'up'][i % 4]);
      // 关键：等到 DOM 真的出现该步结果再刷新（沿用 FT-07 已跑通的 waitForFunction 写法）。
      // await 落盘后，"DOM 更新"必然晚于 setItem 完成 → 这一步之后刷新必须保持
      await page.waitForFunction(s => {
        const t = [...document.querySelectorAll('.game-container .row')]
          .map(r => [...r.querySelectorAll('.tile')].map(x => x.textContent.trim() || '0').join(',')).join('|');
        return t && t !== s;
      }, beforeSig, { timeout: 4000 }).catch(() => {});
      const mid = await readBoard(page);
      await page.reload({ waitUntil: 'domcontentloaded' });
      await page.waitForFunction(() => !!window.Blazor, null, { timeout: 15000 }).catch(() => {});
      await expect.poll(async () => sig(await readBoard(page)), { timeout: 7000 }).toBe(sig(mid));
      rows.push({ i, kept: sig(await readBoard(page)) === sig(mid) });
    }
    check('G2048-45', rows.length > 0 && rows.every(r => r.kept), `5 轮明细：${JSON.stringify(rows)}`);
  });
});
```

> 三条用例刻意都**不依赖时序卡点**：G2048-43 读服务端原始 HTML（确定性快照）、G2048-44 只验"门闸会解除"、G2048-45 验"DOM 变化之后必定已落盘"。窗口内点击的拦截能力交给 FT-08 的 `element.click()`（它绕得过 `disabled`，正好能验代码守卫）。

## 5. 残余边界与误判风险（如实登记）

| 项 | 说明 | 处置 |
|---|---|---|
| **P-007 不可根除** | 用户在 `setItem` 执行前导航，该步必丢。任何客户端方案都绕不开（状态在服务端、interop 必然异步） | 只承诺"看到即已存"；台账写"**部分缓解**"，不要写"已修" |
| **P-009 不可根除** | 预渲染实例拿不到 `sessionStorage` | 降级为加载态；若有人主张"关掉 prerender"（`render-mode="Server"`），会连带改变**全站**首屏与 SEO，属全局决策，不在本单范围 |
| 恢复窗口内点击"无效" | 语义选择：v1.0 选"恢复让位于重玩"，v2.0 选"点击忽略"（因为按钮本就是禁用态，且"让位"需要窗口内写档，与写闸门语义打架） | 已改为"忽略"；若后续想改"让位"，必须用**序号快照**而不是布尔（`OnInitialized` 会污染布尔） |
| `session-tip` 的 20px 抖动 | 仅存在于毫秒级窗口 | 若被视觉验收挑刺，改 `min-height` 预留 |
| `async` 化后的重复渲染 | `AfterMove` 内 `StateHasChanged` + `finally` 内 `StateHasChanged` 可能连发两帧 | 无害（Blazor 会合并）；不要为此加"脏标记"复杂度 |
