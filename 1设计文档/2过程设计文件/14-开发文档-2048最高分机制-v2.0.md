### 1.2 调用链（I-01 的判据）

```
@onclick="MoveLeft"  ─┐
[T] OnKeyDown → MoveLeft ─┴→ MoveLeft() → Merge()×4（Score 累加）→ AfterMove(before) → AddRandomTile()
```

- **唯一收口在 `AfterMove`**：按钮与键盘两条通道都汇流到此，故最高分判断只需要 1 个落点；
- `RestartGame` 不经过 `AfterMove`，天然不会被"重开"误触发写入；
- `AfterMove` 的早退分支（棋盘无变化）必然伴随"无合并"，`Score` 不可能变 → 早退前不判断最高分是安全的，**不需要额外补一个判断**。

## 2. 存储选型（沿用 v1.0，结论不变）

| 方案 | 结论 |
|---|---|
| **A. localStorage（键 `jtjsym.g2048.best`）** | **采用**。"最高分"语义即"本浏览器记录"；站点无账户体系 |
| B. 服务端单例字典 | 否。Blazor Server circuit 随刷新销毁，**刷新即丢**，不满足需求 |
| C. Cookie | 否。纯展示值不值得每请求上行 |
| D. IndexedDB / 引 Blazored.LocalStorage | 否。一个键值对不值得建库/引包 |

**仍不新建 JS 文件**：`localStorage.getItem/setItem` 走 Blazor 的点分路径 interop（`window.localStorage.getItem`，实现会保留 `this` 绑定），两行即可。已在仓库全量搜索确认：**当前无任何 `localStorage`/`sessionStorage` 使用**，本机制是首例。

## 3. 详细设计

### 3.1 字段（L48 `Score` 之后）

```csharp
private const string BestKey = "jtjsym.g2048.best";
private int BestScore = 0;
private bool isBestLoaded = false;     // 只在第一次交互渲染时读一次
```

### 3.2 读（并入 `OnAfterRenderAsync`，见 §3.6 的分段）

```csharp
if (!isBestLoaded)
{
    isBestLoaded = true;               // 先置位：读失败也不重试（避免每次渲染都打 interop）
    try
    {
        var raw = await JS.InvokeAsync<string?>("localStorage.getItem", BestKey);
        if (int.TryParse(raw, out var v) && v > 0) BestScore = v;
    }
    catch (JSException) { }            // 隐私模式/存储被禁：BestScore 保持 0，游戏零降级
    catch (JSDisconnectedException) { }

    StateHasChanged();                 // 预渲染首帧是 0，这一帧补成真实值
}
```

- `StateHasChanged()` 会再触发一次渲染 → 该次 `OnAfterRenderAsync` 的 `firstRender` 为 `false`，被首行守卫挡掉，**不会递归**；
- 用 `int.TryParse` 而非 `Convert.ToInt32`：损坏值不抛异常（`'abc'`、`''`、`'9e9'`、`' 500 '` 全部安全）。

### 3.3 写

```csharp
/// <summary>破纪录即异步落盘；未破纪录不产生任何 interop 开销（绝大多数走子走这条返回）</summary>
private void UpdateBestScore()
{
    if (Score <= BestScore) return;    // 只增不减：重玩后 Score=0 自然不会覆盖
    BestScore = Score;
    _ = WriteBestAsync();
}

private async Task WriteBestAsync()
{
    try { await JS.InvokeVoidAsync("localStorage.setItem", BestKey, BestScore); }
    catch (JSException) { }               // 存储被禁：本次会话内仍有效
    catch (JSDisconnectedException) { }   // 关页/断线
    catch (ObjectDisposedException) { }   // 电路已释放（补齐 v1.0 遗漏）
}
```

- `_ =` 是有意的 fire-and-forget：写盘不该阻塞渲染帧，且已在内部吞掉全部已知异常；
- 连续两步都破纪录会并发两次 `setItem`，但**值单调递增**，后发的一定不小于先发的，无需串行化。

### 3.4 调用点（**1 处**，I-01 修正）

```csharp
private void AfterMove(int[,] boardBefore)
{
    if (!IsBoardChanged(boardBefore, board))
    {
        StateHasChanged();
        return;
    }

    UpdateBestScore();     // ← 唯一新增行：Score 已在 Merge 内累加完毕
    AddRandomTile();

    if (IsGameOver()) isGameOver = true;
    StateHasChanged();
}
```

| 时机 | 行为 | 依据 |
|---|---|---|
| `AfterMove`（棋盘确有变化） | `UpdateBestScore()` | 得分已定型、且尚未生成新块；按钮与键盘共用 |
| `AfterMove` 早退分支 | 不判断 | 无位移/无合并 ⇒ `Score` 不变 |
| `RestartGame` | **不清** `BestScore` | 标准 2048：最高分跨局保留 |
| 游戏结束 | 无特殊处理 | 破纪录发生在得分瞬间，不是结束帧 |
| 组件销毁 | 无清理 | localStorage 不依赖电路；`isBestLoaded` 随实例消亡 |

> **不要**把 `UpdateBestScore()` 塞进 `Merge()`：一是纯计算里混 IO，二是每次移动 `Merge` 被调 4 次（每行/列一次），会产生 4 次 interop。

### 3.5 展示（**独立 `<p>`**，I-02 修正）

```razor
<p>分数：@Score</p>
<p class="best-score">最高分：@BestScore</p>
```

- 原 `<p>分数：@Score</p>` **一字不改** → `D02-12`（`/^分数：\d+$/`）、`readScore`、`NF-04` 全部零影响；
- `class="best-score"` 供 e2e 精确定位（`p.best-score`），不依赖中文文案顺序；
- 不新增卡片、不加图标，保持与现有两行 `<p>` 同风格；
- 预渲染首帧显示"最高分：0"，`firstRender` 后毫秒级跳到真实值 —— 与键盘模块同一 trade-off，06/10 文档已确立该模式，可接受。

> **被否决的方案**：`<p>分数：0　最高分：500</p>` 单行。省一行高度，但代价是改 `d02_keyboard_ui.spec.mjs:333` 的锚定正则 —— 为一个展示细节去动 P0 门禁断言，不划算。

### 3.6 生命周期分段（I-06 修正）

```csharp
protected override async Task OnAfterRenderAsync(bool firstRender)
{
    // 预渲染实例不会走到这里；交互实例的后续渲染也从这里直接返回
    if (!firstRender) return;

    // ① 读最高分：与键盘模块解耦，键盘将来怎么改都不影响它
    if (!isBestLoaded) { …§3.2… }

    // ② 键盘注册（原逻辑，保持不变）
    if (keyModule is not null) return;

    keyRef = DotNetObjectReference.Create(this);
```

## 5. 测试计划

### 5.1 `helpers.mjs` 新增（紧接 `readScore` 之后）

```js
/** 最高分文案 "最高分：N"；元素不存在（其他页面）返回 null，便于复用 */
export const readBest = async page => {
  const loc = page.locator('p.best-score');
  if ((await loc.count()) === 0) return null;
  const txt = (await loc.first().textContent()) ?? '';
  return parseInt(/最高分[:：]\s*(\d+)/.exec(txt)?.[1] ?? '-1');
};
```

### 5.2 新增 `tools/e2e/tests/d16_best_score.spec.mjs`

> 三条设计要点：① 预置**只在键不存在时**写（I-03）；② 需要"得分"时用方向循环走子而**不**预置大分数（I-04）；③ 落盘断言一律 `expect.poll`，因为 `setItem` 是异步的。

```js
// D-16：2048 最高分持久化（localStorage `jtjsym.g2048.best`）
// 手法：预置/直读都走 localStorage，断言一律"页面文案 + 存储值"双向核对；
//      需要得分时按方向循环走子（2048 前几步必有合并），不依赖固定棋盘。
import { expect, test } from '@playwright/test';
import { check, checkEq, open, readBest, readScore, sleep } from './helpers.mjs';

const KEY = 'jtjsym.g2048.best';
const DIRS = ['⬅️', '⬇️', '➡️', '⬆️'];

/** ⚠ addInitScript 在每次导航（含 reload）都会重跑，故只在键不存在时预置；
 *  无条件写会把上一局刚存下的值冲掉，让"刷新后保持"变成永远为真的假绿。 */
const seedBest = (page, val) =>
  page.addInitScript(
    ([k, v]) => {
      if (localStorage.getItem(k) === null) localStorage.setItem(k, v);
    },
    [KEY, val],
  );

const stored = page => page.evaluate(k => localStorage.getItem(k), KEY);

async function step(page, i) {
  if (await page.locator('.game-over').count()) {   // 已结束：按钮 disabled，先重开
    await page.locator('.overlay-replay-btn').click();
    await sleep(300);
    return;
  }
  await page.locator(`.controls fluent-button:has-text("${DIRS[i % 4]}")`).click();
  await sleep(220);
}

async function playUntil(page, pred, maxMoves = 40) {
  for (let i = 0; i < maxMoves; i++) {
    if (await pred()) return true;
    await step(page, i);
  }
  return pred();
}

test.describe('D16 2048 最高分', () => {
  test('G2048-24 读取：预置 500 → 最高分 500、当前分 0', async ({ page }) => {
    await seedBest(page, '500');
    await open(page, '/game_2048', 1600);
    checkEq('G2048-24', { best: await readBest(page), score: await readScore(page) },
      { best: 500, score: 0 }, '历史最高分应被读出且不影响当前分');
  });

  test('G2048-25 容错：损坏值 "abc" → 最高分 0、游戏可正常开局', async ({ page }) => {
    await seedBest(page, 'abc');
    await open(page, '/game_2048', 1600);
    const tiles = (await page.$$eval('.game-container .tile', ts => ts.map(t => t.textContent.trim())))
      .filter(Boolean).length;
    checkEq('G2048-25', { best: await readBest(page), tiles }, { best: 0, tiles: 2 },
      '损坏值按 0 处理，开局不受影响');
  });

  test('G2048-26 写入：得分超过预置值 → 最高分跟进并落盘', async ({ page }) => {
    await seedBest(page, '2');                       // 首次合并（+4）即超越，无需打满 500
    await open(page, '/game_2048', 1600);

    const score = await readScore(page);

    await playUntil(page, async () => (await readScore(page)) > 0);

    await expect.poll(() => readBest(page), { timeout: 7000 }).toBe(best);
  });

  test('G2048-28 重玩：分数归零、最高分保持', async ({ page }) => {
    await open(page, '/game_2048', 1600);
    await playUntil(page, async () => (await readScore(page)) > 0);
    const best = await readBest(page);
    await page.locator('.replay-btn').first().click();
    await sleep(400);
    checkEq('G2048-28', { score: await readScore(page), best: await readBest(page) },
      { score: 0, best }, '重开不得清最高分');
  });

  test('G2048-29 跨路由：离开再回来最高分保持', async ({ page }) => {
    await open(page, '/game_2048', 1600);
    await playUntil(page, async () => (await readScore(page)) > 0);
    const best = await readBest(page);
    await open(page, '/', 1200);
    await open(page, '/game_2048', 1600);
    await expect.poll(() => readBest(page), { timeout: 7000 }).toBe(best);
```

## 6. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| `localStorage.getItem` 点分调用在个别宿主不可用 | 读取失败 | try/catch 降级为 0；真遇到再落 JS 模块（不预先做） |
| 破纪录步的 `setItem` 与关页竞态 | 最后一步未落盘 | 最多少记一步的分值，下次得分即修正；不值得做 flush |
| 多标签页互相覆盖（A 页内存里 500，B 页已写 1000，A 破纪录写 600） | 最高分回退 | 概率极低、代价仅一个数字；治它要"写前重读比较"，多一次 interop，不做 |
| e2e 断言依赖中文文案"最高分：" | 文案变更即假失败 | 选择器用 `p.best-score`（类名），正则只兜底 |
| `reuseExistingServer` 复用旧 IL | 新 spec 假红/假绿 | 跑门禁前重启实例（09 已固化） |
| 改动溢出到合并逻辑 | 影响计分正确性 | `git diff` 应恰好 4 处代码 + 1 个 spec + 2 个小改；`test:g2048` 逐步比对是硬门禁 |

**回退**：还原 `Game_2048.razor` 一个文件即可（业务改动全在该文件）；localStorage 里的键无需清理（还原后代码不再读它，无害）。
