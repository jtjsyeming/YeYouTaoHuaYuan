## 3. 任务 A/B：键盘操作

### 3.1 选型：window 级 JS 监听（维持 v1.0 结论）

理由与 v1.0 相同，补充两条实测/代码依据：

- Blazor 的 `@onkeydown` 只能挂在元素上，`tabindex` 方案在焦点离开游戏区后失效；而**Tetris 的软降必须有 `keyup`**，元素级方案无法覆盖"鼠标点过按钮后按住键盘"的场景；
- 需要按键级 `preventDefault()`：只拦四个方向键，F5/Tab/Ctrl 组合零干扰（元素级 `@onkeydown:preventDefault` 是整元素全拦）。

### 3.2 共享模块 `wwwroot/js/gamekeyboard.js`（重写）

比 v1.0 多三件事：**注册 id 守卫**（防跨页竞态）、**按页配置连发**（2048 与 Tetris 语义不同）、**吞掉 Promise 拒绝**（防控制台报错）。

```js
// 夜游桃花源 游戏键盘支持（Game_2048 / Tetris 共用）
// 设计要点见《10-开发文档-D02…-v2.0.md》§3.2
const MOVE_KEYS = ['ArrowLeft', 'ArrowRight', 'ArrowUp', 'ArrowDown'];
const REPEAT_MIN_INTERVAL_MS = 60;   // 连发节流：浏览器 autorepeat ~30Hz，一次按键 = 一次 SignalR 往返

let cfg = { repeatKeys: [] };        // 允许连发的键（2048 传空数组 = 全部忽略连发）
let currentId = 0;
let seq = 0;
let keydownHandler = null, keyupHandler = null;
let lastInvokeAt = Object.create(null);

/** 返回注册 id；调用方保存它，Dispose 时传给 unregister */
export function register(ref, options = {}) {
  removeListeners();                 // 幂等：先拆旧监听（含上一页遗留）
  cfg = { repeatKeys: options.repeatKeys ?? [] };
  lastInvokeAt = Object.create(null);

  keydownHandler = (e) => {
    if (!MOVE_KEYS.includes(e.key)) return;
    e.preventDefault();                                   // 只拦方向键，其余按键不受影响
    if (e.repeat) {
      if (!cfg.repeatKeys.includes(e.key)) return;         // 2048 与 ↑：连发无意义，忽略
      const now = performance.now();
      if (now - (lastInvokeAt[e.key] ?? 0) < REPEAT_MIN_INTERVAL_MS) return;
      lastInvokeAt[e.key] = now;
    }
    // catch：断线/组件已销毁时 Promise 会被 reject，不接住会污染控制台（NF-06）
    ref.invokeMethodAsync('OnKeyDown', e.key).catch(() => {});
  };

  keyupHandler = (e) => {
    if (!MOVE_KEYS.includes(e.key)) return;
    ref.invokeMethodAsync('OnKeyUp', e.key).catch(() => {});
  };

  window.addEventListener('keydown', keydownHandler);
  window.addEventListener('keyup', keyupHandler);

  currentId = ++seq;
  return currentId;
}

/**
 * 仅在 id 仍是当前注册时拆除。
 * 跨页导航时"新页 register"与"旧页 unregister"的先后顺序没有保证，
 * 若旧页后执行 unregister 而无条件拆监听，会把新页刚装上的监听删掉。
 */
export function unregister(id) {
  if (id !== currentId) return;
  removeListeners();
  currentId = 0;
}

/** 页面隐藏/失焦时释放所有按键：防止"按住 ↓ 切走窗口"导致软降卡死 */
export function releaseAll(ref) {
  ref.invokeMethodAsync('OnKeyUp', 'ArrowDown').catch(() => {});
}

function removeListeners() {
  if (keydownHandler) window.removeEventListener('keydown', keydownHandler);
  if (keyupHandler) window.removeEventListener('keyup', keyupHandler);
  keydownHandler = keyupHandler = null;
}
```

> `releaseAll` 是 v1.0 漏的场景：键盘只有 `keyup`，而 `keyup` 在窗口失焦 / 切标签页时**收不到**（事件发给新窗口），Tetris 会一直处于软降状态直到下一次按键。C# 侧在 `window.blur` 与 `visibilitychange` 时调用它（用 `register` 时顺带挂两个监听，实现时二选一：JS 内部挂，或 C# 用 `OnAfterRenderAsync` 加一次 `document.addEventListener` —— 推荐 **JS 内部挂**，减少一次互操作）。

### 3.3 Game_2048 接入

**指令区只追加 2 行**（`@inject NavigationManager Navigation` 已存在于 L2，勿重复声明，否则编译失败）：

```razor

```

**标记区**（合并 §4 的空块改动）：

```razor

    @for (int col = 0; col < GridSize; col++)
    {
        <div class="tile @TileClass(board[row, col])">@(board[row, col] == 0 ? "" : board[row, col].ToString())</div>
    }
</div>
```

**`@code` 追加**：

```csharp
private IJSObjectReference? keyModule;
private DotNetObjectReference<Game_2048>? keyRef;
private int keyRegId;

protected override async Task OnAfterRenderAsync(bool firstRender)
{
    // 仅交互实例会走到 firstRender=true，规避 ServerPrerendered 的预渲染实例
    if (!firstRender || keyModule is not null) return;

    keyRef = DotNetObjectReference.Create(this);
    keyModule = await JS.InvokeAsync<IJSObjectReference>("import", "./js/gamekeyboard.js");
    // 2048：一次按键 = 一步，忽略连发
    keyRegId = await keyModule.InvokeAsync<int>("register", keyRef,
        new { repeatKeys = Array.Empty<string>() });
}

[JSInvokable]
public async Task OnKeyDown(string key)
{
    await InvokeAsync(() =>
    {
        switch (key)
        {
            case "ArrowLeft":  MoveLeft();  break;
            case "ArrowRight": MoveRight(); break;
            case "ArrowUp":    MoveUp();    break;
            case "ArrowDown":  MoveDown();  break;
        }
    });
}

[JSInvokable]
public Task OnKeyUp(string key) => Task.CompletedTask;   // 2048 无 keyup 需求，接口占位

public async ValueTask DisposeAsync()
{
    if (keyModule is not null)
    {
        try
        {
            await keyModule.InvokeVoidAsync("unregister", keyRegId);
            await keyModule.DisposeAsync();
        }
        catch (JSDisconnectedException) { /* 断线/关页，无需清理 */ }
        catch (ObjectDisposedException) { /* 电路已释放 */ }
        keyModule = null;
    }
    keyRef?.Dispose();
    keyRef = null;
}
```

**必须补的守卫**（v1.0 判断正确）：四个 `MoveX()` 首行加 `if (isGameOver) return;`。这样按钮与键盘共用同一守卫，避免两套语义。注意这会让"结束后点按钮不再走棋"——属修 bug，需在记录中注明（G2048-04/05 仍阻塞，无法自动验证）。

### 3.4 Tetris 接入（**先接生命周期**）

#### 3.4.1 现状：`Dispose()` 是死代码

`Tetris.razor` 没有任何 `@implements`，但写了：

```csharp
public void Dispose()      // L932
{
    isDisposed = true;
    StopTimers();
}
```

Blazor 只对实现了 `IDisposable` / `IAsyncDisposable` 的组件调用释放方法 → **这个方法从未被执行**。后果：

- `isDisposed` 永远 false，`StopTimers()` 永不执行 → 离开 `/tetris` 后三个 `Timer` 继续跑（`gameTimer` 每 `speed` 毫秒、`difficultyTimer` 每 3 分钟）；
- 每次触发都 `InvokeAsync(...)` 到已销毁的组件，抛 `ObjectDisposedException` 并被三个 `catch` 吞掉 —— 所以**表面上"没有异常"**，这正是 07 的 TRIS-19/22 一直通过、缺陷一直没被发现的原因；
- 若照 v1.0 只"追加 IAsyncDisposable"而不看清这点，会误以为"JS 清理 + 既有 Dispose 都被调用了"——其实 `DisposeAsync` 才是第一次真正生效的释放路径。**本次必须显式写清这一点，并在记录里登记 D-13。**

#### 3.4.2 接法

```razor
@inject IJSRuntime JS
@implements IAsyncDisposable
```

```csharp
private IJSObjectReference? keyModule;
private DotNetObjectReference<Tetris>? keyRef;
private int keyRegId;

protected override async Task OnAfterRenderAsync(bool firstRender)
{
    if (!firstRender || keyModule is not null) return;

    keyRef = DotNetObjectReference.Create(this);
    keyModule = await JS.InvokeAsync<IJSObjectReference>("import", "./js/gamekeyboard.js");
    // Tetris：←/→ 允许按住连发（移动需要）；↑ 旋转、↓ 软降不连发
    keyRegId = await keyModule.InvokeAsync<int>("register", keyRef,
        new { repeatKeys = new[] { "ArrowLeft", "ArrowRight" } });
}

[JSInvokable]
public async Task OnKeyDown(string key)
{
    await InvokeAsync(() =>
    {
        switch (key)
        {
            case "ArrowLeft":  MovePiece(-1, 0); break;
            case "ArrowRight": MovePiece(1, 0);  break;
            case "ArrowUp":    RotatePiece();    break;
            case "ArrowDown":  StartSoftDrop();  break;   // 自带 isSoftDropping 幂等守卫
        }
    });
}

[JSInvokable]
public async Task OnKeyUp(string key)
{
    if (key == "ArrowDown")
        await InvokeAsync(StopSoftDrop);
}

public async ValueTask DisposeAsync()
{
    if (keyModule is not null)
    {
        try
        {
            await keyModule.InvokeVoidAsync("unregister", keyRegId);
            await keyModule.DisposeAsync();
        }
        catch (JSDisconnectedException) { }
        catch (ObjectDisposedException) { }
        keyModule = null;
    }
    keyRef?.Dispose();
    keyRef = null;

    Dispose();          // ★ 关键：既有同步释放逻辑（isDisposed=true + StopTimers）现在才第一次真正被调用
}
```

> 注意 `Tetris` 组件**不要**再补 `@implements IDisposable`：同时实现两个接口时 Blazor 只调 `DisposeAsync`，`IDisposable` 那份等于没写；保留 `public void Dispose()` 作为普通方法由 `DisposeAsync` 显式调用，语义最清晰。

### 3.5 行为边界（实施后应成立）

| 场景 | 期望 |
|---|---|
| 2048 结束态 | 按键无效（MoveX 守卫），按钮也无效；「重玩」后恢复 |
| 2048 按住 ← | **只走 1 步**（忽略 repeat） |
| Tetris ←/→ 按住 | 连发 ≈16 格/秒（60ms 节流） |
| Tetris ↑ 按住 | **只转 1 次**（忽略 repeat） |
| Tetris ↓ 按住 | 连续软降（由 `softDropTimer` 驱动，与 repeat 无关）；松手即停 |
| Tetris 暂停/结束 | 按键全部无效（方法级守卫） |
| 按住 ↓ 时切走窗口/切标签页 | 失焦即释放，回来不会继续软降（`releaseAll`） |
| 从 `/game_2048` 点导航进 `/tetris` | Tetris 键盘可用；2048 不再响应（unregister id 守卫） |
| 从 `/tetris` 点导航离开 | 键盘在其它页面必须完全无效（D-13 修复后；修复前 Timer 仍在跑但无 UI 影响） |
| JS 加载失败 / 移动端 | 屏幕按钮完全不受影响（键盘是纯增强） |

### 4.3 空块的两种取向（需拍板，二选一）

| 方案 | CSS | 观感 | 结论 |
|---|---|---|---|
| 标准 2048 | `background: #cdc1b4` | 棋盘是一整块亮米色板，压在 `rgba(0,0,0,.8)` 玻璃容器上，与全站暗色风格割裂 | 若用户想要"原汁原味 2048"选它 |
| **暗色玻璃（推荐）** | `background: rgba(255, 255, 255, .06)` | 空位透出容器底色，彩色块仍然醒目，风格与全站一致 | 同时消掉 v1.0 §8 自列的"空块对比度"风险 |

> 本次实施按推荐方案，`.tile-empty` 只此一行即可切换，成本可忽略。

### 4.4 标记与代码

```razor
<div class="tile @TileClass(board[row, col])">@(board[row, col] == 0 ? "" : board[row, col].ToString())</div>
```

```csharp
private static string TileClass(int v) => v switch
{
    0       => "tile-empty",
    <= 2048 => $"tile-{v}",
    _       => "tile-super"
};
```

> 棋盘值只可能是 0/2/4/…/4096，`tile-{v}` 一定命中表内类；>2048 一律 `tile-super`。

## 9. 风险与回退

| 风险 | 影响 | 缓解 / 回退 |
|---|---|---|
| 跨页注册/注销顺序不可控 | 第二个游戏页键盘失灵 | id 守卫（§3.2）+ D02-9 用导航链接覆盖；极端情况回退为"每页各自模块实例" |
| `keyup` 丢失（切窗口时按住 ↓） | Tetris 软降卡死 | `releaseAll` 在 blur/visibilitychange 时释放；且 `PauseGame` 已调 `StopSoftDrop` |
| 连发经 SignalR 往返积压 | 手感粘滞、"松手还在动" | Tetris ←/→ 60ms 节流；2048 直接禁用连发；`unregister` 后无残留 |
| 接上 `IAsyncDisposable` 后暴露既有 Timer 行为变化 | 原"离开页面 Timer 还在跑"变为正常停止 | 这正是修复目标；用 TRIS-19/22 与人工观察确认无新异常 |
| 配色后 `.tile-empty` 与容器对比不足 | 棋盘格不清晰 | 暗色版用 6% 白，实测可辨；若嫌弱改 10%，只调一行 |
| 文案改动牵动 e2e | G2048/NF 假红 | §5 已列全 4 处代码 + 1 处文档；先改 e2e 再改页面，或同一提交 |
| 键盘事件误伤未来新增输入框 | 输入时游戏乱动 | 现在两页无输入控件；将来加输入框需在 JS 里判 `e.target.tagName`（已在 §3.2 留注释位置） |
