## 0. 本次修订摘要

v1.0 的**问题诊断与方向判断全部成立**，但落到 .NET 8 + FluentUI 3.8.0 + `Nullable=enable` 的实际工程时，有 3 处会直接编译失败或产生新警告、2 处运行时隐患。v2.0 的差异如下：

| # | v1.0 做法 | v2.0 做法 | 原因 |
|---|---|---|---|
| 1 | `System.Timers.Timer` + `async void`，仅 `catch (ObjectDisposedException)` | `PeriodicTimer` + `async Task` 循环 + `CancellationTokenSource`，`catch (Exception)` 兜底 | `async void` 里的非预期异常在 .NET Core 下会击穿到线程池（进程级风险）；循环写法天然串行、可取消 |
| 2 | `@bind-Value` 与 `ValueChanged` 并用，并注明"以实测为准" | 改用 .NET 7+ 的 `@bind-Value:after` | 组件的 `@bind-Value` 已占用 `ValueChanged`，二者同时写会冲突，属于"写不出来"的写法 |
| 3 | `private Dictionary<string, DateTime> activeDates;` 无初始化 | `private readonly Dictionary<string, DateTime> anchorDates = new(timePoints);` | 工程已启用 `Nullable`，无初始化的非空字段会产生 CS8618 警告，违背"不新增警告"的约定 |
| 4 | 标记中每帧调用 `GetDays()` | 天数列表缓存到字段 `days`，仅在年/月变更时 `RebuildDays()` | 加入 1 秒刷新后，`GetDays()` 将每秒新建一个 `List`（原来只在事件时渲染），属新增的隐性开销 |
| 5 | 保留两个 `CalculateElapsedTime` 重载 | 统一为单一 `Render(anchor, type, now)` 入口 | 原两个重载逻辑重复，长期会漂移；顺带解决"三条线取不同 `DateTime.Now` 导致秒数不一致" |
| 6 | 事件处理器末尾手动 `StateHasChanged()` | 删除（Blazor 事件回调后自动重渲染） | 冗余代码 |
| 7 | 测试用例 T6「通过 URL/调试绕过联动选 2 月 30 日」 | 改为代码审查项 + 临时改字段验证 | 该操作在现有 UI 下不可构造，用例不可执行 |
| 8 | 未提"自选日期会覆盖页面顶部内置纪念日展示" | 明确写出该副作用，并提供"恢复默认"按钮（P1） | 属行为语义，用户会感知，应显式约定 |
| 9 | 无构建/运行验证步骤 | 增加 `dotnet build` + `http://localhost:14074/loveTime` 实测 | 与《05-开发文档》的实施口径保持一致 |

## 1. 对 v1.0 的可行性检视

### 1.1 事实核对（对现有代码逐条验证）

| v1.0 的描述 | 代码事实 | 结论 |
|---|---|---|
| `days = Enumerable.Range(1, 31)` 固定 1~31 | `LoveTime.razor:83` 完全一致 | ✅ 属实 |
| 选 2 月 31 日 → `new DateTime(y,m,d)` 抛异常且未捕获 | `LoveTime.razor:127` 无 try/catch；异常会终止电路并显示 Blazor 错误条 | ✅ 属实，且后果比文档描述的"崩溃"更明确：**整个 SignalR 电路被中止**，用户必须刷新页面 |
| `OnInitialized` 只计算一次 | `LoveTime.razor:96-102` | ✅ 属实 |
| `ElapsedTimeYear/Months/Day` 已算未渲染 | `LoveTime.razor:112-118` 计算，标记区（L5-7）只渲染 `ElapsedTime` | ✅ 属实 |
| 组件未实现 `IDisposable` | 文件内无 `@implements` | ✅ 属实 |
| `_Host.cshtml` 为 `ServerPrerendered` | `Pages/_Host.cshtml:10` `render-mode="ServerPrerendered"` | ✅ 属实，§2.2 的推论成立 |
| Tetris 是 Timer 生命周期的同源模式 | `Tetris.razor:423/454-627/861`（`isDisposed`/`timerLock`/`InvokeAsync`/`Dispose`） | ✅ 属实 |

**结论：v1.0 的现状分析与修复方向（秒级刷新 + `DaysInMonth` 联动 + 未来日期校验）全部成立，无需推翻。**

### 1.2 必须修改的问题（阻塞级）

**① `@bind-Value` 与 `ValueChanged` 并用 —— 写不出来**

v1.0 §3.4 的写法：

```razor
<FluentSelect TOption="string" Label="月份：" @bind-Value="selectedMonth"
              ValueChanged="OnYearMonthChanged">
```

`@bind-Value` 在编译期就会展开成 `Value` + `ValueChanged` 两个参数，再手写 `ValueChanged` 属重复指定，Razor 编译报错。v1.0 注释里"如版本行为异常，可改为只用 `ValueChanged`"实际上不是"备选"，而是**唯一可行的两条路之一**。

v2.0 采用更干净的 .NET 7+ 语法 `@bind-Value:after`（绑定赋值完成后再执行回调，字段已更新）：

```razor
<FluentSelect TOption="string" Label="月份：" @bind-Value="selectedMonth"
              @bind-Value:after="OnYearMonthChanged">
```

> 已在 FluentUI 3.8.0 包内确认 `ListComponentBase<T>` 提供 `Value` / `ValueChanged`（`EventCallback<T>`）参数，`@bind-Value` 可直接工作；`@bind-Value:after` 是 Razor 编译器特性，与组件实现无关。

**② `async void` + 只捕获 `ObjectDisposedException` —— 进程级风险**

v1.0 §3.3 的 `OnRefreshTimerElapsed` 是 `async void`。该回调里除 `ObjectDisposedException` 外的任何异常（如电路断开时 `InvokeAsync` 抛出的 `InvalidOperationException`、渲染期 `NullReferenceException`）都会逃逸到线程池，**.NET Core 下未观测异常可终止进程**。个人站点一旦被一个已断开的标签页拖垮，代价过高。

v2.0 用 `PeriodicTimer` + `async Task` 循环，异常统一 `catch (Exception)` 后静默退出循环。

**③ 字段未初始化 + `Nullable=enable` —— 新增编译警告**

`jtjsym.csproj` 已设 `<Nullable>enable</Nullable>`。v1.0 §3.2 的 `private Dictionary<string, DateTime> activeDates;` 会在构造函数退出时仍为 null，触发 **CS8618**。改为就地初始化即可（`new(timePoints)` 还能省掉 `OnInitialized` 里的赋值语句）。

### 1.3 建议优化的问题（非阻塞）

| # | 问题 | 说明 |
|---|---|---|
| 4 | `AutoReset=true` + `async void` 无重入保护 | 若某次渲染耗时接近 1 秒，两次 Tick 会叠加，三组时间被并发写入。`PeriodicTimer` 循环 await 天然串行，不需要额外锁 |
| 5 | `GetDays()` 每秒被调用一次 | 标记区每次渲染都会执行，加入 1s 刷新后相当于每秒新建一个 `List<string>`。缓存到字段即可 |
| 6 | 事件处理器末尾 `StateHasChanged()` 冗余 | Blazor 事件回调结束后自动重渲染，手动调用无意义 |
| 7 | 两个 `CalculateElapsedTime` 重载重复 | 建议收敛为单一 `Render`，并在函数内只取一次 `DateTime.Now`（否则三条线可能跨秒边界，出现"相识 3 秒、相爱 2 秒"的抖动感） |
| 8 | T6 用例不可执行 | "通过 URL/调试绕过联动"在现有 UI 下做不到；改为临时把 `selectedDay` 改成 `"30"` 验证 try/catch，验证后还原 |
| 9 | 缺少构建验证 | 本项目口径是 `dotnet build` 0 错误 0 新增警告 + 运行实测（见《05-开发文档》§4.4） |

### 1.4 提示级（记录即可，本次不处理）

- **时区**：全部计算基于服务器本机 `DateTime.Now`。IIS 部署在国内单一时区，无 DST，可接受；若将来跨时区部署，需改为显式时区换算。
- **年/月/天换算仍为 365/30 近似**（`elapsed.Days / 365`、`% 365 / 30`），跨闰年会差 1 天。v1.0 已把它列入后续，v2.0 同（见 §7，附精确算法备用）。
- **后台标签页仍在每秒推送**：Blazor Server 不会因页面不可见而停止渲染，会持续产生 SignalR 帧。个人站点可忽略，见 §7 的可选优化。

## 2. 需求与验收目标（修订后）

**P0（本次必做）**

1. 三条内置纪念日计时 + 用户自选结果，**每秒自动刷新**，无需刷新页面；
2. 日选项随年/月联动（含闰年 2 月 29 日），切换后越界日期自动收敛；
3. 未来日期拒绝计算并给出中文提示；非法日期（双保险）不崩溃；
4. 用户自选日期后，该类型的计时**以自选日为锚点持续跳动**，不被内置纪念日覆盖；
5. 组件销毁（离开页面/断线）时定时器释放干净，无异常日志；
6. 不改动其他页面与全局样式，`dotnet build` 0 错误、0 新增警告。

**P1（一并做，成本极低）**

7. "恢复默认纪念日"按钮：自选日期覆盖后，可一键还原为内置纪念日。

**非目标**：不改 365/30 换算算法、不做持久化、不引入 JS 计时。

## 3. 方案设计

### 3.1 总览

```
页面加载（预渲染实例）
  OnInitialized    → RebuildDays() + RefreshAll()     仅算首屏，不建定时器
页面加载（交互实例）
  OnInitialized    → 同上（幂等，重复执行无副作用）
  OnAfterRender(true) → StartTicker()：仅交互实例会走到这里
每秒（PeriodicTimer 循环，串行）
  → InvokeAsync → isDisposed 检查 → RefreshAll() → StateHasChanged()
用户改动年/月
  @bind-Value 赋值 → @bind-Value:after → RebuildDays()（重建天数 + 收敛 selectedDay + 清提示）
用户点"计算XX时间"
  → 校验（解析 / 日期存在 / 不晚于今天）→ 通过则 anchorDates[type] = 自选日 → Render 一次
组件销毁
  Dispose() → isDisposed = true → tickerCts.Cancel() → 循环退出 → PeriodicTimer 释放
```

### 3.2 状态模型

| 字段 | 类型 | 作用 |
|---|---|---|
| `timePoints` | `static readonly Dictionary<string, DateTime>` | 三个内置纪念日，**常量语义，永不被改写** |
| `anchorDates` | `readonly Dictionary<string, DateTime>`，初始 `= new(timePoints)` | 各类型**当前生效的锚点**：默认 = 内置纪念日；用户自选后 = 自选日。刷新 Tick 只读它 |
| `elapsedTimes` | `Dictionary<string, ElapsedTimeInfo>` | 渲染用的字符串缓存（保持现有结构不变） |
| `days` | `List<string>` | 当前可选的日列表，由 `RebuildDays()` 生成 |
| `validationMessage` | `string?` | 校验提示，null 表示不显示 |
| `tickerCts` | `CancellationTokenSource?` | 刷新循环的取消源，null 表示未启动 |

> 相比 v1.0 的 `activeDates`，只是改名（`anchorDates` 语义更准）+ 就地初始化，其余一致。
> **重要语义**：`anchorDates[type]` 被改写后，页面顶部"我们相识已经过去了…"那一行也会随之变化——这是**现有行为**（原来点"计算"就会覆盖顶部展示），本次只是让它继续跳动。见 §3.6 的"恢复默认"。

### 3.3 秒级刷新

**选型对比**

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. `System.Timers.Timer`（v1.0） | 与 Tetris 写法一致 | `async void` 异常外溢；`AutoReset` 可能重入；需手写锁 | 不采用（Tetris 那是"随游戏状态反复启停 + 变速"的场景，这里是常驻单频，模式不匹配） |
| **B. `PeriodicTimer` + `async Task` 循环** | 无 `async void`；await 串行；`CancellationToken` 原生支持；无锁 | 需要自己管 CTS 生命周期 | **采用** |
| C. JS `setInterval` + JSInterop 只改 DOM 文本 | 服务端零开销 | 破坏"状态在服务端"的既有模型；引入 JS/互操作复杂度；首屏与刷新两套逻辑 | 备选，见 §7 |

> 与项目约定《现状.md》§3.4「定时逻辑沿用 Tetris 模式」的关系：本方案**保留其全部安全内核**——`isDisposed` 双检、`InvokeAsync` 切回渲染上下文、`Dispose()` 统一释放、`catch` 兜底——只把"触发器"从 `Timer`+`async void` 换成 `PeriodicTimer`+循环，属于同一模式的更稳实现，不算偏离。

**实现要点**

```csharp
private CancellationTokenSource? tickerCts;
private bool isDisposed;

protected override void OnAfterRender(bool firstRender)
{
    if (firstRender) StartTicker();     // 仅交互实例执行，规避预渲染双执行
}

private void StartTicker()
{
    if (isDisposed || tickerCts is not null) return;   // 防重复启动
    tickerCts = new CancellationTokenSource();
    _ = RunTickerAsync(tickerCts.Token);
}

private async Task RunTickerAsync(CancellationToken token)
{
    using var timer = new PeriodicTimer(TimeSpan.FromSeconds(1));
    try
    {
        while (await timer.WaitForNextTickAsync(token).ConfigureAwait(false))
        {
            await InvokeAsync(() =>
            {
                if (isDisposed) return;
                RefreshAll();
                StateHasChanged();      // InvokeAsync 不会自动渲染，必须显式调用
            });
        }
    }
    catch (OperationCanceledException) { /* 正常退出 */ }
    catch (Exception) { /* 电路已断开/渲染器已释放，静默退出，不击穿线程池 */ }
}

public void Dispose()
{
    isDisposed = true;
    tickerCts?.Cancel();
    tickerCts?.Dispose();
    tickerCts = null;
}
```

- `PeriodicTimer` 属 `System.Threading`（`ImplicitUsings` 已覆盖），**不再需要 `@using System.Timers`**；
- 循环内 `await InvokeAsync(...)` 保证串行，不会出现 v1.0 的重入竞争；
- `Dispose()` 只发取消信号，`PeriodicTimer` 由 `using` 在循环退出时释放，不会与回调线程抢锁；
- 首帧（预渲染 HTML）由 `OnInitialized` 里的 `RefreshAll()` 提供，因此"预渲染显示静态值 → 交互连接后开始跳动"的过渡是连续的，不会出现空白或 `00 秒`。

### 3.4 年月日联动

**核心：天数列表缓存 + 变更时重建 + 越界收敛**

```csharp
private void RebuildDays()
{
    if (!int.TryParse(selectedYear, out var y) || !int.TryParse(selectedMonth, out var m))
        return;

    var count = DateTime.DaysInMonth(y, m);
    days = Enumerable.Range(1, count).Select(d => d.ToString()).ToList();

    // 越界收敛：1/31 → 切到 2 月 → 收敛为 2 月最后一天
    if (!int.TryParse(selectedDay, out var d) || d < 1 || d > count)
        selectedDay = days[^1];
}

private void OnYearMonthChanged()
{
    validationMessage = null;
    RebuildDays();        // 字段已在 @bind 赋值阶段更新完毕
}

private void OnDayChanged()
{
    validationMessage = null;   // 用户改了日，旧的报错信息应失效
}
```

标记区：

```razor
<FluentSelect TOption="string" Label="年份：" @bind-Value="selectedYear"
              @bind-Value:after="OnYearMonthChanged"
              class="custom-select" Width="120px">
    @foreach (var y in years) { <FluentOption Value="@y">@y</FluentOption> }
</FluentSelect>

<FluentSelect TOption="string" Label="月份：" @bind-Value="selectedMonth"
              @bind-Value:after="OnYearMonthChanged"
              class="custom-select" Width="100px">
    @foreach (var m in months) { <FluentOption Value="@m">@m</FluentOption> }
</FluentSelect>

<FluentSelect @key="@($"{selectedYear}-{selectedMonth}")"
              TOption="string" Label="日期：" @bind-Value="selectedDay"
              @bind-Value:after="OnDayChanged"
              class="custom-select" Width="100px">
```

- `@key` 让"日"下拉在年/月变化时**重建实例**。FluentUI 3.x 的 `FluentSelect` 底层是 FAST Web Component，仅替换子 `<FluentOption>` 时存在选项列表未真正刷新的已知风险（v1.0 未考虑）；用 `@key` 强制重建最省心。**若实测不加 `@key` 也能正确刷新，可去掉**——保留与否以 T4/T5 实测为准；
- 年月下拉**不加** `@key`（避免用户正在展开的弹层被销毁）。

### 3.5 合法性校验

单一入口，三级校验，全部返回而非抛异常：

```csharp
private void ApplyCustomDate(string type)
{
    validationMessage = null;

    // 1) 完整性
    if (!(int.TryParse(selectedYear, out var year) &&
          int.TryParse(selectedMonth, out var month) &&
          int.TryParse(selectedDay, out var day)))
    {
        validationMessage = "请先选择完整的年、月、日。";
        return;
    }

    // 2) 日期存在性（双保险：联动正常时不会走到这里）
    DateTime selectedDate;
    try
    {
        selectedDate = new DateTime(year, month, day);
    }
    catch (ArgumentOutOfRangeException)
    {
        validationMessage = "所选日期不存在，请检查年、月、日。";
        return;
    }

    // 3) 未来日期
    if (selectedDate > DateTime.Today)
    {
        validationMessage = "纪念日不能晚于今天，请重新选择。";
        return;
    }

    anchorDates[type] = selectedDate;
    Render(selectedDate, type);
    // 事件回调结束后 Blazor 自动重渲染，无需 StateHasChanged()
}
```

### 3.6 统一渲染入口 + 恢复默认（P1）

```csharp
private void RefreshAll()
{
    var now = DateTime.Now;                 // 一次取时，三条线同源，秒数对齐
    foreach (var type in anchorDates.Keys)
        Render(anchorDates[type], type, now);
}

private void Render(DateTime anchor, string type, DateTime? now = null)
{
    var elapsed = (now ?? DateTime.Now) - anchor;
    if (elapsed < TimeSpan.Zero) elapsed = TimeSpan.Zero;   // 双保险：不展示负值

    var info = elapsedTimes[type];
    info.ElapsedTime = $"{elapsed.Days} 天, {elapsed.Hours} 小时, {elapsed.Minutes} 分钟, {elapsed.Seconds} 秒";

    info.ElapsedTimeYear   = (elapsed.Days / 365).ToString();
    info.ElapsedTimeMonths = ((elapsed.Days % 365) / 30).ToString();
    info.ElapsedTimeDay    = ((elapsed.Days % 365) % 30).ToString();
}

// P1：一键还原内置纪念日
private void ResetAnchor(string type)
{
    anchorDates[type] = timePoints[type];
    validationMessage = null;
    Render(timePoints[type], type);
}
```

```razor
@code {
    private sealed class ElapsedTimeInfo
    {
        public string ElapsedTime { get; set; } = string.Empty;
        public string ElapsedTimeDay { get; set; } = string.Empty;
        public string ElapsedTimeMonths { get; set; } = string.Empty;
        public string ElapsedTimeYear { get; set; } = string.Empty;
    }

    private readonly Dictionary<string, ElapsedTimeInfo> elapsedTimes = new()
    {
        { "meet", new ElapsedTimeInfo() },
        { "love", new ElapsedTimeInfo() },
        { "married", new ElapsedTimeInfo() }
    };

    /// <summary>内置纪念日，常量语义，永不被改写。</summary>
    private static readonly Dictionary<string, DateTime> timePoints = new()
    {
        { "meet", new DateTime(2018, 4, 22) },
        { "love", new DateTime(2022, 2, 25) },
        { "married", new DateTime(2023, 8, 8) }
    };

    /// <summary>各类型当前生效的锚点：默认 = 内置纪念日，用户自选后被替换。</summary>
    private readonly Dictionary<string, DateTime> anchorDates = new(timePoints);

    private readonly List<string> years =
        Enumerable.Range(1950, DateTime.Now.Year - 1949).Select(y => y.ToString()).ToList();
    private readonly List<string> months =
        Enumerable.Range(1, 12).Select(m => m.ToString()).ToList();

    private List<string> days = new();

    private string selectedYear = "1950";
    private string selectedMonth = "1";
    private string selectedDay = "1";

    private string? validationMessage;

    private CancellationTokenSource? tickerCts;
    private bool isDisposed;

    protected override void OnInitialized()
    {
        RebuildDays();
        RefreshAll();
    }

    protected override void OnAfterRender(bool firstRender)
    {
        if (firstRender)
        {
            StartTicker();
        }
    }

    // ---------- 秒级刷新 ----------

    private void StartTicker()
    {
        if (isDisposed || tickerCts is not null) return;

        tickerCts = new CancellationTokenSource();
        _ = RunTickerAsync(tickerCts.Token);
    }

    private async Task RunTickerAsync(CancellationToken token)
    {
        using var timer = new PeriodicTimer(TimeSpan.FromSeconds(1));

        try
        {
            while (await timer.WaitForNextTickAsync(token).ConfigureAwait(false))
            {
                await InvokeAsync(() =>
                {
                    if (isDisposed) return;

                    RefreshAll();
                    StateHasChanged();
                });
            }
        }
        catch (OperationCanceledException)
        {
            // 正常退出
        }
        catch (Exception)
        {
            // 电路已断开或渲染器已释放，静默退出，避免异常逃逸到线程池
        }
    }

    public void Dispose()
    {
        isDisposed = true;
        tickerCts?.Cancel();
        tickerCts?.Dispose();
        tickerCts = null;
    }

    // ---------- 渲染 ----------

    private void RefreshAll()
    {
        var now = DateTime.Now;

        foreach (var type in anchorDates.Keys)
        {
            Render(anchorDates[type], type, now);
        }
    }

    private void Render(DateTime anchor, string type, DateTime? now = null)
    {
        var elapsed = (now ?? DateTime.Now) - anchor;
        if (elapsed < TimeSpan.Zero)
        {
            elapsed = TimeSpan.Zero;
        }

        var info = elapsedTimes[type];
        info.ElapsedTime =
            $"{elapsed.Days} 天, {elapsed.Hours} 小时, {elapsed.Minutes} 分钟, {elapsed.Seconds} 秒";

        info.ElapsedTimeYear = (elapsed.Days / 365).ToString();
        info.ElapsedTimeMonths = ((elapsed.Days % 365) / 30).ToString();
        info.ElapsedTimeDay = ((elapsed.Days % 365) % 30).ToString();
    }

    // ---------- 日期联动 ----------

    private void RebuildDays()
    {
        if (!int.TryParse(selectedYear, out var y) || !int.TryParse(selectedMonth, out var m))
        {
            return;
        }

        var count = DateTime.DaysInMonth(y, m);
        days = Enumerable.Range(1, count).Select(d => d.ToString()).ToList();

        if (!int.TryParse(selectedDay, out var d) || d < 1 || d > count)
        {
            selectedDay = days[^1];
        }
    }

    private void OnYearMonthChanged()
    {
        validationMessage = null;
        RebuildDays();
    }

    private void OnDayChanged()
    {
        validationMessage = null;
    }

    // ---------- 计算 ----------

    private void ApplyCustomDate(string type)
    {
        validationMessage = null;

        if (!(int.TryParse(selectedYear, out var year) &&
              int.TryParse(selectedMonth, out var month) &&
              int.TryParse(selectedDay, out var day)))
        {
            validationMessage = "请先选择完整的年、月、日。";
            return;
        }

        DateTime selectedDate;
        try
        {
            selectedDate = new DateTime(year, month, day);
        }
        catch (ArgumentOutOfRangeException)
        {
            validationMessage = "所选日期不存在，请检查年、月、日。";
            return;
        }

        if (selectedDate > DateTime.Today)
        {
            validationMessage = "纪念日不能晚于今天，请重新选择。";
            return;
        }

        anchorDates[type] = selectedDate;
        Render(selectedDate, type);
    }

    private void ResetAnchor(string type)
    {
        anchorDates[type] = timePoints[type];
        validationMessage = null;
        Render(timePoints[type], type);
    }
}
```

## 7. 风险与权衡

| 风险 | 影响 | 缓解 |
|---|---|---|
| `PeriodicTimer` 在电路断开后 `InvokeAsync` 抛异常 | 循环异常退出 | 已用宽 `catch (Exception)` 兜底，且 `Dispose` 主动取消（§3.3） |
| 每秒 `StateHasChanged` 重渲染整页 | 标记区含 3 个 `FluentSelect`，重渲染会增加 diff 开销 | 天数已缓存（不再每秒 new List）；`FluentSelect` 参数未变时 Blazor 不会重渲染子组件。若实测有闪烁/焦点丢失，再把计时文本抽成独立子组件（`ElapsedTicker.razor`），使其成为唯一重渲染的子树 |
| `FluentSelect` 替换选项后未刷新 | 日下拉显示与字段不一致 | 日下拉加 `@key` 强制重建（已内置）；实测正常则可移除 |
| 后台标签页持续推送 | 每秒一帧 SignalR | 个人站点可忽略；见 §7.1 可选优化 |
| `DateTime.Now` 依赖服务器时区 | 跨时区部署会出现小时级偏差 | 单机国内部署无此问题；如需跨区，改为 `TimeZoneInfo` 显式换算 |
| 用户自选日期覆盖顶部内置展示 | 语义混淆 | 已提供"恢复默认"按钮（P1）；文案与文档均已注明 |

### 7.1 后续可选优化（不在本次范围）

| # | 项 | 说明 |
|---|---|---|
| 1 | 展示"X 年 X 月 X 天" | `ElapsedTimeYear/Months/Day` 已算未展示。若展示，建议同时把 365/30 近似换成日历精确算法（下方参考） |
| 2 | 页面不可见时暂停刷新 | 通过 JSInterop 监听 `document.visibilitychange`，切走时取消循环、回来时重启，省流量 |
| 3 | 刷新频率提到 250ms 但仅在"秒"变化时才渲染 | 秒数更"准点"，且不增加 SignalR 帧数（代价是服务端 CPU 略升） |
| 4 | 纪念日可配置 | 三个内置日期硬编码，可改为 `appsettings.json` 或在页面内编辑 + 持久化（需引入存储层） |
| 5 | 倒计时模式 | 支持未来纪念日"距离 XX 还有 X 天"，可用同一套 `anchorDates` 模型 |

精确年/月/天换算（供第 1 项使用）：

```csharp
private static (int Years, int Months, int Days) DiffYmd(DateTime from, DateTime to)
{
    int years = to.Year - from.Year;
    int months = to.Month - from.Month;
    int days = to.Day - from.Day;

    if (days < 0)
    {
        months--;
        var prevMonth = to.AddMonths(-1);
        days += DateTime.DaysInMonth(prevMonth.Year, prevMonth.Month);
    }

    if (months < 0)
    {
        years--;
        months += 12;
    }

    return (years, months, days);
}
```
