## 2. D-11 修复：PageTitle 冲突

### 2.1 根因（执行记录 §3 已确认）

`App.razor` NotFound 分支声明 `<PageTitle>Not found</PageTitle>`，但内容包在 `<LayoutView Layout="MainLayout">` 里，而 `MainLayout.razor` 第一行也有 `<PageTitle>jtjsym</PageTitle>`。两者都渲染进同一个 `HeadOutlet`，后渲染的 MainLayout 覆盖前者 → 任何路由标题恒为 `jtjsym`。

### 2.2 修复方案：布局层让位 + 页面各自声明标题

**原则**：`<PageTitle>` 只由页面级组件声明；布局层不再声明。

**(1) `Shared/MainLayout.razor`** —— 删除第 3 行 `<PageTitle>jtjsym</PageTitle>`。

**(2) `App.razor`** —— NotFound 标题改为全站一致的中文：

```razor
<NotFound>
    <PageTitle>页面不存在</PageTitle>
    <LayoutView Layout="@typeof(MainLayout)">
        <p role="alert">Sorry, there's nothing at this address.</p>
    </LayoutView>
</NotFound>
```

> 正文 `Sorry, there's nothing...` 不在本次范围；标题取中文是为与全站风格一致。若倾向保留英文 `Not found`，仅需同步修改 §5 的 NAV-09 预期值。

**(3) 为缺标题的页面补 `<PageTitle>`**（此前靠 MainLayout 兜底，移除后必须补齐）：

| 文件 | 追加内容 |
|---|---|
| `Pages/MyPage/LoveTime.razor` | `<PageTitle>爱情计时器</PageTitle>` |
| `Pages/MyPage/Game_2048.razor` | `<PageTitle>2048</PageTitle>` |
| `Pages/MyPage/CodingPlace.razor` | `<PageTitle>编程挑战</PageTitle>` |

已自带标题、无需改动的页面：Index（jtjsym）、Counter（按下试试）、Tetris（俄罗斯方块）。`_Layout.cshtml` 的静态 `<title>jtjsym</title>` 保留，作为预渲染间隙的回退。

### 2.3 修复后标题基线（回归对照表）

| 路由 | 浏览器标题 |
|---|---|
| `/` | jtjsym |
| `/counter` | 按下试试 |
| `/loveTime` | 爱情计时器 |
| `/game_2048` | 2048 |

## 3. D-12 修复：/loveTime 375px 横向溢出

### 3.1 根因（执行记录 §6 已确认）

375px 视口下 `scrollWidth 430 > 375`。三行计时文本（"我们步入婚姻已经过去了：1181 天, 5 小时, 30 分钟, 10 秒"）本身很长，叠加 `.timer` 的固定样式 `padding: 0 30px`（左右共 60px）与 `margin: 20px`（左右共 40px），且 `.timer` 为 `inline-flex` + 固定 `height: 52px`，收缩能力差。

**约束**：`.timer` 类同时被三个 FluentButton（计算按钮）复用——修复样式**不能破坏按钮形态**，必须只作用于三个展示行。

### 3.2 修复方案：展示行专用类 + 窄屏媒体查询

**(1) `Pages/MyPage/LoveTime.razor`** —— 三个展示行追加专用类（保留 `.timer` 基础外观）：

```razor
<div class="timer timer-display">我们相识已经过去了：@elapsedTimes["meet"].ElapsedTime</div>
<div class="timer timer-display">我们相爱已经过去了：@elapsedTimes["love"].ElapsedTime</div>
<div class="timer timer-display">我们步入婚姻已经过去了：@elapsedTimes["married"].ElapsedTime</div>
```

**(2) `wwwroot/css/site.css`** —— 新增规则（追加到文件末尾）：

```css
/* D-12：展示行允许换行收缩，不参与按钮样式 */
.timer-display {
    max-width: 100%;
    box-sizing: border-box;
    font-variant-numeric: tabular-nums; /* 秒级刷新时数字宽度稳定，避免整行抖动 */
}

@media (max-width: 480px) {
    .timer-display {
        display: block;          /* 覆盖 inline-flex，可正常折行 */
        height: auto;            /* 解除固定 52px，允许两行 */
        min-height: 52px;
        margin: 10px auto;
        padding: 8px 12px;       /* 替代 0 30px 的左右大内边距 */
        white-space: normal;
        overflow-wrap: break-word;
        text-align: center;
    }

    .date-bar {
        flex-wrap: wrap;         /* 年/月/日三个下拉在极窄屏可换行 */
    }
}
```

设计说明：

- 桌面端（>480px）**零变化**：媒体查询外的 `.timer-display` 只加了 `max-width`、`box-sizing`、`tabular-nums`，无视觉影响；
- 三个 FluentButton 未加 `timer-display`，`.timer` 原样式不受影响；
- `tabular-nums` 顺带解决每秒刷新时数字宽度变化导致的轻微抖动（配合 06 文档的秒级自动刷新）；
- 若 T2 实测仍有残余溢出（个别机型字体差异），回退手段：媒体查询内追加 `letter-spacing: -0.2px` 或把"已经过去了："改为窄屏短文案（如"相识："）——二选一，不叠加。

## 4. 任务 C：测试脚本固化进仓库

### 4.1 现状

2026-11-01 全量测试由 8 个 Playwright 脚本驱动，位于临时目录 `C:\Users\jtjsy\AppData\Local\Temp\jtjsym_e2e\`，**未纳入仓库**（执行记录 §8）。问题：换机器/清临时目录后回归能力归零；脚本与《07》用例的对应关系无版本化记录。

### 4.2 固化方案：`tools/e2e/` Playwright 回归套件

在仓库根新建 `tools/e2e/`，用 `@playwright/test` 官方测试运行器承载（替代裸 .mjs 脚本，获得重试/报告/过滤能力）：

```
tools/e2e/
├── package.json              # @playwright/test 依赖 + npm scripts
├── playwright.config.mjs     # baseURL 可配、复用运行中实例、chromium+firefox
├── README.md                 # 运行说明（安装/启动/命令/踩坑）
└── tests/
    ├── smoke.spec.mjs        # ★ 冒烟集：P0 用例自动化版（28 条中可自动化部分）
    ├── nav_fish.spec.mjs     # NAV + FISH 全量（迁自 nav_fish/fix 脚本）
    ├── lt.spec.mjs           # LT 24 条（迁自 lt.mjs）
    ├── g2048.spec.mjs        # G2048 全量 + 40 步不变式校验（迁自 g2048/b）
    ├── tris.spec.mjs         # TRIS 可自动化部分（迁自 tris_core 等，分钟级等待项标记 slow）
    ├── code_nf.spec.mjs      # CODE + NF（Firefox、375px、Slow 3G、并发、控制台）
    └── d11_d12.spec.mjs      # ★ 本次新增：D-11/D-12 修复验证（见 §6）
```

**关键配置要点**（`playwright.config.mjs`）：

```js
export default defineConfig({
    testDir: './tests',
    timeout: 60_000,
    reporter: [['list'], ['html', { open: 'never' }]],
    use: {
        baseURL: process.env.BASE_URL ?? 'http://localhost:14074',
    },
    projects: [
        { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
        { name: 'firefox', testIgnore: /smoke/, use: { ...devices['Desktop Firefox'] } }, // Firefox 仅 NF 兼容组跑
    ],
    // VS 调试实例已占用端口时直接复用，避免重复启动
});
```

**`package.json` scripts**（模块级单跑 = "跑对应的测试用例"的落点）：

```json
{
  "scripts": {
    "test:smoke":  "playwright test tests/smoke.spec.mjs",
    "test:nav":    "playwright test tests/nav_fish.spec.mjs --grep NAV",
    "test:fish":   "playwright test tests/nav_fish.spec.mjs --grep FISH",
    "test:lt":     "playwright test tests/lt.spec.mjs",
    "test:g2048":  "playwright test tests/g2048.spec.mjs",
    "test:tris":   "playwright test tests/tris.spec.mjs",
    "test:code":   "playwright test tests/code_nf.spec.mjs --grep CODE",
    "test:nf":     "playwright test tests/code_nf.spec.mjs --grep NF|D12",
    "test:all":    "playwright test"
  }
}
```

**迁移原则**：脚本逻辑以 2026-11-01 执行记录中已验证的行为为准原样迁移（选择器、等待策略、校验算法——含 G2048 的 40 步不变式校验），仅做三件事：① 适配 test runner 断言写法；② 按模块拆分归位；③ 补 D-11/D-12 新断言（§6）。**不趁机重写测试逻辑**，避免固化时引入未验证行为。

### 4.3 git 纳管与忽略规则

`.gitignore` 追加：

```gitignore
# tools/e2e（Playwright 回归套件）运行产物
node_modules/
playwright-report/
test-results/
```

`package-lock.json` **提交**（保证依赖可复现）；Playwright 浏览器二进制（`npx playwright install` 装到用户目录）不入库。

### 4.4 运行前提（写入 tools/e2e/README.md）

1. 一次性：`cd tools/e2e && npm install && npx playwright install chromium firefox`；
2. 启动站点：`dotnet run`（或复用 VS 调试实例）；
3. 站点地址非默认端口时：`BASE_URL=http://localhost:<port> npm run test:smoke`；
4. 踩坑提示（沿用执行记录 §1）：VS 调试中 `dotnet build` 可能报 `MSB3027`（dll 被锁）——先关调试再构建，或直接对运行中实例执行测试。

## 5. 流程约定：开发完代码 → 跑测试 → 登记

固化后的固定流程（写入 `tools/e2e/README.md`，并作为项目协作约定执行）：

```
代码开发完成
  ① dotnet build —— 0 error 才继续
  ② 启动站点（dotnet run 或 VS 调试）
  ③ cd tools/e2e
     npm run test:<本次改动模块>     ← 对应用例
     npm run test:smoke             ← 冒烟集必跑
  ④ 全绿 → 本次无遗留；有失败 → 回到代码修复，不得带病登记
  ⑤ 登记：新建 1设计文档/9测试用例固定执行历史/YYYY-MM-DD-<主题>-测试执行记录.md
        （格式沿用 2026-11-01 记录：执行环境 / 结果汇总表 / 失败项 / 关键结论）
  ⑥ 台账联动：修复的 D-xx 在《07》§10.1 改状态为"已关闭"并移入 §10.2（附 commit/依据）
  ⑦ 之后才按既有约定更新《技术栈与代码结构现状》《更新记录》
```

> 阻塞/人工项（服务端日志、生产环境 HTTPS、分钟级等待等）沿用执行记录 §4 的处理方式：在登记记录中标注"人工验收"并注明原因。
