## 5. 关键实测结论

### 5.1 新增：`--no-launch-profile` 会打歪所有尺寸类断言（本次最大坑）

用 `dotnet run --no-launch-profile` 起站点时，环境回落为 **Production**，StaticWebAssets 不再从构建输出提供，`_content/Microsoft.Fast.Components.FluentUI/*` **全部 404**。后果：

- Fluent 自定义元素不升级，`<fluent-option>` 以行内元素渲染 → 页面宽度被撑到 2.7~3.1 倍；
- 此时测出的"横向溢出"是**假结果**——一开始 D-12 的六条断言全红，且桌面 1400px 也"溢出"，才定位到是资源 404 而非 CSS。

已在 `playwright.config.mjs`、`tools/e2e/README.md`、《04-技术栈速查》三处写入「`--no-launch-profile` 必须配 `--environment Development`」。

### 5.2 TRIS 消行断言：不能靠分数反推消行数

自动玩过程中，软降每格 +1 会与消行奖励混在同一次分数增量里（实测出现 116 = 软降 16 + 消 1 行 100）。最终口径：

```
cleared = (落前非空格数 + 本次方块格数 − 落后非空格数) / 10   ← 由棋盘精确反推，不猜
分数增量 ∈ [奖励, 奖励+25]                                  ← 留 20 行软降余量
```

另修正两处模拟实现：`landGrid` 返回的是**形状矩阵第 0 行**的行号（与 overlay 同一坐标系），`applyClear` 消行后必须在**顶部补等量空行**（行数恒 20，与 `Tetris.ClearRows` 一致）——最初用 `filter` 把数组压成 18 行，导致 TRIS-12 一度 0/20。

结果：TRIS-10 消 1 行 20 次、TRIS-11 全部奖励档位校验通过、TRIS-12 消行后棋盘与模拟**逐格一致 20/20**、TRIS-13 无消行落块得分均 ≤25、TRIS-20 堆满后方向/旋转按钮全部禁用、TRIS-21 重开恢复 `分数 0 / 难度 1`。

### 5.3 G2048 合并规则：40 步不变式覆盖 G2048-07~18

`G2048-STEP` 每走一步都用**独立实现的标准规则**（浏览器内 JS）模拟该方向，再与页面实际棋盘、分数、块数逐项比对，40 步零偏差、其中 25 步含合并。这等价覆盖了 G2048-07~18 的合并语义（含"合并出的块不得再合并"、"先压缩再合并"、边界不合并）。

> **遗留**：单例显式断言仍需 `Game2048Core` 抽离后以 xUnit 落地（《07》§12 建议）。本轮不新增该工程，故记入 §7 阻塞。

### 5.4 未修复缺陷保持"红而不绿"

`TRIS-26`（暂停期间难度不应上升，D-04）以 `test.fixme` 标记并写明理由，**不计入通过数**。11-01 基线已实测证据：暂停 3 分钟后难度 `1 → 2`，而方块位置与分数均未变。

## 7. 本次工具链踩坑（已固化到 README 与《现状》§3.4）

1. **`trace` 必须关**：3 分钟量级用例单条能产 7000+ 帧截图（实测 7144 个文件），导致 Playwright 清理 `test-results` 时被文件安全守卫拦截、整轮测试直接失败。现设 `trace:'off'`，需要逐帧复盘时临时 `--trace on`；
2. **FluentSelect 不能"赋 value + 派发 change"**：Blazor 不认，必须点击展开后点 `fluent-option`；
3. **木鱼装饰图标是 `<div><img src="counter.gif">`**，不是 `fluent-icon`；
4. **`.top-row a` 会误匹配导航栏品牌链接**，须用 `main .top-row a`；
5. **方块坐标不能 `parseFloat(style.top)`**：《08》后 `top` 已是 `calc(var(--cell-size) * n)`，须读 `getBoundingClientRect()`；
6. **`checkEq` 要用 `toEqual`**：`toBe` 对对象/数组做引用比较，整表比对必然假红。
