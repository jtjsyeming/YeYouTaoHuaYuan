## 2026-11-01　`ca58914`　移动端网格自适应缩放（Tetris / 2048）

依据《08-开发文档-移动端网格自适应缩放-v2.0.md》实施，解决 `/tetris` 与 `/game_2048` 在窄屏的横向溢出：

- **尺寸单一来源**：`.tetris-container` 新增 `--cell-size: min(30px, calc((100vw - 78px) / 10))`，`.grid-cell` / `.piece-cell` / `.piece-empty` 的 30px 硬编码改为引用变量（`.piece-empty` 补 `box-sizing`）；`.side-panel` 新增 `--preview-size: min(18px, calc(var(--cell-size) * 0.6))` 供 `.preview-cell` 使用；
- **overlay 去硬编码（关键）**：当前方块内联样式由 `top: @(y * 30)px` 改为 `top: calc(var(--cell-size) * @(y))`（left 同），网格与 overlay 共用同一小数坐标，缩放后仍逐格对齐，C# 游戏逻辑零改动；
- **L1 放开容器宽**：`@media (max-width: 900px)` 下 `.top-area` 由 80% 改 100%（桌面 ≥901px 保持原样）；
- **L2 纵向堆叠**：`.top-area` 改列方向；`.side-panel` 加 `box-sizing: border-box` 且宽度取 `calc(var(--cell-size) * 10 + 4px)`，与画布外框严格等宽（实测差 0.00px）；
- **L4 按钮缩档**：`@media (max-width: 400px)` 下按钮组由 291px 收到 236px，320px 视口不再溢出；
- **2048（防御性改动）**：`.game-container` 加 `--tile-size: min(50px, calc((100vw - 120px) / 4))`，`.tile` 引用该变量、字号改 `calc(var(--tile-size) * 0.4)`、补 `box-sizing`。主流机型（≥320px）实测无变化，仅为 <305px 兜底；
- **与文档的两处偏差（实测修正）**：
  1. `<style>` 内 `@media` 必须写成 `@@media`，否则 razor 按 C# 解析报 `CS0103: 不存在名称 media`；
  2. 文档断点只覆盖 "≤520px"，实测 641~749px（侧栏已出现、宽 335px < 横排硬性下限 424px）仍溢出 3px——`width: 100%` 压不动 flex 子项的 min-content。故把堆叠断点扩成 `(max-width: 520px), (min-width: 641px) and (max-width: 780px)`（上界取 780 以容纳 15px 竖滚动条）。文档 T3 中 700px 的预期"横排"在数学上不可达，实际为堆叠；
- 未改动：C# 逻辑、其他页面、`MainLayout`、`Program.cs`；
- 验证（Playwright 驱动真实浏览器，Chromium + Firefox）：**视口矩阵 46/46 通过**，280/320/360/375/414/480/520/640/641/700/750/761/781/785/800/860/901/1024/1440 共 19 档全部 `scrollWidth == clientWidth`；桌面 1440 保持 cell 30px、`top-area` 600px 的零变化；cell 曲线 375→29.69、360→28.19、320→24.19、280→20.19 与文档预算吻合；overlay 在 414/375 下与网格行/列偏差 0.00px；375px 旋转/软降/锁定实测落位与 overlay 一致（列集合、最底行 19 均符合）；Firefox 同批断言全通过；`dotnet build` 0 错误、警告数仍为 5（全为 `CodingPlace.razor` 既有警告）。
- 副作用说明：`.tile` 加 `box-sizing` 后每块外框由 52px 变 50px（棋盘整体 223→215px），字号仍 20px，四位数文本实测占用 46.02px < 内容宽 48px 不溢出。

## 2026-11-01　`8b5aef5`　爱情计时器自动刷新与日期联动

依据《06-开发文档-爱情计时器自动刷新与日期联动-v2.0.md》§3.7 整页重写 `Pages/MyPage/LoveTime.razor`：

- **秒级自动刷新**：改用 `PeriodicTimer` + `async Task` 循环 + `CancellationTokenSource`，在 `OnAfterRender(firstRender)` 启动（规避 `ServerPrerendered` 预渲染实例重复建表），`Dispose()` 取消释放。取代 v1.0 的 `System.Timers.Timer` + `async void`（避免异常逃逸到线程池）；
- **年月日联动**：新增 `RebuildDays()`，按 `DateTime.DaysInMonth` 生成日选项（含闰年 2 月 29 日）；年/月变更经 `@bind-Value:after` 触发重建，越界日期自动收敛（1/31 → 2 月 → 28/29）；日下拉加 `@key` 强制重建实例，规避 FAST Web Component 选项列表不刷新；
- **合法性校验**：三级校验（完整性 → 日期存在性 `try/catch` → 不晚于今天），全部返回中文提示而非抛异常——原 `new DateTime(y,m,d)` 未捕获会中止整个 SignalR 电路的问题已消除；
- **锚点模型**：新增 `anchorDates`（默认 = 内置纪念日），自选日期后该类型以自选日为锚点**持续跳动**，不被内置纪念日覆盖；
- **统一渲染入口**：两个 `CalculateElapsedTime` 重载合并为 `Render(anchor, type, now)`，`RefreshAll()` 一次取 `DateTime.Now`，消除三行秒数跨秒抖动；负时长钳制为 0；
- **P1 恢复默认**：新增三个 `Appearance="Lightweight"` 的"恢复相识/恋爱/结婚默认"按钮；
- 清理：删除重复的 `<h3>爱情计时器</h3>` 及无用的 `@using System.Globalization`、`@inject IJSRuntime`、`@using System.Timers`；
- 未改动：`site.css`、其他页面、`Program.cs`、`_Imports.razor`；新增样式写在页面内 `<style>`，类名带 `love-` 前缀避免全局污染；
- 验证：`dotnet build` 0 错误、警告数仍为 5（全为 `CodingPlace.razor` 既有警告，**无 CS8618**）；`/loveTime` 预渲染正常且三行秒数一致；日期联动与校验共 14 组断言全部通过（闰年 2 月、1/31→2 月收敛、2/30 与 13 月非法日期、未来日期拒绝、负时长钳制）。
