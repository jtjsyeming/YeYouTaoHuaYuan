### 1.2 优先级定义

| 级别 | 含义 | 全量测试中的角色 |
|---|---|---|
| P0 | 核心功能，坏了即不可用 | **冒烟集**（每次发布必测，见 §11.3） |
| P1 | 重要功能或边界，坏了明显影响体验 | 全量测试必测 |
| P2 | 一般功能、文案、样式细节 | 抽测 |

### 1.3 缺陷处理方式（取代 v1.0 的 `[已知缺陷]` 内联标注）

**v1.0 的做法已废弃**：把缺陷直接标在用例预期里，修复合入后需要逐条回改用例，且极易出现"缺陷修了、标注没改"的漂移（本次检视正是这种情况）。

v2.0 改为两层：

1. **用例的"预期结果"只写当前代码的真实行为**（可从源码读出）。用例永远描述"系统现在应该是什么样"，不描述"应该修成什么样"。
2. **缺陷与观察项统一登记在 §10 缺陷台账**，分配 `D-xx` 编号。用例若当前行为违反标准规则，在"备注"列写 `见 D-xx`，**不影响该用例判定通过**。

> 收益：缺陷修好后只改台账一行（状态 → 已关闭），99 条用例零改动。

### 1.4 结果记录

每条用例执行后记录：**通过 / 失败 / 阻塞 / 未测**。失败须附：实际结果、截图、复现步骤。
全量测试结果汇总表见 §11.4。

## 2. 测试环境与前置条件

### 2.1 启动方式（v1.0 此处会导致启动失败）

```bash
# 正确：显式指定 http 端口，规避缺失的 HTTPS 开发证书

dotnet run --no-launch-profile --urls http://localhost:14074
# 或用 VS Code：F5「jtjsym 网站 (Blazor Server)」（preLaunchTask 已含上述参数）
```

| 项 | 要求 |
|---|---|
| 运行时 | .NET 8 SDK（本机实测 SDK 9.0.101 亦可编译 net8.0） |
| 访问地址 | `http://localhost:14074`（**不要用** `https://localhost:14073`，本机无开发证书） |
| 主测浏览器 | Chrome / Edge 最新版 |
| 兼容测试 | Firefox；移动端用 DevTools 设备模拟（375px） |
| 网络模拟 | DevTools Network throttling（Slow 3G、Offline） |
| 生产侧验证 | 部署目录 `E:\300programing\390Publish\391jtjsym`（IIS inprocess），用于 NF-05 / NF-08 |
| 数据 | 无需预置（无数据库）；每条用例开始前刷新页面复位状态 |

> **踩坑提示**：站点正在被调试器运行时执行 `dotnet build` 会报 `MSB3027/MSB3021`（`jtjsym.dll` 被 VS 调试适配器锁定）。构建前先停止调试，或直接看编译警告是否只有 §2.2 列出的 5 条。

### 2.2 构建基线

| 项 | 基线值 |
|---|---|
| `dotnet build` | 0 编译错误 |
