# 夜游桃花源网站技术栈与代码结构现状

> 版本：v1.27　|　更新日期：2026-11-07　|　适用范围：`jtjsym/` 工程
> 本文档描述网站**当前**的技术栈与代码结构，随代码演进持续更新；迭代历史见同目录《更新记录.md》。

## 1. 项目简介

**夜游桃花源**（工程名 jtjsym）是基于 C# Blazor 的个人小型网站，包含电子木鱼、爱情计时器、2048、俄罗斯方块等功能页。站点已完成 ICP 备案（陕ICP备2024056488号），面向公网提供 HTTPS 服务。

- 解决方案：`jtjsym/jtjsym.sln`
- 实际工程：`jtjsym/jtjsym/`（注意两层同名目录）
- 特点：无数据库、无外部服务，所有页面状态保存在服务端组件内存中，会话级生命周期。

### 3.4 关键运行机制备忘

1. **状态在服务端**：Blazor Server 模式下游戏棋盘、计时器都在服务器内存，用户刷新/断线即重置；改状态后需 `StateHasChanged()` 才推送渲染。
2. **Tetris 的 Timer 三重保护**：`isDisposed` 标志 + `timerLock` 互斥 + `InvokeAsync` 切回渲染上下文，组件释放时 `Dispose()` 统一停表。**注意（D-13）**：该类原先只写了 `public void Dispose()` 却未实现 `IDisposable`/`IAsyncDisposable`，Blazor 从不调用它，等于死代码（Timer 靠 `catch (ObjectDisposedException)` 掩盖）；现由 `DisposeAsync()` 显式调用，才真正生效。**位置是硬约束（D-19）**：`Dispose();` 必须在 `DisposeAsync` **首行**——两个 `await` 期间 `isDisposed` 为 `false` 时 Timer 会照常回调 `DropPiece/SoftDropPiece/IncreaseDifficulty` 并渲染；且不能顺手把 `keyRegId = 0` 一起提前（`unregister` 收到旧 id 会短路，监听卸不掉）。
3. **LoveTime 的秒级刷新（PeriodicTimer 模式）**：常驻单频刷新用 `PeriodicTimer` + `async Task` 循环 + `CancellationTokenSource`，在 `OnAfterRenderAsync(firstRender)` 里**先** `StartTicker()`、**再** `await import("./js/lovetimer.js")` 注册可见性监听（顺序不可颠倒 —— 相位从"开始交互那一瞬"起算，先 await 会让 φ 跟着 import 往返漂移，LT-31 依赖），`DisposeAsync` 首行调 `Dispose()` 取消并释放 CTS。安全内核与上一条一致（`isDisposed` 双检 + `InvokeAsync` + 兜底 `catch`），差别只在触发器选型：
   - **随状态反复启停 / 需要变速** → `System.Timers.Timer`（Tetris）
   - **常驻单频** → `PeriodicTimer` 循环（LoveTime），await 天然串行、无重入、无 `async void` 异常外溢风险
   - **单一取时点是硬约束（P-010）**：`RefreshAll()` 是**唯一**取 `DateTime.Now` 的地方，`Render(anchor, type, now)` 的 `now` 为**必传参数**（不再有 `DateTime? now = null` 那种"零成本二次取时"的降级入口）；事件回调（计算相识/恋爱/结婚、恢复默认）也必须走 `RefreshAll()`，不能只 `Render` 被点那一行——否则被点行跳到新秒、另两行停在上一次 tick，实测签名为 `[k, k-1, k-1]`。
   - **年份列表在 `RefreshAll` 里按 `now.Year` 自愈（P-014）**：`years` 由 `EnsureYearsFresh(now.Year)` 惰性构建（初值 `years = new()`、闸门 `yearsBuiltFor = 0` ⇒ 首次必建），跨年时引用替换为"末尾追加一项"，`fluent-select` 已选值不受影响（无需 `@key`，与日期下拉"选项集合整体变化"性质不同）。**该自愈依附于秒刷**——D-08 把后台的 tick 停掉后，靠"回到前台的补刷"补上这一段：`OnVisibilityChanged` 的 visible 分支**必须先 `RefreshAll()` 再让 ticker 继续**，否则跨年后台返回的年份列表会停在旧年。
   - **后台暂停（D-08）是"标志位跳过"，不是 Cancel/重建 CTS**：`RunTickerAsync` 循环体首行 `if (isHidden) continue;` —— 位置必须在 `InvokeAsync` **之前**（进了渲染上下文就必然推一帧）。`isHidden` 声明为 `volatile`（JS 回调线程写、ticker 线程读）。选它而不选 `Cancel + 重建` 的理由：`StartTicker()` 的守卫是 `tickerCts is not null`，Cancel 后必须**成对**置 `null` 否则恢复后再也不启动（静默失效），而 `using var timer` 的释放是异步的，新旧循环会有同一 tick 并存的窗口；`Stop`/`Start` 那套 API 本页根本没有。

4. **无持久化**：如需存档/排行榜，需先引入存储层（SQLite 或云数据库）。**例外**：2048 最高分为纯展示值，用 localStorage（`jtjsym.g2048.best`，无服务端参与），不构成存储层；后续 Tetris 等若只记本地最好成绩，可沿用同一 `jtjsym.` 前缀约定。**2048 对局进度**为 `sessionStorage`（`jtjsym.g2048.session`，标签页会话级、关标签即清），同属纯浏览器侧、无服务端参与，也不算存储层。
5. **VS Code 一键运行/调试/发布**（2026-11-01 起随仓库提供 `.vscode/`）：`launch.json` 内含「jtjsym 网站 (Blazor Server)」「MineSweeper 扫雷 (WinForms)」与「同时启动」三条配置，均在 F5 前自动执行对应 `build-*` 任务；网站固定监听 `http://localhost:14074`（本机无 HTTPS 开发证书，故不用 14073）。`tasks.json` 另提供 `publish-jtjsym`：Release + win-x64 + 框架依赖（`--self-contained false`、`PublishSingleFile=false`）发布到 `.publish/staging`，成功后用 `robocopy /MIR` 镜像到 `E:\300programing\390Publish\391jtjsym`（保留 `web.config` 的 IIS inprocess 形态，并清除目标目录中过期的旧 dll）。
6. **CSS 尺寸单一来源 + 响应式断点**（Tetris / 2048）：像素尺寸不再散落在样式与标记里，而是由容器上的 CSS 变量统一派生——`--cell-size: min(30px, calc((100vw - 78px) / 10))`（Tetris）、`--tile-size: min(50px, calc((100vw - 120px) / 4))`（2048），标记里只写 `calc(var(--cell-size) * 列号)`。要点：
   - **`<style>` 内的 `@media` 必须写成 `@@media`**：razor 会把单个 `@` 当 C# 表达式解析，直接报 `CS0103: 不存在名称 media`；
   - 可用宽预算：`78px = px-4(48) + 容器 padding(20) + 画布边框(4) + 6px 余量`；有侧栏时另扣 `250(侧栏) + 32/24(article padding) + 20`；
   - **`width: 100%` 压不动 flex 子项的 min-content**：`.top-area` 横排硬性下限为 `304(画布) + 10(gap) + 110(面板) = 424px`，故 641~780px（侧栏已出现、宽度不够）也必须走纵向堆叠，仅靠放开 80% 无法消除溢出；
   - 堆叠态下 `.side-panel` 需 `box-sizing: border-box` 且宽度取 `calc(var(--cell-size) * 10 + 4px)` 才能与画布外框严格等宽。
7. **端到端回归套件 `tools/e2e`（Playwright，仅开发期）**：把《07-测试文档》里可自动化的用例固化为脚本，按模块分 spec + 一个冒烟集。

8. **键盘操作共享模块 `wwwroot/js/gamekeyboard.js`**（D-02）：window 级 `keydown`/`keyup` 监听（Blazor 的 `@onkeydown` 挂在元素上，焦点离开即失效，且拿不到 window 级 keyup）：
   - `register(ref, options)` 返回**注册 id**，`unregister(id)` 只在该 id 仍是当前注册时才拆监听——跨页导航时"新页 register / 旧页 unregister"的先后顺序没有保证，无条件拆会把新页刚装的监听删掉；
   - 连发按页配置：2048 传空数组（一次按键=一步）；Tetris 只放行 `←`/`→`（60ms 节流），`↑` 防连转、`↓` 的连续下落交给 `softDropTimer`；
   - `invokeMethodAsync(...).catch(() => {})`：断线/组件已销毁时 Promise 会被 reject，不接住会污染控制台（NF-06）；
   - 窗口失焦/切标签页时 `keyup` 收不到，故在 `blur`/`visibilitychange` 上 `releaseAll()` 释放软降；**该释放延迟 150ms 并用 `pagehide` 短路**——导航离开时 `visibilitychange(hidden)` 会在连接断开后触发，直接 invoke 会让 `blazor.server.js` 打出 `Cannot send data if the connection is not in the 'Connected' State.`（Firefox 实测必现，NF-01 红）；
   - `[JSInvokable]` **不会**自动重渲染（与 `@onclick` 不同），两个页面的移动方法内部已各自 `StateHasChanged()`，故 `OnKeyDown` 里不再重复触发（否则双帧渲染）。

9. **可见性桥 `wwwroot/js/lovetimer.js`**（D-08）：`register(ref)` 返回**自增 id**（函数不可 JSON 序列化，回传函数只会得到 `undefined`，于是永远注销不掉），`unregister(id)` 只在 `id === currentId` 时才拆监听 —— 与 `gamekeyboard.js` 同款护栏，跨页时"新页 register / 旧页 unregister"顺序无保证。两条硬约束：
   - **只读 `document.visibilityState`，绝不读 `document.hidden`**：`document` 实例上 defineProperty 遮蔽的注入法（e2e 造后台）**不会**同步改写 `hidden`，读 `hidden` 会让 `D08-1~3` 全部假绿；
   - **`invokeMethodAsync(...).catch(() => {})`**：断线/组件已销毁时 Promise 会被 reject，不接住会污染控制台（NF-06）。

10. **2048 纯逻辑抽离 `Services/Game2048Core.cs`**（H-008）：只搬**线粒度**的三块，棋盘形状一行未动（仍是 `int[,]`），`GetRow/SetRow/GetColumn/SetColumn` 早已把棋盘隔离成"一条线"：

   - `IsGameOver(int[] flat, int size = 4)` —— 组件侧 `board.Cast<int>().ToArray()` 是**行主序**（`[0,0],[0,1]…`），与存档的 `i / GridSize, i % GridSize` 完全一致，不会引入转置错误；
   - `SpawnValue(Random rng, int fourPercent = 10)` —— 90/10 的常量随迁（D-01 的单一来源）。
   - 等价性验收口径不是"看代码像不像"，而是**抽离前后跑同一份 G2048 / d18 / d19 用例，零改动全绿**；`dotnet test` 23 条 35ms。
