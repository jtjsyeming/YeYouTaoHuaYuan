## 1. 项目简介

**夜游桃花源**（工程名 jtjsym）是基于 C# Blazor 的个人小型网站，包含电子木鱼、爱情计时器、2048、俄罗斯方块等功能页。站点已完成 ICP 备案（陕ICP备2024056488号），面向公网提供 HTTPS 服务。

- 解决方案：`jtjsym/jtjsym.sln`
- 实际工程：`jtjsym/jtjsym/`（注意两层同名目录）
- 特点：无数据库、无外部服务，所有页面状态保存在服务端组件内存中，会话级生命周期。

### 3.4 关键运行机制备忘

1. **状态在服务端**：Blazor Server 模式下游戏棋盘、计时器都在服务器内存，用户刷新/断线即重置；改状态后需 `StateHasChanged()` 才推送渲染。
2. **Tetris 的 Timer 三重保护**：`isDisposed` 标志 + `timerLock` 互斥 + `InvokeAsync` 切回渲染上下文，组件释放时 `Dispose()` 统一停表。**注意（D-13）**：该类原先只写了 `public void Dispose()` 却未实现 `IDisposable`/`IAsyncDisposable`，Blazor 从不调用它，等于死代码（Timer 靠 `catch (ObjectDisposedException)` 掩盖）；现由 `DisposeAsync()` 显式调用，才真正生效。
3. **LoveTime 的秒级刷新（PeriodicTimer 模式）**：常驻单频刷新用 `PeriodicTimer` + `async Task` 循环 + `CancellationTokenSource`，在 `OnAfterRender(firstRender)` 启动（规避 `ServerPrerendered` 预渲染实例重复建表），`Dispose()` 取消并释放。安全内核与上一条一致（`isDisposed` 双检 + `InvokeAsync` + 兜底 `catch`），差别只在触发器选型：
   - **随状态反复启停 / 需要变速** → `System.Timers.Timer`（Tetris）
   - **常驻单频** → `PeriodicTimer` 循环（LoveTime），await 天然串行、无重入、无 `async void` 异常外溢风险
4. **无持久化**：如需存档/排行榜，需先引入存储层（SQLite 或云数据库）。
5. **VS Code 一键运行/调试/发布**（2026-11-01 起随仓库提供 `.vscode/`）：`launch.json` 内含「jtjsym 网站 (Blazor Server)」「MineSweeper 扫雷 (WinForms)」与「同时启动」三条配置，均在 F5 前自动执行对应 `build-*` 任务；网站固定监听 `http://localhost:14074`（本机无 HTTPS 开发证书，故不用 14073）。`tasks.json` 另提供 `publish-jtjsym`：Release + win-x64 + 框架依赖（`--self-contained false`、`PublishSingleFile=false`）发布到 `.publish/staging`，成功后用 `robocopy /MIR` 镜像到 `E:\300programing\390Publish\391jtjsym`（保留 `web.config` 的 IIS inprocess 形态，并清除目标目录中过期的旧 dll）。
6. **CSS 尺寸单一来源 + 响应式断点**（Tetris / 2048）：像素尺寸不再散落在样式与标记里，而是由容器上的 CSS 变量统一派生——`--cell-size: min(30px, calc((100vw - 78px) / 10))`（Tetris）、`--tile-size: min(50px, calc((100vw - 120px) / 4))`（2048），标记里只写 `calc(var(--cell-size) * 列号)`。要点：
   - **`<style>` 内的 `@media` 必须写成 `@@media`**：razor 会把单个 `@` 当 C# 表达式解析，直接报 `CS0103: 不存在名称 media`；
   - 可用宽预算：`78px = px-4(48) + 容器 padding(20) + 画布边框(4) + 6px 余量`；有侧栏时另扣 `250(侧栏) + 32/24(article padding) + 20`；
   - **`width: 100%` 压不动 flex 子项的 min-content**：`.top-area` 横排硬性下限为 `304(画布) + 10(gap) + 110(面板) = 424px`，故 641~780px（侧栏已出现、宽度不够）也必须走纵向堆叠，仅靠放开 80% 无法消除溢出；
   - 堆叠态下 `.side-panel` 需 `box-sizing: border-box` 且宽度取 `calc(var(--cell-size) * 10 + 4px)` 才能与画布外框严格等宽。
7. **端到端回归套件 `tools/e2e`（Playwright，仅开发期）**：把《07-测试文档》里可自动化的用例固化为脚本，按模块分 spec + 一个冒烟集。

   四条踩过的坑（写新用例前务必先看）：
   - **`--no-launch-profile` 必须配 `--environment Development`**（见 §2 环境要求下方注），否则 `_content/*` 全 404、尺寸类断言全是假结果；
   - **FluentSelect 不能用"赋 `value` + 派发 `change`"驱动**，Blazor 不认，必须点击展开后点 `fluent-option`；
   - **木鱼装饰图标是 `<div><img src="counter.gif">`**，不是 `fluent-icon`；
   - **TRIS 的方块落点要读渲染坐标**（`getBoundingClientRect`），因为 `style.top` 现在是 `calc(var(--cell-size) * n)`，`parseFloat` 只会得到 `NaN`；
   - **`page.keyboard.down()` 不会产生 autorepeat**（只发一次 keydown），测"按住连发"必须派发 `new KeyboardEvent('keydown', { repeat: true })`。

8. **键盘操作共享模块 `wwwroot/js/gamekeyboard.js`**（D-02）：window 级 `keydown`/`keyup` 监听（Blazor 的 `@onkeydown` 挂在元素上，焦点离开即失效，且拿不到 window 级 keyup）：
   - `register(ref, options)` 返回**注册 id**，`unregister(id)` 只在该 id 仍是当前注册时才拆监听——跨页导航时"新页 register / 旧页 unregister"的先后顺序没有保证，无条件拆会把新页刚装的监听删掉；
   - 连发按页配置：2048 传空数组（一次按键=一步）；Tetris 只放行 `←`/`→`（60ms 节流），`↑` 防连转、`↓` 的连续下落交给 `softDropTimer`；
   - `invokeMethodAsync(...).catch(() => {})`：断线/组件已销毁时 Promise 会被 reject，不接住会污染控制台（NF-06）；
   - 窗口失焦/切标签页时 `keyup` 收不到，故在 `blur`/`visibilitychange` 上 `releaseAll()` 释放软降；**该释放延迟 150ms 并用 `pagehide` 短路**——导航离开时 `visibilitychange(hidden)` 会在连接断开后触发，直接 invoke 会让 `blazor.server.js` 打出 `Cannot send data if the connection is not in the 'Connected' State.`（Firefox 实测必现，NF-01 红）；
   - `[JSInvokable]` **不会**自动重渲染（与 `@onclick` 不同），两个页面的移动方法内部已各自 `StateHasChanged()`，故 `OnKeyDown` 里不再重复触发（否则双帧渲染）。
